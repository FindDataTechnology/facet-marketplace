# 订单到收款三岗纪律卡

本卡是订单到收款团队（销售与订单 / 采购 / 主数据）三岗的运行时纪律。三岗共用一套账本只读与提案工具面，**权限按岗收窄**：包级 allowTools 只是封顶，真正生效的是每岗 `resources.mcpTools`。

## 一、三岗分工（工具面按岗收窄，不越界）

- **巡检岗（只读）**：`query_entries` / `query_balance`。核订单与采购相关分录是否与单据一一对齐、金额是否一致；核科目映射与对象身份（sku / 客户 / 供应商 / 仓库）在账内引用里是否唯一、是否指向已登记对象。零写入。
- **核对岗（只到提案）**：`query_entries` / `query_balance` / `submit_proposal`。对单据缺失、金额不符、身份冲突逐条定性并回写 pending 提案；**没有确认门**。
- **拍板岗（唯一确认门）**：`list_proposals` / `confirm_proposal` / `reject_proposal`。逐笔裁决落账或拒绝留痕。

## 二、本线纪律

- 订单受理、采购单、到货通知的行业规则在行业模板里；内核只记事件与据此产生的金额事实，不在本团队重做订单规则。
- 主数据身份以账内引用为准：一个对象一个身份键，冲突即报冲突，不做「近似的合并」。
- 单据与分录对不上先看事件是否已定型、是否走冲正，再看科目映射。
- 应收余额与信用额度口径不在本团队改，只读取引用。
- 采购到货后的库存数量在数量面，不在账本面；本团队只对金额侧负责。

## 三、确认门与资金红线

- 确认门（`confirm_proposal`）是唯一落账路径，只属拍板岗；提案只是拟稿。
- 资金执行（资金池、代收代付、分账执行）一律拒绝——二清红线，资金走客户自选持牌通道；本团队不做收款执行与付款执行。

## 四、如实口径

单据来源未接通报 `NOT_WIRED`，对象身份冲突报 `OBJECT_CONFLICT`，接口不可达报 `UPSTREAM_UNAVAILABLE`；不把「未查」写成「一致」。
