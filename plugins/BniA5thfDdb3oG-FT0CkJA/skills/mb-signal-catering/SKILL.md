# 餐饮信号包

**本技能是内核套件「生意体检」（`mb-business-checkup`）的行业信号姊妹件。** 内核在阶段 3 调用本技能；本技能**只做餐饮行业的环境信号读取与解读**，不做问诊、不做盈亏平衡/毛利/现金流计算（那是内核与三个计算器的事），也**不修改内核工作流**。

**叠装契约**：内核 + 本包 = 完整餐饮版体检。只装内核不装本包时，内核在阶段 3 走"未安装行业信号包"降级分支并如实标注——这是预期行为，不是故障。

---

## §0 与内核的协作契约（本包声明）

本包向内核提供以下信号，每个信号声明：**读什么源、怎么读、异动意味着什么、局限是什么**。内核按本声明调用并把结果汇总进阶段 3 输出。

| 信号 id | 信号名 | 数据来源单元 | 频率 | 是否代理 |
|---|---|---|---|---|
| `catering.cost_trend` | 食材成本趋势 | dce（大商所期货） | 日 | 是（趋势代理） |
| `catering.footfall_proxy` | 商圈活跃度 | zgdypf-boxoffice（专资办票房） | 日/周 | 是（客流代理） |
| `catering.channel_shift` | 堂食/外卖结构 | nmc-weather（中央气象台） | 时 | 是（结构提示） |
| `catering.competition_density` | 同业密度（可选） | ia35（工商登记） | 批次快照 | 否（存量格局） |

---

## §1 食材成本趋势（`catering.cost_trend`）

### 读什么

大连商品交易所期货行情，覆盖餐饮业最大变动成本项：**生猪、豆粕、玉米、棕榈油**。

- 生猪 → 肉禽类原料成本
- 豆粕、玉米 → 饲料成本（传导到肉蛋奶）
- 棕榈油 → 食用油与煎炸用油成本

取数走 `mcp__fd-find-data-business-mcp__ai_search` 或 `mcp__fd-open-data-mcp__ai_search` 定位指标，再 `read` / `read_series` / `read_range` 取序列（概念与实体按平台语义模型提问）。

### 怎么读

看**趋势与方向**，不看单日点位：

1. 取近 8–12 周序列，看方向（上行/下行/横盘）与斜率变化
2. 看是否连续（连涨三周比单日跳涨更值得说）
3. 对应到用户店里的具体成本项（"你主要用油" → 看棕榈油；"你卖猪肉菜" → 看生猪）

### 异动意味着什么

上行趋势 → 该原料成本项**大概率**抬头，进货成本压力增加，需考虑提前锁价、调整菜谱结构或调价。下行趋势 → 成本窗口，可考虑适度促销或补库。

### 局限（必须随信号一并输出）

**期货价不等于本店进货价。** 期货是大宗标准化合约价，本店进货渠道、规格、账期、地区差价都不同；传导也有时滞。本信号回答"成本方向朝哪走"，**不回答"你的进货价是多少"**。

**禁止表述**："你的进货价会涨到 X 元""你下月食材成本是 Y 元"。

### 取不到时

如实标注「食材成本信号未连接」，本信号段不输出，其余信号继续。**不得**用模型记忆的价格数字填充。

## §2 商圈活跃度代理（`catering.footfall_proxy`）

### 读什么

国家电影专资办电影票房日榜/周榜（`zgdypf-boxoffice` 单元，2017-01 起日粒度可回溯）。

### 怎么读

1. 取用户所在**城市**或大区的票房序列（日榜看近期，周榜看趋势）
2. 与上一周期比（本周 vs 上周、本月 vs 上月）
3. 结合节假日节奏看（档期前后的波动是常态，不是异常）

### 异动意味着什么

票房显著上行 → 该区域**消费活跃度**偏高，外出消费意愿可能较强，堂食场景相对有利。显著下行 → 消费活跃度回落，需更关注性价比与外卖渠道。

### 局限（必须随信号一并输出）

**票房反映商圈/城市消费活跃度，不等于本店客流。** 看电影的人不一定吃你的店；商圈活跃也可能被其他业态吸走。本信号只作**环境冷暖**的参考，**不回答"你的客流是多少"**。

**禁止表述**："你的客流会涨 X%""你的进店人数是 Y"。

### 取不到时

如实标注「商圈活跃度信号未连接」，本信号段不输出，其余信号继续。

## §3 堂食/外卖结构（`catering.channel_shift`）

### 读什么

中央气象台实况与预报（`nmc-weather` 单元，34 省 2529 站，时级）。

### 怎么读

1. 取用户所在城市的实况与未来 3–7 日预报
2. 看降水、极端温度、大风等对**外出就餐**不利的天气
3. 结合本店是否已上线外卖/是否有外卖位（问内核档案，或直接问用户）

### 异动意味着什么

连续降水/极端高温 → 堂食客流受抑、外卖需求相对上升，是**排班与备货的结构性提示**（如提前备外卖包装、调整堂食与外卖出品配比）。

### 局限（必须随信号一并输出）

**天气是堂食/外卖结构的提示，不是客流预测。** 不等于本店外卖单量会涨多少；本店是否有外卖位、是否上线平台、平台排名如何，都是本信号覆盖不到的。

### 取不到时

如实标注「天气信号未连接」，本信号段不输出，其余信号继续。

## §4 同业密度（`catering.competition_density`，可选信号）

### 读什么

工商登记（`ia35`）：`mcp__fd-find-data-business-mcp__ia35_reg_counts_read`（新增注册数，支持 `province` + `city` + `county`，行业可下钻 `industry_level` = 门类/大类/中类/小类）与 `mcp__fd-find-data-business-mcp__ia35_company_search`（企业档案，`company_type="个体工商户"` 可筛个体户）。

餐饮对应行业小类示例：**正餐服务（H6210）、快餐服务（H6220）**。

### 参数陷阱（必读）

`ia35_reg_counts_read` 的 `city` / `county` 过滤**必须同时提供 `province`**，否则返回 `invalid_params`（无省份锚点会退化为全表扫描并超时）。调 county 前先确认用户给的区县名能对应库内口径；对不上就回问，不要猜。

### 两条硬标注（缺一即不合格输出）

1. **批次与时效**：输出必须标注该批数据的**批次年份**（年份一律取工具响应携带的字段 `latest_year_available` / `batch_year` / `snapshot_year`，**不得凭记忆填写**），并写明「**历史格局，非实时**」。它回答"这条街历史上是什么竞争强度"，**不回答**"最近三个月新开了几家"。
2. **无注销/吊销口径**：数据源只有**新增注册**口径，**没有**注销、吊销、关店的流量口径。用户问"这条街关了多少家""餐饮倒闭率多少"——**必须明示做不了**，并给出可得替代：存量快照的**状态分布**（在营/存续/吊销未注销/注销等状态占比，走 `ia35_company_search` 的 `status` 字段）。**禁止编造关店数量、禁止估算退出率、禁止用新增注册下降反推关店。**

### 局限

即使拿到区县 + 小类的新增注册序列，它也只说明**登记层面的进入热度**，不等于实际竞争强度（存活率、经营质量、客群重叠度都在数据之外）。

## §5 汇总输出格式（交给内核阶段 3）

每个信号一律四行，缺依据不许写：

```
【信号】食材成本趋势（代理：大宗期货，非本店进货价）
  读数：<工具返回的方向与区间，附来源与口径时间>
  含义：<对本店成本项的提示，给方向不给编造幅度>
  局限：期货价 ≠ 本店进货价（渠道/规格/地区/时滞均不同）

【信号】商圈活跃度（代理：票房，非本店客流）
  读数：<城市票房序列与环比，附来源>
  含义：<环境冷暖提示>
  局限：票房反映商圈活跃度，不等于本店客流
```

**汇总顺序**：先成本（直接影响钱），再商圈（影响客流环境），再天气（影响渠道结构），最后同业密度（影响长期判断）。

**信号源不可用**：该信号段写「<信号名>未连接」，其余照常，**分析不中断**。

## §6 术语对照（面向小老板，首次出现必须解释）

| 术语 | 日常语言解释 |
|---|---|
| 变动成本 | 卖一份就多花一份的钱（食材、包装、平台佣金） |
| 期货价 | 批发市场里"约定以后交货"的价格，用来判断东西要变贵还是变便宜 |
| 代理信号 | 不是直接量你的店，而是量你店周边的环境，只能当参考 |
| 批次快照 | 这是某一年的登记底册，不是今天实时的情况 |
| 存量状态分布 | 现在册子上这些店各是什么状态（还在开/已注销等）的占比 |

## hard_constraints

1. **每个信号 MUST 标注代理性质与其局限**（写清"它反映什么、不等于什么"），禁止把代理信号表述成对本店的直接测量。
2. **信号源不可用即降级**：MUST 明示「未连接该数据源」，分析在其余信号上继续；**禁止**用模型记忆的价格、票房、客流数值填充。
3. **数值 MUST 来自工具实际返回**，附来源与口径时间；禁止编造任何价格、票房、客流、注册数。
4. **工商类信号 MUST 带批次年份与「历史格局，非实时」标注**；批次年份 MUST 取自工具响应字段，禁止凭记忆填写。
5. **无注销口径 MUST 明示**：涉及"关了多少家/倒闭率/退出量"的提问，MUST 明示数据源无此口径、做不了，并给出存量状态分布替代；**禁止编造关店数量、禁止估算退出率、禁止用新增注册下降反推关店**。
6. **不重复内核工作**：本技能 MUST NOT 包含问诊建档、盈亏平衡、毛利结构、现金流账期计算（属 `mb-business-checkup` 与三个计算器）；也 MUST NOT 修改内核工作流。
7. **术语可懂**：面向小老板输出时，专业术语首次出现 MUST 附一句日常语言解释。
8. **不承诺实时性**：MUST NOT 将批次快照数据呈现为实时登记状态。

**硬失败项**（出现任一即不合格）：把代理信号说成本店实测；信号未连接却给出数值；工商类输出缺批次年份或"非实时"标注；被问关店量时给出任何数量或比率。

## 免责声明

本技能输出的环境信号均为**代理指标**，反映的是区域/大盘环境而非本店实际经营数据，仅供经营参考，不构成投资或经营决策建议。工商登记数据为历史批次快照，不反映实时状态，亦不含注销/吊销口径。最终经营决策由经营者本人作出。
