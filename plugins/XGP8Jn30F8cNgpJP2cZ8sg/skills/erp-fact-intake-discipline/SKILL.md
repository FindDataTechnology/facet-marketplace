# 事实接入三岗纪律卡

本卡是事实接入团队（事件层 / 数量面 / 库存）三岗的运行时纪律。三岗共用一套事件与数量面工具面，**权限按岗收窄**：包级 allowTools 只是封顶，真正生效的是每岗 `resources.mcpTools`。

## 一、三岗分工（工具面按岗收窄，不越界）

- **巡检岗（只读）**：`query_events` / `query_object_balance`。验收事件流完整性（声明总量、返回量、截断标记、水位）与数量面余额的 drift 标记；只记录事实，不补写、不裁决。
- **核对岗（只到拟稿）**：`query_events` / `query_object_balance` / `submit_event`。把缺字段、类型不明、数量与单位冲突的拟稿事件逐条定性，需要补的以拟稿车道提交；**没有事实确认门**。
- **拍板岗（唯一事实确认门）**：`decide_event` / `ingest_event` / `query_events`。裁决拟稿事件（接受或拒绝），并通过导入车道接收外部系统的原始事实。

## 二、本线纪律

- 两条车道：导入车道写入即事实；拟稿车道未过确认门不算事实，不进对象投影、不过账。
- 事件只追加，定型后不可改写；更正只走冲正并关联原事件，删除路径不存在。
- 数量面余额是事件投影产物，不可直写；drift 为真时以事件重算为准。
- 读取必须自证完整性：截断（truncated）不等于全部，按游标续读后再下结论。
- 未知字段用显式未知标记，不用空串或零值冒充「已知为零」。

## 三、确认门与资金红线

- 事实确认门（`decide_event`）只属拍板岗；导入车道也只在拍板岗，避免未定型事实从旁路进入。
- 资金执行（资金池、代收代付、分账执行）一律拒绝——二清红线，资金走客户自选持牌通道；数量面只记数量，不记资金。

## 四、如实口径

事件类型未登记报 `EVENT_UNKNOWN_TYPE`，状态不允许报 `EVENT_STATE`，接口不可达报 `NOT_WIRED`；不把截断结果当全集，不把一个单位当另一个单位。
