# 三步使用指南模板（`guide.steps`）

装上 pack 之后，用户会先看到这三步。**必须恰好 3 步**，每步 `title` ≤60 字符、`body` ≤500 字符。

写法：**用户视角**（用户要做什么），不是功能清单。

## 模板

```json
"guide": {
  "steps": [
    {
      "title": "准备",
      "body": "说明用户要先完成什么。典型是：① 装这个功能集（设置 → 功能集）；② 连接 MCP 市场（设置 → MCP 市场 → 连接，本人的一次点击，管理员代不了）；③ 备好本次要用的材料（贴文本/传文件/说清楚标的）。"
    },
    {
      "title": "开问",
      "body": "给一句可以照抄的示例提问——具体到能直接跑，别写「请描述你的需求」。好例子：「帮我看这份合同里的风险点：<粘贴>」。提醒可以接着说「换一个角度」「展开第 2 点」。"
    },
    {
      "title": "拿到什么",
      "body": "说清产出形式与边界：会得到什么（表格/清单/文档/图表）、什么情况下会说做不到。数据未连接时如实降级——把「取不到就说取不到」写进来，这是对用户的承诺。"
    }
  ]
}
```

## 好坏对照

| 差 | 好 |
|---|---|
| 「先点击设置里的功能集，然后订阅」 | 「装好这个包（设置 → 功能集 → 订阅并安装），再点设置 → MCP 市场 → 连接（这一步必须你本人点）」 |
| 「向助手描述你的需求」 | 「试试：「帮我把这份合同的风险点列出来」——然后粘上合同全文」 |
| 「助手会为你生成专业的分析报告」 | 「你会拿到一张风险清单（条款位置 / 风险等级 / 改法），每条都标了引用来源；原文里找不到的会写『待核』，不会编」 |

## 为什么值得认真写

- 这三步是**用户第一次接触这个 pack 的全部说明**——写清楚，用户 30 秒能用起来；写糊，他装了就闲置。
- 「准备好材料」那步最容易漏，也最影响体验：用户不知道该准备什么，第一句就会问偏。
- 第三步的降级说明是**防幻觉的护栏**：提前告诉用户"取不到会说取不到"，比事后解释便宜得多。
