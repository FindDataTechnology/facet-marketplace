# 发布之后：自查（facet-forge-acceptance）

**发布 ≠ 可用。** 发布只是把内容摆上货架；装得上、跑得通、说得诚实，是另外三件事。

## 一、装机自查（自己试一遍）

用**你自己的账号**走一遍真实路径：

1. 壹座 → 设置 → 功能集 → 找到你的包 → 订阅并安装。
2. 看三样东西是否**都**物化了：
   - 设置 → 技能：你的技能在列表里，**点开能看到内容**（不是空壳）；
   - 设置 → MCP：你的 MCP 服务器在列表里，状态不是报错；
   - 对话选择器：你的角色出现，能选中。
3. 缺哪样，对着下表看：

| 症状 | 大概率原因 | 你能做的 |
|---|---|---|
| 装包时报 `requires group: xxx` | 你的 pack 引用的 server 属于某个用户组，你的测试账号不在组里 | 把包的描述写清"适合谁用"，或换用公开权限的 server |
| 装包时报 `credential-required` | 测试账号还没连过市场凭据 | 用户本人去 设置 → MCP 市场 → 连接（这一步只能本人点，你不能代做） |
| 装包后技能是空的 | 技能内容没进去 | 回去查 manifest 的 `skills[].content` 是否非空 |
| 装包后 MCP 连不上 | server 未在册或组权限 | 用发现工具确认该 server 可用，必要时换一个 |

**重要**：用户在装机时遇到的前两类问题，**不是你 pack 的缺陷**——但它们会影响体验。
所以包描述里写清"需要先连接市场 / 适合哪个用户群"，比事后解释便宜。

## 二、功能自查（让它真干活）

发一条**真实的问题**（不要问"你好"）：

1. 看回答里有没有**真实数据**——数字、条款、案例是否来自工具，而不是模型编的。
2. 在会话的 **trace / 工具调用**视图里确认 `mcp__<server>__<tool>` **真的被调用了**。
   - 工具被调用 + 有结果 = 通了；
   - 没有调用记录但回答里有数据 = **编造**，必须改技能（把"必须调用工具"写死）。
3. 试一次**取不到**的情况（比如问一个你的数据覆盖不到的问题）：
   应该如实说"取不到"，而不是编一个像样的答案。这一条比第一条更重要。

## 三、能改的与改不了的

**你自己能改**（改完重发新版本）：

- 技能内容（措辞、步骤、防编造约束）
- 包名与描述（影响搜索）
- 三样东西的增删（技能/MCP/角色）
- 可见性（public / private）

**要联系平台运营**：

- 需要新的 MCP server（你自己加不了）
- 某个 server 的工具名对不上（登记层的事）
- 调用报计费/额度类错误（`CALLER_NOT_MAPPED` 等）
- 用户组权限开通

**改完记得**：改内容 → 预校验 → 复述确认 → **发新版本**（`packId` 续版）。
已发布的版本不可变，用户装的是他们订阅时的版本；发新版后用户可以升。

## 四、收集反馈

货架上的包可以在 设置 → 功能集 → 我的创作 看到订阅数。
有人装、没人用很常见——回去看技能的第一步（准备）是不是没说清，
或者包描述没让正确的人找到它。
