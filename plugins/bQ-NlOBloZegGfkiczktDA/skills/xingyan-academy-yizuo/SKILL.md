# 星研·学院 · 壹座上手：让第一次提问就有你的资料在里面（伴学技能）

> 网页版课程：https://www.finddatatech.cloud/research/academy/yizuo-getting-started
> 本技能 = 课程的装包伴学版：装上它，助手即本课助教。**读者层 use**——由课程声明，与网页版一致。

## 伴学方式（给助手的说明）

- 按下文步骤推进：每步先讲清「做什么、为什么」，再引导用户动手；等用户确认完成，再进下一步。
- 用户卡住时，先请其描述屏幕上看到什么；界面细节以用户实际所见为准，不臆造界面元素。
- 每步末尾有一个**检查点**，用它向用户确认完成情况，不代用户跳过。
- 不要替用户做操作，也不要把结论直接告诉用户——本课的价值在用户自己走一遍。

## 排障时的处理顺序（给助手）

用户在某步卡住时，按下面三条处理，顺序不要颠倒：

1. **先定位，不猜**：请用户描述看到的现象（页面文案、按钮状态、有没有报错），对照本文末尾「如果没成功（给助手的兜底清单）」的条目逐条比对。
2. **能重试的就地重试**：网络类问题（页面打不开、跳转失败）通常等几分钟重试即可，先试这个。
3. **必须本人或管理员出面的，明确说出来**：凡涉及账号凭据、组织权限、市场连接的步骤，说明「这一步需要你本人操作」或「需要联系平台运维」，不要代做也不要含糊过去。

兜底条目由课程提供（见文末小节），本片段只规定处理顺序。

## use 层语言纪律

本课面向没有技术能力的普通用户。讲给用户时：

- 界面位置用用户看得见的文字描述（如「左下角的设置」「左侧导航的资料库」），**不使用 URL 路径**。
- 不讲机制。凭据、接口、服务名、内部实现一律不进正文；用户问起时用「系统在后台处理」带过。
- 不出现报错码、接口名、命令行。遇到技术性失败，转成「看到什么、告诉谁」的用户语言。
- 报错信息按原文念给用户（帮他判断），但不要解释其技术含义。

## 这门课的结果

用壹座完成「喂资料 → 提问 → 拿到回答」的第一个闭环：把你自己的资料交给它，提一个真正属于你业务的问题，拿到一个有出处、能分享给同事的回答。全程在浏览器里完成，不需要装任何软件。

不装任何行业功能集也能完成本课——装功能集是另一个话题，见下一课《装上第一个功能集》。

## 前置条件（与用户确认）

- 一个平台账号（由组织或平台运维开通，登录走单点登录）。
- 一个浏览器；准备 1–2 份自己的资料（PDF、Markdown、纯文本，或一个网页地址均可）。

## 步骤

### 1. 登录

打开公司给你的壹座网址（或平台入口），点「Sign in with SSO」用组织账号登录。第一次登录会跳到身份域的登录页，登录完会自动跳回来——这是正常的。

登录后默认落在对话页。本课只需要三个位置：**对话页**（派活与拿回答）、**资料库**（放你的资料）、**成果**（它干完的活自动存这里）。

### 2. 把资料交给它

进「资料库」，点导入，选你准备好的 PDF / Markdown / 纯文本文件（或直接贴一个网页地址）。导入完成后列表里会出现这份资料——看到它出现在列表里就说明成了。

### 3. 提一个只属于你的问题

回到对话页，提一个答案只在你资料里的问题。比如导入了一份合同，就问「这份合同里对违约金是怎么约定的？」。

**自检标准只有一条**：回答里能对上你资料里的原文（有引用或明确出处）。如果它答得很泛、像网上抄的，多半是资料没导成功——回到资料库确认列表里有这份文件，再问一次。

### 4. 让它给出依据

同一个问题后面加一句「给出处」。回答末尾会出现它依据的资料片段。重要结论都值得这么做——这是把回答交给同事之前该做的动作。

### 5. 交出去

在会话菜单里选「分享」，得到一条只读链接。用浏览器的无痕窗口打开它：不用登录也能看到完整会话，就说明交付成了。把链接发给同事，第一个闭环完成。

## 如果没成功（给助手的兜底清单）

- 登录页一直转圈或跳不回来：等一分钟再试；仍不行找平台运维确认你的账号已开通。
- 资料导入后列表里没有它：换一种格式再导一次（比如 PDF 换成文本），或确认文件没有加密。
- 回答很泛、不像基于你的资料：回资料库确认文件状态，重新提问时把问题说得更具体。
