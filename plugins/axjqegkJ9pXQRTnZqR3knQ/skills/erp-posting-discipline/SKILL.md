# 过账三岗纪律卡

本卡是过账治理团队（过账层 / 审批流）三岗的运行时纪律。三岗共用一套过账工具面，**权限按岗收窄**：包级 allowTools 只是封顶，真正生效的是每岗 `resources.mcpTools`。

## 一、三岗分工（工具面按岗收窄，不越界）

- **巡检岗（只读）**：`list_posting_rules` / `list_posting_gaps`。盘规则各版本与状态（草稿、生效、退役）、盘缺规则待补清单（哪些事件在等哪条规则）。零写入。
- **核对岗（只到草稿）**：`list_posting_rules` / `list_posting_gaps` / `submit_posting_rule`。对等规则的事件逐条定性，草拟规则：借贷两侧齐全、科目落在机器车道白名单内、同事件类型只提一条；**没有审批门**。
- **拍板岗（唯一审批门）**：`approve_posting_rule` / `post_event` / `list_posting_gaps`。审批规则上线并对已接受事件过账。

## 二、本线纪律

- 规则须人工审批上线；同事件类型只允许一条 active；升版退役旧版本，不重写历史分录。
- 缺规则不猜科目：事件挂入待补清单，账本余额不变，不生成零金额占位分录。
- 过账是已接受事实的确定性派生；拟稿事件未过事实确认门不得过账。
- 待补清单必须逐条有去向：补规则、调整事件类型、或登记不做，不能静默消失。
- 资金类科目不在机器车道白名单内，任何规则都不得把它们写成可写。

## 三、确认门与资金红线

- 规则审批门（`approve_posting_rule`）只属拍板岗；核对岗提交的草稿未经审批不参与过账。
- 资金执行（资金池、代收代付、分账执行）一律拒绝——二清红线，资金走客户自选持牌通道；过账不产生任何资金动作。

## 四、如实口径

缺规则报 `POSTING_RULE_MISSING` 并落待补清单，借贷不平报 `UNBALANCED`，接口不可达报 `NOT_WIRED`；不伪装空成功。
