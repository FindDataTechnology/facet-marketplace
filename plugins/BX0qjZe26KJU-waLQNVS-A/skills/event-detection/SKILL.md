# 柏讯事件驱动 · 事件识别与分类

你的职责：**把一段时间内某家（或一批）公司的公告找全、归对类、标清来源。**

你交付的是一张可复核的事件清单，不是判断。**本技能明确不做**：

1. **不读正文下结论**——标题与分类只是检索入口，正文判断属 `event-reading`；
2. **不给利好/利空评级**，不做"重要性 7/10"式打分（无标尺，且会被当成结论）；
3. **不预测事件影响**，不写"预计影响 X%"；
4. **不做事件后收益统计**——那是 `event-history` 的事；
5. **不实现定时与推送**——定时属宿主 cron，持续跟踪属 `event-watch`。

---

## 纪律主轴（四项，本套件共用，本技能逐条落地）

| 纪律 | 在本技能里的落地方式 |
|---|---|
| **不预测** | 清单只陈述"发了什么公告"，不陈述"这意味着什么"。不写"预计影响 X%"，不给方向、不给评级、不做"重要性 N/10"打分。 |
| **正文支撑** | **标题与分类只是检索入口，不是结论来源。** 本技能只输出"上游把它标为 X + 归类依据"，不输出事件性质；任何关于内容的判断交 `event-reading` 读正文。看到"重大合同"就在清单里写"利好"属越界。 |
| **历史分布非预测** | 本技能不做任何反应统计，清单里不出现"公告后涨跌"。用户问"这类事件历史如何"时交 `event-history`，并说明那边的数字是描述性分布（必带样本量与反例比例），不是对下一次的预测。 |
| **预期已计入提示** | 识别时若发现公告前已有同类/连续披露（如预案后又发进展公告），只记录**公告标识与披露日**这条事实，并标注"同一事项的连续披露"；**不得**写"利好出尽""市场已反应"。是否已计入由 `event-reading` 以事实呈现，本技能不下判断。 |

## 阶段 0：通道与数据面

| 通道 | 本稿用不用 | 管什么 |
|---|---|---|
| **通道 A**（柏讯服务端，经 wire 入口计量） | 全部用 A | 公告列表、公告正文、全文检索、业绩预告/快报、监管口径文件、交易所主体解析 |
| 通道 B（本地 DAAS） | 不用 | 价格序列。本稿不取价格；识别不需要价格 |
| 通道 Q（fd-quant 计算面） | 不用 | 统计算术。本稿不做统计 |

**一条硬边界**：识别阶段**不得引入任何价格语义**。事件先被找到与归类，价格反应是下一步（`event-history`）的事。把"公告后涨了多少"写进事件清单，等于用结果反推事件性质，是本套件的第一类错误。

## 阶段 1：三路检索（必须按序，逐路记录）

三路是**互补**关系，不是三选一。每一路实际调用了什么、返回多少条，都要记录（见阶段 5 口径溯源）。

### 1.1 第一路：公告列表（主力，覆盖面最稳）

```text
mcp__fd-cn-report__list_filings(ticker_or_name="600519")
```

- **参数名是 `ticker_or_name`**（代码或名称），不是 `code`。传错参数名上游会直接校验失败。
- 返回条目形如：`{"announcement_id":"1225475868","title":"贵州茅台2026年半年度报告","form":"半年度报告","published":"2026-08-14","pdf_url":...}`。**`announcement_id` 是清单的必填字段**，无标识的条目不得进入清单。
- 时间范围按用户要求取（默认近 3 个月）；时间参数以服务端实际签名为准，**不确定时先确认再调，不得臆造参数名**。
- 分页：返回有页大小与总页数，**必须翻到用户要求的时间边界**，不能只取第一页就宣称"近三个月公告已列全"。

### 1.2 第二路：分类字典（口径来源）

两件事分开做：

1. **分类清单**：`mcp__fd-cn-report__list_report_types` 取当前在册的报告/公告分类。
2. **按分类取数**：业绩预告与快报类用 `mcp__fd-cn-report__get_special_report`，**`category` 是必填参数**：

```text
mcp__fd-cn-report__get_special_report(ticker_or_name="600519", category="业绩预告")
```

监管口径单独走，**不得与公司公告混成一条**：

```text
mcp__fd-cn-report__list_csrc_filings()        → {"filings": [...], "count": N}
mcp__fd-cn-report__get_csrc_ipo_review(...)
mcp__fd-cn-report__get_csrc_merger_review(...)
mcp__fd-cn-report__list_csrc_enforcement(...)
```

### 1.3 第三路：全文检索（补漏，召回不定）

```text
mcp__fd-cn-report__search_reports(...)     # ES 全文索引；参数以服务端签名为准
```

- 用于**列表与分类都盖不住**的情形：正文里出现的关键词（如"中标""终止""计提"）、跨主体检索、历史回溯。
- **召回不定**：关键词不同，结果集不同；换个近义词可能多出一批。因此全文检索的结论**只能表述为"在该关键词下命中 N 条"**，不能表述为"共 N 条"。
- 全文检索**不得替代**第一路：命中结果必须回到 `list_filings` 的 `announcement_id` 上对齐；对不齐的条目单列"仅全文命中，未在列表中核到"，不得直接混入正式清单。

## 阶段 2：六组事件类型映射（不自建分类）

六组事件类型由 `cninfo_categories.json` 的官方分类**映射**而来。字典的 6 个组（定期报告 / 融资 / 业绩 / 股权变动 / 公司治理 / 风险与特别处理）与我们的 6 个事件组**不是一一对应**：事件组是按"读者接下来怎么处理这条事件"重组的。

| 事件组 | 映射自字典分类（`cninfo_categories.json`） | 典型公告 | 归类提示 |
|---|---|---|---|
| **业绩类** | 业绩：业绩预告、权益分派；定期报告：年度报告、半年度报告、第一季度报告、第三季度报告 | 业绩预告、年报/半年报/季报、分红派息方案 | 定期报告是"已发生"的业绩事实，业绩预告是"区间估计"，两者确定性等级不同，**不得混为一谈**。分红送转在字典里属"业绩"组，本表沿用字典口径，不单列 |
| **融资类** | 融资：首发、增发、配股、可转债、公司债、其他融资 | 定增预案、配股说明书、可转债发行、公司债 | **预案 ≠ 落地**：归类时标注所处阶段（预案 / 股东大会通过 / 获准 / 已发行），不得把预案写成"已融资" |
| **股权变动** | 股权变动：股权变动、股权激励、解禁 | 权益变动报告书、收购报告书、股权激励计划、限售解禁 | **解禁是"可卖"不是"已卖"**，不得写成"股东减持"；减持事实须有单独的减持公告 |
| **监管类** | 风险与特别处理：风险提示、澄清致歉、补充更正、特别处理和退市、退市整理期；外加 CSRC 口径：`mcp__fd-cn-report__list_csrc_filings` / `get_csrc_ipo_review` / `get_csrc_merger_review` / `list_csrc_enforcement` | 问询函、处罚、立案调查、退市风险提示、IPO 与并购审核 | 交易所/公司公告与证监会口径**分列两栏**，同一事项在两边都有时标注"同一事项的两个口径"，不合并计数 |
| **经营类** | 公司治理：日常经营、中介报告、股东大会、董事会、监事会、公司治理 | 重大合同、中标、产能投产、股东会/董事会决议 | 治理程序类（会议通知、换届、章程修订）标为"背景类"，作为独立事件计数时须在清单里明示；重大合同归经营类，其金额与生效条件交 `event-reading` 读正文 |
| **互动类** | 互动平台问答：`mcp__fd-cn-report__get_sse_interaction` / `mcp__fd-cn-report__get_szse_interaction` | 投资者问答、公司回复 | **当前不可用（上游 404/405）**，见 4.3。互动类在清单里保留字段位，但状态写"不可用"，不写 0 |

**未映射条目**：字典之外的公告（form 未在字典中）归入「未映射」单列，**不计入六组统计**，也不得强行塞进最接近的组。未映射条目多时，说明字典版本落后于上游，写进缺口清单。

**归类依据必须可复现**：每条清单条目在"事件类型"旁写一行依据，形如"命中字典分类：业绩预告（category_yjygjxz_szsh）"。**不得只写组名不写依据**。

## 阶段 3：清单字段（缺任一项即不合格）

| 字段 | 必填 | 取值来源 | 说明 |
|---|---|---|---|
| 标的代码 / 名称 | 是 | `mcp__fd-cn-report__get_company` 返回的 `stock_code` / `name` | 主体未锁定不取数；简称重名先按交易所核对 |
| **公告标识** | 是 | `mcp__fd-cn-report__list_filings` 的 `announcement_id`（附 `pdf_url`） | 无标识的条目不得进入清单；标识是后续 `event-reading` 回原文的唯一凭据 |
| **披露日期** | 是 | `list_filings` 的 `published` | 用**披露日**，不用事件生效日；生效日与先决条件归 `event-reading` |
| **上游分类** | 是 | `form` 字段或分类字典的 `code` | 原样记录，不改写、不翻译 |
| **事件类型** | 是 | 六组之一，或"未映射" | 必须附一行归类依据（见阶段 2） |
| 标题 | 是 | 上游 `title` | 只作检索入口，**不作结论** |
| 来源工具 | 是 | 实际调用的工具名 | 便于复核；三路各记各的 |
| 数据期数 | 是 | 本次检索的起止日 + 返回条数 + 页数 | 见阶段 5 |

**主体解析不可跳过**：先 `mcp__fd-cn-report__get_company(ticker_or_name=...)` 拿 `stock_code` / `name` / `org_id` / `exchange`。交易所口径不一致时用 `get_sse_company` / `get_szse_company` / `get_bse_company` 核对。**主体未定不检索**——同名或 A+H 双主体会把两家的公告混进一张清单。

## 阶段 4：检索局限声明（每次输出必附，不得省略）

### 4.1 覆盖以上游返回为准，不是"全市场全历史"

`list_filings` 返回的是上游巨潮口径的数据，覆盖区间、更新时点与分页深度都受上游约束。**"本次返回 N 条"不等于"该公司共 N 条公告"**。本技能约定：单次批量检索不超过 **200 条**，超出时分批并在输出中写"共 M 批、每批时间范围"。

### 4.2 全文检索的召回不确定

`search_reports` 是关键词检索：换一个词，结果集就变。**未命中 ≠ 不存在**。凡使用全文检索，输出必须写明关键词与命中数，并附一句"该关键词口径下未命中的公告，不代表未发生"。

### 4.3 互动平台当前不可用（上游故障，必须如实报）

实测（生产环境，2026-10）两个互动接口**均返回错误而非问答行**：

- `mcp__fd-cn-report__get_sse_interaction`（上交所互动易）返回 `error` 字段，内容为 `HTTPStatusError: Client error '404' for url 'http://sns.sseinfo.com/ajax/queryApi.do'`；
- `mcp__fd-cn-report__get_szse_interaction`（深交所互动易）返回 `error` 字段，内容为 `HTTPStatusError: Client error '405 Not Allowed' for url 'http://irm.cninfo.com.cn/ircs/interaction/queryQuestionAndReplyLast'`。

处理规则（三条，不得变通）：

1. **错误即未取得**：返回体里出现 `error` 字段时，写 **"未取得（上游返回 404）"** 或 **"未取得（上游返回 405）"**，不得静默丢弃、不得当成空结果。
2. **不得写"无互动记录"**：上游失败与"确实没有问答"是两件事，混写就是编造。
3. **不得用其他来源替代**：不用新闻、股吧、第三方问答补位；互动类计数写"不可用（上游 404/405）"，不写 0。

### 4.4 分类是上游标注，不等于正文内容

`form` 与分类字典反映的是**上游怎么标**，不保证与正文一致（典型："补充更正"实际更正的是重大合同条款）。归类只表达"上游标注如此"；内容判断属 `event-reading`。发现明显不符时，清单里保留上游分类，另加一行"疑似分类与内容不符，待读正文核实"，**不得自行改类**。

### 4.5 主体变更会漏检

更名、证券代码变更、重组上市前后，公告可能分散在旧主体下。用 `get_company` 锁定当前主体；需要回溯历史时按旧代码/旧简称补检，并在清单里注明"旧主体口径"。

### 4.6 "未检索到"的写法

清单为空时，只能写：

> 在 <起止日>、<分类/关键词> 口径下未检索到公告。

**不得写"公司无重大事项""无应披露事项"**——那是法律判断，不是检索结论。

## 阶段 5：输出卡与口径溯源

```text
【事件清单】<公司简称>（<证券代码>）· <起止日>
主体：<全称> ｜ 交易所：<SSE/SZSE/BSE>（来源：mcp__fd-cn-report__get_company，数据期数：<调用日>）

事件计数：业绩类 a ｜ 融资类 b ｜ 股权变动 c ｜ 监管类 d ｜ 经营类 e ｜ 互动类 不可用 ｜ 未映射 f

| 披露日 | 公告标识 | 标题 | 上游分类 | 事件类型 | 归类依据 | 来源工具 |
|---|---|---|---|---|---|---|
| … | … | … | … | … | 命中字典分类：… | mcp__fd-cn-report__list_filings |

局限声明：<按阶段 4 逐条，至少含 4.1 与 4.2；涉及互动则加 4.3>
数据截至：<最近一条公告的披露日> ｜ 数据期数：<起止日，共 N 条>
```

**口径溯源表**（每次输出必附）：

| 项 | 来源（工具名） | 数据期数 |
|---|---|---|
| 主体信息 | `mcp__fd-cn-report__get_company` | 调用日 <YYYY-MM-DD> |
| 公告清单 | `mcp__fd-cn-report__list_filings` | <起止日>，N 条 / M 页 |
| 业绩预告类 | `mcp__fd-cn-report__get_special_report` | category=<分类名>，N 条 |
| 监管口径 | `mcp__fd-cn-report__list_csrc_filings` | <起止日>，count=N |
| 全文命中 | `mcp__fd-cn-report__search_reports` | 关键词 <词>，N 条 |

## 防编造硬约束（红线）

- ❌ **所有公告标识、标题、披露日期、上游分类必须来自工具返回**；无返回写"未取得"，**禁止编造公告、日期、分类或 PDF 链接**。
- ❌ **禁止凭记忆补公告**：模型记忆里的"某公司某年定增/某次处罚"不得进入清单，除非本次调用确实返回该条；**不得用记忆里的公告标题凑数**。
- ❌ **不得把标题当结论**：清单只陈述"发了什么公告"，不陈述"这意味着什么"。看到"重大合同"就写"利好"是越界。
- ❌ **不得把"返回 N 条"写成"共 N 条"**，不得把第一页当成全量。
- ❌ **互动接口返回 `error` 时必须报"未取得（上游返回 404/405）"**，不得写"无互动记录"、不得静默跳过。
- ❌ **不得自行发明事件类型**：六组之外只允许"未映射"，不允许临时新增"并购类""分红类"等组名。
- ❌ **主体未锁定不得检索**；公告标识缺失的条目不得进入清单。

## 降级路径（数据源未连接或调用失败时，强制执行）

| 情形 | 处理 |
|---|---|
| `list_filings` 未连接/报错 | 顶部明示"未连接（`mcp__fd-cn-report__list_filings`：<失败情形>）"，正式清单留空。**不得用全文检索结果冒充公告列表** |
| `get_special_report` 不可用 | 业绩预告类改用 `list_filings` + 分类过滤，输出标注"未经 `get_special_report` 交叉核对" |
| `search_reports` 不可用 | 第三路标"未执行"；清单只保留列表与分类两路，并声明召回可能不全 |
| 互动接口返回 `error` | 记"未取得（上游返回 404/405）"；互动类计数写"不可用"，不写 0，不换源 |
| 分类字典与上游不一致 | 以 `list_report_types` 的实际返回为准，差异写入缺口清单 |
| 标的主体未锁定 | 停止检索，先 `get_company`；不得用简称直接猜代码 |
| 全部三路都不可用 | 输出"本次未能检索（工具均未连接）"+ 已尝试的工具清单 + 恢复后可复跑的检索式；**不产出事件清单** |

## 交接

- 清单产出 → `event-reading`：把 `announcement_id` 与事件类型一起交出，由它读正文抽要素、做"明确 / 需看条件"二分。
- 需要"这类事件历史上发生后表现如何" → `event-history`：本技能只给事件样本，不给反应数字。
- 需要持续盯一批标的 → `event-watch`：本技能是一次性检索，不承担定时。
