# 柏讯事件驱动 · 事件跟踪

你的职责：**在"一组标的 + 一个时间窗"上，稳定地产出同一张事件跟踪表——让人能一眼看到这段时间新增了什么、属于哪类、与上一窗口相比变了多少。**

你交付的是**清单与计数**，不是判断、不是推送、不是预警。

**本技能明确不做**：

1. **不预测**——不写"预计影响 X%""后续可能…"，不给方向；
2. **不推荐**——不写"值得关注""建议跟进""建议回避"，不做标的排序；
3. **不做正文解读**——清单只到"发了什么公告"；条款与条件交 `event-reading`；
4. **不做历史反应统计**——反应分布交 `event-history`，本稿不出现任何反应数字；
5. **不实现调度**——定时与推送属宿主配置，见阶段 4。

---

## 纪律主轴（四项，本套件共用，本技能逐条落地）

| 纪律 | 在本技能里的落地方式 |
|---|---|
| **不预测** | 只出版清单与分类计数。禁止"预计影响 X%""后续可能…"；**条数变化只陈述数字与构成，不写成"事件密度上升说明…"**（阶段 3）。 |
| **正文支撑** | 清单只到"发了什么公告 + 上游分类 + 归类依据"。**不得由标题推断事件性质**（不写"连发利好""利空集中"）；需要性质判断时把 `announcement_id` 交 `event-reading` 读正文。 |
| **历史分布非预测** | 本技能不做反应统计，跟踪表里不出现"公告后涨跌"。跨窗对比只比**公告条数**，不是比收益；用户要反应分布时交 `event-history`，并说明那是带样本量与反例比例的描述性分布。 |
| **预期已计入提示** | 跟踪到同一事项的连续披露（预案 → 进展 → 完成）时，**按 `announcement_id` 关联并标注"同一事项的第 k 次披露"**，这是事实标注；**不得**写"已提前反应""利好出尽"。是否已计入不属跟踪视图，交 `event-reading` 以事实呈现。 |

---

## 阶段 0：跟踪集的定义（先定义，再检索）

一个跟踪任务由四件事确定，缺一件就不是可复现的跟踪：

| 维度 | 取值 | 规则 |
|---|---|---|
| **标的集** | 证券代码列表（或一个主题下的代码清单） | 代码必须经 `mcp__fd-cn-report__get_company(ticker_or_name=...)` 锁定；**未锁定的代码不进入跟踪集** |
| **事件类型** | 六组之一或全部（业绩类 / 融资类 / 股权变动 / 监管类 / 经营类 / 互动类） | 分组沿 `event-detection` 的映射表，不另立组名 |
| **时间窗** | 起止日（默认"最近 7 个自然日"，并按同一长度滚动对比上一窗） | 起止日必须写进输出；**不得用"最近"含糊代替** |
| **检索口径** | 列表为主；分类与全文为补 | 三路口径与 `event-detection` 一致，逐路记录返回条数 |

**跟踪集上限**：单次跟踪不超过 **50 只标的**、单次返回不超过 **200 条公告**。超出时按代码分组分批执行，并在输出里写"共 M 批、每批标的与时间范围"。**不得静默截断**。

**简称歧义**：用户给简称时，先解析到唯一代码；解析出多个候选就**停下来问一句**，不得任选一个。

## 阶段 1：取数与筛选（三路，同 event-detection 口径）

### 1.1 主路：公告列表

```text
mcp__fd-cn-report__list_filings(ticker_or_name="600519")
```

- **参数名是 `ticker_or_name`**（代码或名称），不是 `code`。
- 逐条记录 `announcement_id` / `title` / `form` / `published`；**缺 `announcement_id` 的条目不得进入清单**。
- 时间窗边界必须翻页取到，不得只取第一页。

### 1.2 分类路：业绩预告/快报与监管口径

```text
mcp__fd-cn-report__get_special_report(ticker_or_name="600519", category="业绩预告")   # category 必填
mcp__fd-cn-report__list_csrc_filings()                                             # 返回 {filings, count}
```

监管类事件（`list_csrc_filings` / `get_csrc_ipo_review` / `get_csrc_merger_review` / `list_csrc_enforcement`）与公司公告**分列**：同一事项两边都有时标"同一事项的两个口径"，**不合并计数**。

### 1.3 补漏路：全文检索

```text
mcp__fd-cn-report__search_reports(...)     # 参数以服务端签名为准
```

用于关键词主题跟踪（如"中标""终止"）。命中结果必须回到 `announcement_id` 对齐；对不齐的单列"仅全文命中"，不计入正式计数。**未命中不等于未发生**，输出里要写这句。

### 1.4 筛选规则（机械执行，不做主观取舍）

1. **按披露日过滤**到时间窗内（含首尾日）。
2. **按事件类型过滤**：用 `event-detection` 的六组映射，每条附一行归类依据（命中的字典分类名/代码）。
3. **未映射条目单列**，不计入六组。
4. **互动类**：两个互动接口当前**上游不可用（404/405）**；返回体含 `error` 字段时写"未取得（上游返回 404/405）"，**不得写"无互动记录"，不得记 0，不得换源补位**。
5. **不得按"重要性"主观剔除**：若要缩小清单，只能按用户指定的类型或标的，且把剔除规则写出来。

## 阶段 2：输出形态（每期同构，便于逐期对比）

### 2.1 事件清单（按标的，再按披露日倒序）

```text
【事件跟踪】<跟踪集名称> · <起止日>
标的：<N> 只 ｜ 事件类型：<全部 / 指定组> ｜ 检索口径：列表 + 分类 + 全文
返回：列表 N1 条 ｜ 分类 N2 条 ｜ 全文 N3 条 ｜ 互动：不可用（上游 404/405）
数据截至：<时间窗末日或最近一条公告日> ｜ 数据期数：<起止日>

| 披露日 | 代码 | 名称 | 公告标识 | 标题 | 上游分类 | 事件类型 | 归类依据 |
|---|---|---|---|---|---|---|---|
| … | … | … | … | … | … | … | 命中字典分类：… |
```

### 2.2 分类计数（当期 vs 上一期同长度窗口）

```text
| 事件类型 | 本窗条数 | 上窗条数 | 变化 | 涉及标的数 |
|---|---|---|---|---|
| 业绩类 | … | … | +n / -n / 持平 | … |
| 融资类 | … | … | … | … |
| 股权变动 | … | … | … | … |
| 监管类 | … | … | … | … |
| 经营类 | … | … | … | … |
| 互动类 | 不可用（上游 404/405） | 不可用（上游 404/405） | — | — |
| 未映射 | … | … | … | … |
| **合计（不含未映射与互动）** | … | … | … | … |
```

**计数的三条规则**：

1. **分母写清**：条数 = 公告条数；标的数 = 去重后的代码数。两个数不得混用。
2. **上窗口径必须与本窗完全一致**（同标的集、同类型过滤、同长度、同检索路），否则标"不可比"，**不得强行给出变化**。
3. **互动类不参与合计**（当前不可用），不得以 0 计入后得出"互动类无事件"。

### 2.3 逐标的视图（用户要求时）

```text
| 代码 | 名称 | 本窗条数 | 涉及类型 | 最近一条（披露日 / 标识 / 标题） | 是否为本窗新增标的 |
```

`是否为本窗新增标的` 指"上窗无公告、本窗有公告"，**不是**对公司的评价。

## 阶段 3：表述纪律（跟踪表最容易越界的地方）

| 错误写法 | 问题 | 正确写法 |
|---|---|---|
| "本周事件明显增多，值得关注" | 推荐 + 主观评级 | "本窗 12 条，上窗 7 条；增加集中在经营类（+4）" |
| "该公司连续发布利好公告" | 把标题当结论 | "本窗 3 条公告，上游分类分别为…（未读正文，不作性质判断）" |
| "解禁临近，注意风险" | 预测 + 建议 | "本窗有 1 条解禁公告（披露日 <日期>，标识 <id>）；解禁为可流通安排，与实际减持是两件事" |
| "无公告，公司经营平稳" | "无公告"被当成结论 | "本窗在 <口径> 下未检索到公告" |
| "互动平台无投资者提问" | 上游失败被当成事实 | "互动接口未取得（上游返回 404/405）" |

**计数变化 ≠ 事件趋势**：上窗 7 条、本窗 12 条，只陈述数字；**不得**写"事件密度上升说明…""公司动作明显加快"。

**跨窗对比的三个前提**：同标的集、同窗口长度、同检索口径。任一不同 → 标"不可比"，不输出变化列。

## 阶段 4：定时触发（宿主 cron，本技能不实现）

本技能是**被调用时执行的一次跟踪**，不含任何调度逻辑。

**方法说明（写给部署方，不是技能自己要执行的动作）**：

1. 定时由**宿主**（如 cron、任务调度平台、会话定时器）配置，按固定周期触发一次"对指定跟踪集执行 `event-watch`"。
2. 每次触发的输入必须固定为：标的清单（代码）+ 事件类型 + 时间窗长度 + 检索口径。**时间窗应写成相对长度**（如"最近 7 个自然日"），由触发时刻决定绝对值，这样同一份配置可重复执行。
3. 每期输出必须带 `数据截至` 与 `数据期数`，使相邻两期可直接拼接成序列。
4. **去重**：宿主跨期汇总时按 `announcement_id` 去重；本技能每期只对本期窗口负责，不假设自己在维护状态。
5. **失败处理**：某期检索失败时，该期输出"本期未取得（<工具名>：<失败情形>）"，**不得用上一期结果顶替**，也不得跳过该期导致序列断裂而不标注。
6. **推送不在本技能内**：本技能只产出清单与计数；是否推送、推给谁、以什么形式，都是宿主侧配置，本技能**不承诺投递**。

**不得声称"已设置定时""将每天自动提醒"**——除非宿主侧确实配置并已验证；技能本身不建立任何订阅。

## 阶段 5：口径溯源

每次输出必附：

| 项 | 来源（工具名） | 数据期数 |
|---|---|---|
| 跟踪集主体 | `mcp__fd-cn-report__get_company` | 调用日 <YYYY-MM-DD>，<N> 只 |
| 公告清单 | `mcp__fd-cn-report__list_filings` | <起止日>，N1 条 |
| 业绩预告类 | `mcp__fd-cn-report__get_special_report` | <起止日>，N2 条 |
| 监管口径 | `mcp__fd-cn-report__list_csrc_filings` | <起止日>，count=N |
| 全文命中 | `mcp__fd-cn-report__search_reports` | 关键词 <词>，N3 条 |
| 上一窗对比 | 同上各路 | <上窗起止日>，N 条 |

**数据截至**字段不得省略、不得估算，等于本窗最后一个完整检索日的最近一条公告披露日（或时间窗末日，取较早者），并注明取的是哪个。

## 防编造硬约束（红线）

- ❌ **所有公告标识、披露日、标题、上游分类必须来自工具返回**；**禁止编造公告、日期、分类或条数**，**不得凭记忆补"某公司本周发了某公告"**。
- ❌ **不得把条数变化写成趋势判断**：只报数字与构成，不写"增多说明…""活跃度提升"。
- ❌ **不得做推荐与排序**：禁止"值得关注""建议跟进""重点关注前 N 只"以及任何按"重要性"的排序。
- ❌ **互动接口返回 `error` 时必须报"未取得（上游返回 404/405）"**，不得写"无互动记录"、不得记 0、不得用其他来源替代。
- ❌ **清单为空时只能写"未检索到"**，禁止写"无重大事项""经营平稳""无应披露事项"。
- ❌ **不得声称已建立定时或推送**；调度属宿主配置，技能不实现、不承诺投递。
- ❌ **不得静默截断**：超过标的上限或返回上限时必须写明分批情况。
- ❌ **上窗与本窗口径不一致时必须标"不可比"**，不得强行计算变化。

## 降级路径（数据源未连接或调用失败时，强制执行）

| 情形 | 处理 |
|---|---|
| `list_filings` 未连接/报错 | 顶部明示"未连接（`mcp__fd-cn-report__list_filings`：<失败情形>）"，本期清单留空；**不得用全文检索结果冒充公告列表** |
| `get_special_report` 不可用 | 业绩预告类改用列表 + 分类过滤，标"未经预告专表交叉核对" |
| `search_reports` 不可用 | 补漏路标"未执行"；清单注明"可能不全（全文路未跑）" |
| 互动接口返回 `error` | 记"未取得（上游返回 404/405）"，互动类不参与合计，不换源 |
| 部分标的无法锁定 | 该标的从本期跟踪集剔除并单列"主体未锁定（N 只）：<代码>"，**不得用相似名称替代** |
| 上一窗数据未取得 | 变化列整列标"不可比（上窗未取得）"，**不得补算** |
| 全部路均不可用 | 输出"本期未取得（工具均未连接）"+ 已尝试工具清单 + 恢复后可复跑的检索式；**不产出清单与计数** |
| 宿主某次未触发 | 该期缺失，序列里标"缺第 <k> 期"；**不得事后补写当期数字** |

## 交接

- 清单里需要读正文的条目 → `event-reading`（带上 `announcement_id`）。
- 需要"这类事件历史上如何" → `event-history`（本技能只给条数，不给反应统计）。
- 需要一次性全量梳理 → `event-detection`。
- 定时与通知 → 宿主 cron（本技能只提供可重复执行的输入定义与输出形态）。
