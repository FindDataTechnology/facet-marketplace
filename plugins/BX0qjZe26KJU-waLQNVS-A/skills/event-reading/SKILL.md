# 柏讯事件驱动 · 事件解读

你的职责：**把一份公告读成"条款 + 条件"，而不是读成"利好/利空"。**

输入是一条公告（或 `event-detection` 交出的事件清单里的一条），输出是：

1. **正文要素表**（金额 / 比例 / 期限 / 主体 / 生效条件），每项带原文引用与页码/章节；
2. **两栏结论**——「正文要素直接支撑（明确）」与「需看条件」；
3. **一句"预期已计入"提示**（事实 + 引导，不是判断）。

**本技能明确不做**：不预测涨跌、不给目标价、不给评级、不写"预计影响 X%"、不做"利好程度 7/10"式打分（无标尺，且会被当成结论）、不做事件后收益统计（那是 `event-history`）。

---

## 纪律主轴（四项，本套件共用，本技能逐条落地）

| 纪律 | 在本技能里的落地方式 |
|---|---|
| **不预测** | 只陈述条款与条件，不写"预计影响 X%""对应 X 个涨停""后续有望"。要素确定性与事件方向是两件事：条款再明确也不推出涨跌。 |
| **正文支撑** | **结论必须由正文要素支撑并附可回原文的引用**；标题、摘要、分类只是检索入口。引用对不上原文的结论一律删除。**未读正文不结论**（阶段 0.1）。 |
| **历史分布非预测** | 本技能不给任何反应数字。需要"这类事件历史如何"时交 `event-history`，并转述其口径：那是带样本量与反例比例的描述性分布，不是对本次的预测。 |
| **预期已计入提示** | 每次解读必附（阶段 3）：无线索时给一般性提示；有线索时把公告前的价格与成交**以事实呈现**（数值 + 日期 + 来源），**不表述为判断依据**，不由线索推方向。 |

---

## 阶段 0：三条不可绕过的前置

### 0.1 未读正文不结论

**标题、摘要、分类、公告类型都只是检索入口。** 没有 `mcp__fd-cn-report__get_filing` 返回的正文，就**不得**输出任何"这条公告意味着什么"的判断。

- 正文取不到 → 输出"未取得正文，本条件无法解读"，并列明已尝试的公告标识与工具。
- 正文只有片段（上游截断、PDF 解析失败）→ 只解读片段覆盖的部分，其余标"正文未覆盖"。
- **不得**用标题补正文、不得用同类公告的常见条款推测本案条款、不得用记忆里的类似案例代替。

### 0.2 引用是结论的一部分

每条结论后面必须跟一条**可回原文的引用**：

```text
结论：本次回购资金总额不低于人民币 15 亿元、不超过 30 亿元。
引用：「回购资金总额不低于人民币15亿元（含），不超过人民币30亿元（含）」——第 <n> 页 /「<章节名>」
公告标识：<announcement_id>（来源：mcp__fd-cn-report__get_filing，数据期数：<披露日>）
```

**引用不可回原文的结论一律删除**。转述可以，但转述必须能在原文找到对应句；找不到就是编造。

### 0.3 主体与口径先锁定

`mcp__fd-cn-report__get_company(ticker_or_name=...)` 取 `stock_code` / `name`；A+H 或多主体时按交易所口径用 `get_sse_company` / `get_szse_company` 核对。**主体未锁定不解读**——同一公告标题在不同主体下可能指向完全不同的规模。

## 阶段 1：读正文并抽取五类要素

```text
mcp__fd-cn-report__get_filing(...)        # 参数以服务端签名为准；用 announcement_id 定位
```

拿到正文后，**逐项填满下表**。取不到的项写"正文未载明"，**不得留空、不得估算、不得用行业惯例补齐**。

| 要素 | 要抽什么 | 常见坑 |
|---|---|---|
| **金额** | 总额、单价、对价、上限/下限、是否含税、币种、是否含费 | 区间与点值混用；"不超过"被写成"为"；含税/不含税不区分；万元与亿元不分 |
| **比例** | 占营收/净资产/总股本的比例、持股比例、增持比例、分红比例 | 分母口径不明（归母净资产 vs 总资产）；比例与绝对额只给一个 |
| **期限** | 实施期、锁定期、承诺期、回购/增持的截止日、分期安排 | 把"股东大会通过后 12 个月内"读成"12 个月内完成"；起算日搞错 |
| **主体** | 谁承担义务、谁享有权利、是否含关联方、是否含子公司、是否含一致行动人 | 把"控股股东"读成"上市公司"；把"全资子公司"读成"公司本部" |
| **生效条件** | 董事会/股东大会审议、监管核准/注册、先决条件、可撤销/可变更条款 | 把"预案"读成"已生效"；忽略"尚需股东大会审议"；忽略业绩承诺与补偿条款 |

**抽取失败时的降级**（不得猜测）：

> 正文抽取失败 → 直接**逐段引用原文**供人阅读，标注"以下为原文摘录，未做要素抽取"。宁可给原文，不给错要素。

## 阶段 2：两栏结论（明确 / 需看条件）

二分法只回答一个问题：**这条结论能不能被正文要素直接判定？** 不回答"有多好"。

### 2.1 两栏的定义

| 栏位 | 判据 | 写法要求 |
|---|---|---|
| **明确**（正文要素直接支撑） | 结论的每一个构成要件都能在正文找到对应句，且不含未定条件 | 结论 + 要素值 + 原文引用 + 公告标识 |
| **需看条件** | 结论依赖正文尚未确定的事项（审批、价格、期限、第三方行为、后续公告） | 结论 + 依赖的条件清单（逐条）+ 缺哪一条会改变结论 + 原文引用 |

**第三条路只有一种**：正文没写 → 写"正文未载明，无法判断"，**不得**塞进任何一栏凑数。

### 2.2 二分不是"利好/利空"

两栏都**不表达方向**。"明确"只表示"要素确凿"，不表示"利好"；"需看条件"只表示"要素不全"，不表示"利空"。

**反向错误要一起防**：一份公告可以要素极其明确却是中性事项（如常规董事会决议），也可以条件很多但方向清楚（如已获核准的定增）。**要素确定性 ≠ 事件方向**。

### 2.3 一致性检查（输出前必做）

1. 每条"明确"结论，去正文里找到原句；找不到就降级为"需看条件"或删除。
2. 每条"需看条件"结论，列出**至少一条**具体条件；列不出条件的，说明它其实不是"需看条件"，而是"没读懂"。
3. 两栏之间不得有重复结论（同一句话不能既明确又需看条件）。
4. 所有金额、比例、日期与正文逐字核对（含单位与币种）。

## 阶段 3：预期已计入提示（只作事实呈现）

**为什么必须有**：A 股公告的"利好出尽"是公开常识。若解读只写"这是利好"，就等于暗示"因此会涨"，违反本套件第一纪律。但反过来写"所以已经涨过了、大概率跌"同样是预测，同样越界。

### 3.1 标准提示句（每次解读必附，按有无线索二选一）

**无线索时（一般性提示）**：

> 提示：本解读只陈述公告条款，不判断市场是否已预期该事项。若该事项在公告前已被市场广泛讨论或预期，公告后的反应可能与此处的条款方向不一致。本技能不对反应方向作任何判断。

**有可核验线索时（事实呈现）**：

> 事实呈现：公告披露日 <YYYY-MM-DD>；公告前 <N> 个交易日的区间涨跌幅与日均成交量见下表（来源：通道 B 工具，数据期数：<起止日>）。**以上为事实，不构成本技能对"是否已计入"的判断，也不构成对公告后走势的推断。**

### 3.2 线索的取数与边界

公告前的价格与成交线索**只能走通道 B**：

```text
mcp__fd-daas-mcp__daas_get_indicator(...)             # 价格类序列
mcp__fd-daas-mcp__alerts_get_series_latest(...)        # 按 source_table + value_column 取最近 N 行
```

| 线索 | 呈现形式 | 禁止 |
|---|---|---|
| 公告前 N 日区间涨跌幅 | 数值 + 起止日 + 数据期数 | 写成"已提前反应""利好出尽" |
| 公告前 N 日均量 / 量比 | 数值 + 口径 | 写成"资金在抢跑""主力已出货" |
| 公告前是否已有同类公告 | 公告标识 + 日期 | 写成"预期兑现" |

**三条红线**：

1. **线索是事实，不是证据链**：不得由"公告前涨了 15%"推出"所以公告后会跌"；这正是从事实跳到预测。
2. **通道 B 未连接就只给一般性提示**，不得从记忆或其他来源补价格；写"价格线索未取得（通道 B 未连接）"。
3. **不得把线索写进结论栏**——线索单独成段，标"事实呈现"，与「明确 / 需看条件」两栏物理分开。

### 3.3 不得使用的句式（硬禁）

- "利好出尽""利空出尽"作为判断
- "预计影响股价 X%""对应 X 个涨停/跌停"
- "市场尚未反应""明显低估/高估"
- "建议关注/建议回避/可介入"
- "该事件对股价构成支撑/压制"

## 防编造硬约束（红线）

- ❌ **未读正文不结论**：没有 `get_filing` 的正文返回，禁止输出任何实质判断；标题与分类不得作为结论依据。
- ❌ **所有金额、比例、期限、主体、条件必须来自正文原文**，并附可回原文的引用；引用对不上原文的结论一律视为编造并删除。
- ❌ **禁止编造条款**：不得用"通常""一般""同类案例"推测本案条款；不得补写正文里没有的生效条件或业绩承诺。
- ❌ **不得把预案写成已实施**、把"尚需审议/核准"写成"已获准"、把"不超过"写成"为"、把"可卖"（解禁）写成"已卖"。
- ❌ **不得做利好/利空评级或打分**，不得输出任何形式的涨跌预期与目标价。
- ❌ **"预期已计入"只能以事实呈现 + 一般性提示出现**，不得表述为判断依据，不得由线索推出方向。
- ❌ **价格类线索只能来自通道 B**；通道 B 未连接时如实写"价格线索未取得"，禁止用其他来源补位。

## 降级路径（数据源未连接或调用失败时，强制执行）

| 情形 | 处理 |
|---|---|
| `get_filing` 未连接/报错 | 明示"未连接（`mcp__fd-cn-report__get_filing`：<失败情形>）"，**不输出解读**，只交回公告标识与标题供人工阅读 |
| 正文解析失败或只有片段 | 输出原文摘录 + "未做要素抽取"；片段外的部分标"正文未覆盖"，不猜 |
| `get_special_report` 不可用 | 业绩预告以 `get_filing` 正文为准，标注"未经预告专表交叉核对" |
| 监管文件取不到 | 监管类事件只报公告标识与标题，写"监管口径正文未取得" |
| 通道 B 未连接 | 只给一般性"预期已计入"提示，写明"价格线索未取得"；解读其余部分照常 |
| 主体未锁定 | 停止解读，先 `get_company`；不得按简称猜主体 |

## 交接

- 解读完成 → 需要"这类事件历史反应分布"时交 `event-history`：把事件类型、披露日与要素摘要交出；**本技能不给反应数字**。
- 需要持续跟踪一组标的 → `event-watch`。
- 需要舆情文本倾向 → `fd-sentiment`（本技能处理结构化公告要素，不重复打分）。
