# 柏讯 · 事件驱动

柏讯事件驱动四件套：事件识别（公告列表/分类/全文三路检索，六组事件类型映射，附公告标识与日期）、事件解读（读正文抽要素：金额/比例/期限/主体/生效条件，明确与需看条件二分，结论须引原文）、历史反应统计（多窗口收益分布 + 样本量 + 分位 + 必选的反例比例，明确是历史分布不是预测）、事件跟踪（按标的/类型筛选与统计，不含预测与推荐）。与柏讯舆情和投研套件的分工：舆情看文本倾向，投研做论点综合，本套件只处理结构化事件（公告/监管/业绩），不猜情绪也不给结论。核心纪律：不预测（不给涨跌预期、不说预计影响百分比）、正文支撑（标题与分类只是检索入口）、历史分布非预测（必须同时给反例比例）、预期已计入提示。公告是事实，解读是本套件的判断，两者分开呈现。不构成投资建议。

## 技能

- event-detection — 柏讯事件驱动 · 事件识别与分类。当用户要求"这家公司最近有什么公告/大事""近三个月事件梳理""哪些公司发了业绩预告""把公告按事件类型分一下"时使用。三路检索（公告列表 / 分类字典 / 全文检索），把公告归入六组事件类型（业绩类、融资类、股权变动、监管类、经营类、互动类），逐条附公告标识、披露日期、上游分类与归类依据。只做识别与分类：不读正文下结论、不判断利好利空、不做反应统计（分别交给 event-reading 与 event-history）。
- event-reading — 柏讯事件驱动 · 事件解读。当用户要求"这条公告到底说了什么""这个定增/减持/业绩预告怎么看""把公告关键条款摘出来"时使用。读公告正文（get_filing），抽取金额、比例、期限、主体、生效条件五类要素，把结论分成"正文要素直接支撑（明确）"与"需看条件"两栏，每条结论引用原文并给出公告标识。硬约束：未读正文不结论，标题与分类只是检索入口。不做涨跌预测，不给买卖建议；对"预期已计入"只作事实呈现与一般性提示。
- event-history — 柏讯事件驱动 · 历史反应统计。当用户要求"这类事件历史上发生后表现如何""业绩预增公告后 20 天一般怎么走""帮我看看这个事件类型的历史分布"时使用。对同类事件做多窗口（默认 5/10/20 个交易日）的历史反应统计：样本量、分位数、均值与离散度，并强制给出反例比例与样本门槛。全部输出为描述性历史分布，不是预测；样本不足不下结论；口径（按分类或按关键词）随结果一并写出。不提供涨跌预期、不给买卖建议。
- event-watch — 柏讯事件驱动 · 事件跟踪。当用户要求"帮我盯住这几家公司""每天把公告按类型筛一遍""按标的或事件类型给我一张事件跟踪表"时使用。按标的与事件类型筛选公告流，输出事件清单、分类计数与期间对比（本周 vs 上周等），并明确标注检索口径与数据截至日期。不做预告、不做推荐、不预测影响；定时触发属宿主 cron 配置，本技能只提供被调用时的方法与输出形态，不实现调度。

## MCP 连接指引

本插件声明以下 MCP 引用（**不随插件自动连接**——插件本体不携带任何服务器配置或凭据）：

- **fd-cn-report** — 端点 `https://mcp.finddatatech.cloud/fd-cn-report/mcp`（需要组：wire-customers）
- **fd-quant** — 端点 `https://mcp.finddatatech.cloud/fd-quant/mcp`（需要组：wire-customers）
- **fd-daas-mcp** — 端点 `https://mcp.finddatatech.cloud/fd-daas-mcp/mcp`（需要组：wire-customers）
- **wire-build-mcp** — 端点 `https://mcp.finddatatech.cloud/wire-build-mcp/mcp`（需要组：wire-customers）

连接方式：支持 MCP OAuth 的客户端可直接对该端点授权；否则用谦面 CLI 铸取调用键后写入本机配置：

```
npx @finddatatechnology/facet connect
npx @finddatatechnology/facet install <packRef> --target workbuddy --write-mcp
```
