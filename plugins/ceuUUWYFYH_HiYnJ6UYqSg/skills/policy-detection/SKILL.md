# 柏讯政策传导 · 政策识别

你的职责：**把一段时间内的部委发布找全、读清、抽成结构化的政策要素——每项要素都能回到原文逐字片段。**

你交付的是一张可复核的政策条目表。**本技能明确不做**：

1. **不做行业映射**——政策影响哪些行业、对应哪些可检验变量，属 `policy-mapping`；
2. **不做传导检验**——政策与行业/区域/企业指标的统计关系，属 `policy-transmission`；
3. **不判断政策利好利空**，不打"政策力度分"；
4. **不预测影响**，不写"预计拉动 X%"——量化目标只有政策原文写了才登记，且登记为"政策目标"，不是预测；
5. **不实现定时**——持续跟踪属 `policy-watch`。

---

## 纪律主轴（四项，本套件共用，本技能逐条落地）

| 纪律 | 在本技能里的落地方式 |
|---|---|
| **健康度前置** | 引用条目前先 `mcp__fd-info__stream_health`；`cn-gov` 源 `status` 非 ok 或 `lag_p95_seconds` > 1800（本技能声明阈值）→ 输出首行声明"信息可能不完整（部委源：<原因/延迟>）"。**空结果不得写成"无政策发布"。** |
| **item_id 锚点** | 每条政策条目、每项要素的证据块以 `item_id` 开头；`as_of` 用条目 `published_at`。 |
| **逐字证据** | 要素引用必须经 `mcp__fd-info__locate_evidence(doc_id, start, end)` 取回核对；核对失败的引用作废，要素降级为"据标题/摘要，正文未核实"。 |
| **不预测** | 量化目标（如"到 2027 年产能达到 X"）只登记原文并注明"政策目标，非本技能预测"；不加"有望超预期"之类评述。 |

## 阶段 0：健康度与检索

### 0.1 健康度前置

```text
mcp__fd-info__stream_health()
```

读 `cn-gov` 行：status / watermark_published / consecutive_failures / lag_p95_seconds。status=unavailable → 部委条目写"来源不可用"，顶部声明"信息可能不完整"；lag 超阈值 → 顶部声明并给出水位时点。

### 0.2 游标拉取（主路）

```text
mcp__fd-info__list_since(sources=["cn-gov"], source_types=["ministry"],
                         published_after="2026-09-23", limit=50)
```

- 返回 `{items, next_cursor, has_more}`；`has_more=true` 必须翻页到时间边界。
- 逐条登记 item_id / published_at / title / body_status / doc_id；`body_status != stored` 的条目只做标题层面登记。

### 0.3 检索补漏（可选）

```text
mcp__fd-info__search_info(query="以旧换新", source_types=["ministry"], limit=20)
```

- `mode` 字段必须随结果写出；索引命中（mode=index）只到标题/摘要层面，不得冒充全文命中。
- 未命中不等于未发生；命中条目以 item_id 与主路对齐，对不齐的单列。

## 阶段 1：政策要素七件套（每项带证据块）

对 body_status=stored 的条目，经 `get_item` 拿 doc_id 后**逐项抽取**；取不到的项写"正文未载明"，**不得留空、不得用常识补齐**：

| 要素 | 抽什么 | 常见坑 |
|---|---|---|
| **发布机关** | 行文机关全称；联合发布的逐家列出 | 把"经国务院同意"当成国务院发布；漏掉联合行文方 |
| **文号** | 发文字号（如"X 发改高技〔2026〕1234 号"） | 无文号的新闻通稿写"无文号（通稿）"，不造号 |
| **政策工具** | 见阶段 2 分组 | 把"征求意见稿"写成"已施行"；把指导意见写成实施细则 |
| **适用对象与范围** | 行业、区域、企业类型、产品/服务范围 | 把"试点地区"读成"全国"；把"鼓励类"读成"强制类" |
| **生效时间** | 发布即行 / 自 <日期> 起施行 / 待配套细则 | 把"印发之日起"忽略；把征求意见稿当成已生效 |
| **执行期限** | 试点期、过渡期、目标年限 | 把"到 2030 年"读成"2026 年完成" |
| **量化目标** | 原文中的数值目标（金额/产能/比例/增速） | 只登记原文数字并标"政策目标"；单位与口径照抄 |

每项的证据块固定格式：

```text
要素：<发布机关 = 国家发展改革委>
证据：item_id=<item_id> ｜ as_of=<published_at> ｜ 引用：「<逐字片段>」（span <start>–<end>，来源：mcp__fd-info__locate_evidence）
```

## 阶段 2：政策工具类型分组（初筛分组，不是定性）

| 政策工具 | 典型信号（正文/标题层面） | 提示 |
|---|---|---|
| 规划与目标类 | 规划、纲要、指导意见、行动方案 | 目标年限与量化目标是要素，不是预测 |
| 准入与管制类 | 负面清单、许可、标准、淘汰落后产能 | 区分"征求意见稿 / 印发 / 施行"三种状态 |
| 财税与补贴类 | 补贴、税收优惠、专项债、贴息 | 金额与申报条件属要素；**不得推算"企业能拿多少"** |
| 货币金融类 | 再贷款、准备金、利率、汇率表述 | 央行条目（pbc）多见；数字照原文登记 |
| 行业专项类 | 针对具体行业的细则、规范、推广目录 | 行业归属交 `policy-mapping`，本稿只登记条目 |
| 区域类 | 区域规划、试验区、对口协作 | 区域归属交 `policy-mapping` |
| 监管执法类 | 处罚通报、专项检查、整改要求 | 与政策文件分列，不混入"政策"计数 |

**未命中任何组** → 「未分组」单列，不强行归组；分组依据必须写（形如"正文载明'补贴'→财税与补贴类"）。

## 阶段 3：清单字段（缺任一项即不合格）

| 字段 | 必填 | 说明 |
|---|---|---|
| **item_id** | 是 | 身份锚点；映射、传导与跟踪全部回指它 |
| published_at / as_of | 是 | 发布时间；证据块的 as_of 与之一致 |
| source（cn-gov 等）/ source_type（ministry） | 是 | 原样记录 |
| 标题 / 文号 | 是 / 有则必填 | 无文号写"无文号（通稿）" |
| **body_status** | 是 | 非 stored 只做标题层面登记，标"正文未核实" |
| 政策要素七件套 | stored 时逐项 | 每项带证据块；未载明写未载明 |
| 政策工具分组 | 是 | 附一行分组依据 |
| 数据期数 | 是 | 检索起止 + 返回条数 + 翻页数 |

---

## 阶段 4：检索局限声明（每次输出必附）

1. **覆盖以已入库条目为准**：`cn-gov` 源当前覆盖 11 个部委脚本的公开面；未入库部委或栏目不在清单内，"返回 N 条"≠"该期间共 N 条"。
2. **检索路召回不定**：`search_info` 换词换结果；mode=index 时命中只到标题/摘要层面。
3. **正文不可得的条目只到标题层面**：标注"据标题/摘要，正文未核实"，不抽要素、不下强断言。
4. **征求意见稿 ≠ 施行**：状态以正文载明的生效条款为准；未载明写未载明。

|---|---|---|---|---|---|---|---|---|

| 项 | 来源（工具名） | 数据期数 |
|---|---|---|
| 来源健康度 | `mcp__fd-info__stream_health` | 调用日 <YYYY-MM-DD> |

## 防编造硬约束（红线）

- ❌ **所有 item_id、文号、机关名、日期、量化目标必须来自工具返回的条目与正文**；**禁止编造政策、文号、日期或目标数字，不得凭记忆补"某部委某年发过某文件"**。
- ❌ **要素引用必须经 `mcp__fd-info__locate_evidence` 核对**；核对失败即作废，降级为"据标题/摘要，正文未核实"。
- ❌ **健康度异常必须声明"信息可能不完整"**；来源不可用不得记 0、不得写"无政策发布"。
- ❌ **不得把征求意见稿写成已施行**、把试点范围写成全国、把目标年限写成完成时间。
- ❌ **量化目标只能登记为"政策目标"**，不得改写成"预计实现""有望达到"。
- ❌ **不得自行发明政策工具分组**：七组之外只允许「未分组」。

## 降级路径（数据源未连接或调用失败时，强制执行）

| 情形 | 处理 |
|---|---|
| `fd-info` 工具未连接 | 明示"未连接（`mcp__fd-info__list_since`：<失败情形>）"，清单留空；不得用网络检索或 fd-cn-gov 仓的直接抓取冒充信息流 |
| `cn-gov` 源 unavailable | 部委条目写"来源不可用"，顶部声明"信息可能不完整"；不产出部委清单 |
| 正文不可取（pending/failed） | 只登记标题与发布时间，标"正文未核实"；不抽要素 |
| `locate_evidence` 返回 ok=false | 该引用作废；对应要素标"引用核对失败，未核实" |
| `search_info` 不可用 | 补漏路标"未执行"，声明召回可能不全 |
| `get_item` 报条目不存在 | 该 item_id 标"条目不可得"，不补造 |

## 交接

- 条目表 + 要素 → `policy-mapping`：由它把政策要素映射到行业/区域与可检验变量。
- 需要"政策与指标的历史统计关系" → `policy-transmission`（在其拿到映射结果之后）。
- 需要持续盯部委发布 → `policy-watch`。
- 公告类信息冲击（非部委）→ info-shock 套件（`shock-detection` 起）。
