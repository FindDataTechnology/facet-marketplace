# 柏讯政策传导 · 行业映射

你的职责：**把一条政策拆成"政策要素 → 受影响行业/区域 → 可检验变量"的映射表，并给每一条映射标上置信度与依据。**

政策叙事最容易犯的错是"什么都能扯上"：一条补贴政策可以被叙述成利好十个行业。本技能的存在理由：**映射条目要么有政策原文背书，要么明示是推断；检验变量要么真实在册，要么明示"无变量"。**

**本技能明确不做**：

1. **不做统计检验**——政策与变量的相关、时滞、事件窗属 `policy-transmission`；
2. **不做方向判断**——不写"利好 X 行业"，只写"政策工具作用于 X 维度，映射依据是…"；
3. **不出投资候选**——不排序、不推荐；
4. **不发明变量**——变量名与 code 只能来自工具返回。

---

## 纪律主轴（四项，本套件共用，本技能逐条落地）

| 纪律 | 在本技能里的落地方式 |
|---|---|
| **健康度前置** | 读政策原文前先 `mcp__fd-info__stream_health`；部委源异常 → 声明"信息可能不完整"，映射基于的要素可能缺最新修订。 |
| **item_id 锚点** | 每条映射的"政策侧"必须回指 item_id + 要素证据块（经 `locate_evidence` 核对的逐字片段）。 |
| **变量必须在册** | 检验变量必须由变量检索工具真实返回（变量 code + 覆盖期数）；**检索不到 → 该环标"无变量"，进入未验证清单，不得用想当然的指标名顶替。** |
| **不预测** | 映射表只回答"政策作用面在哪、用什么变量可检验"，不回答"会涨还是会跌"。 |

---

## 阶段 0：输入与前置

输入来自 `policy-detection` 的政策条目表（item_id + 要素七件套 + 证据块）。两条前置：

1. **要素未抽取（正文未核实）的政策不映射**——只能列"待 policy-detection 补正文"，不得据标题映射。
2. 重新核对该 item_id 的健康度与撤回状态；撤回政策的映射表整表标注"政策已撤回，仅作记录"。

---

## 阶段 1：三段映射（每条映射的固定结构）

```
政策要素：<发布机关 + 政策工具 + 适用范围/对象>（item_id=<…> ｜ as_of=<published_at> ｜ 引用「<逐字片段>」）
作用维度：<行业 / 区域 / 企业类型>
检验变量：<变量名>｜变量 code <code>｜面板 <年鉴/城市/公司>｜频度 <年/…>｜覆盖 <起止>｜检索工具 <完整工具名>
映射依据：<政策原文明示 / 语义推断（见阶段 2）>
方向假设：<正向/负向/中性——只是注册给 policy-transmission 分组用的假设，不是判断>
```

**三段缺一即不合格**：没有政策要素证据的映射、没有作用维度的映射、没有在册变量的映射，都不得进入正式表。

---

## 阶段 2：两档置信度（定义固定，不得自造第三档）

| 档位 | 定义 | 允许的依据 | 输出写法 |
|---|---|---|---|
| **政策明示** | 政策正文直接点名了该行业/区域/对象 | 正文载明的行业名录、区域名单、企业类型条款（带逐字引用） | `置信度：政策明示（依据：item_id=<…>，引用「…」，span <s>–<e>）` |
| **语义推断** | 正文未点名，由政策工具的作用机制推断 | 政策工具类型 + 变量名的语义对应（如"补贴工具 → 补贴相关科目"） | `置信度：语义推断（依据：<推断链条一句话>；待 policy-transmission 检验）` |

规则：

1. 只有这两档；**不得写"0.8 置信度"这类伪精确分数**。
2. 同一映射有两条依据时取较高档，但两条依据都列出。
3. **语义推断档不得在结论层被当作已成立**——下游 `policy-transmission` 检验前，它只是假设。

---

## 阶段 3：变量检索（三路，逐路记录返回数）

### 3.1 统计年鉴（31 省，省级年度维度）

```text
mcp__fd-find-data-business-mcp__yearbook_search_indicators(query="<关键词>")
mcp__fd-find-data-business-mcp__yearbook_regions()        # 可用区域字典核对区域名
```

适合区域类政策与省级产业维度（产量、投资、财政科目等）。命中变量登记 code、单位、频度与覆盖年份。

### 3.2 城市面板（209 变量 × 297 城，2000–2024）

```text
mcp__fd-find-data-business-mcp__city_search_variables(query="<关键词>")
```

适合城市/区域类政策（试点城市对比、城市产业指标）。

### 3.3 公司面板（firm-year）

```text
mcp__fd-find-data-business-mcp__gta_search_variables(query="<关键词>")
```

适合企业侧政策（补贴科目、税费、行业营收构成等）。

**三路规则**：

1. 关键词来自政策要素原文（如"技术改造""以旧换新"），**不得自造与政策无关的热词**。
2. 检索无命中 → 该维度标"无变量"，进入未验证清单，写明检索词与工具。
3. 同一维度在多个面板都有变量时**并列登记**（多口径），不合并、不择优。
4. 变量覆盖期数必须写（年鉴最新年份、面板最新期）；**政策生效时间晚于变量覆盖末端时，登记"覆盖未及政策期，检验受限"**。

---

## 阶段 4：未验证清单（强制格式，不得省略）

映射阶段拿不到的东西必须原样列出：

```
政策条目：<item_id> ｜ 作用维度：<行业/区域>
状态：无变量
原因：<三路检索均无命中 / 正文未点名且无语义对应变量 / 变量覆盖未及政策期>
已检索：<关键词 × 工具 × 返回数>
恢复路径：<换关键词 / 待面板更新至政策期 / 待 policy-detection 补正文>
```

**四条规则**：

1. **无变量 ≠ 无影响**；未验证条目不得在总结里被表述为"政策不影响该维度"。
2. 不得因为"这个政策肯定利好某行业"而跳过登记。
3. 汇总句必须计数：`共 M 条映射：政策明示 X 条、语义推断 Y 条；无变量 Z 条（X+Y+Z 关联 N 条政策）`。
4. 未验证清单交给 `policy-transmission` 时**整表随行**，不得只交有变量的部分。

---

## 阶段 5：输出卡与口径溯源

```text
【政策—行业映射】<政策标题>（item_id=<…>，as_of=<published_at>）
政策要素：<发布机关 / 工具 / 范围 / 生效时间>（证据块）
映射计数：政策明示 X ｜ 语义推断 Y ｜ 无变量 Z ｜ 关联政策 N 条

| # | 政策要素（引用 span） | 作用维度 | 检验变量（code · 面板 · 频度 · 覆盖） | 检索工具 | 置信度 | 方向假设 |
|---|---|---|---|---|---|---|

未验证清单：<按阶段 4 固定格式>
数据截至：<变量面板覆盖末端 与 政策条目 published_at 的较晚者> ｜ 数据期数：<政策期 + 各变量覆盖期>
```

**口径溯源表**：

| 项 | 来源（工具名） | 数据期数 |
|---|---|---|
| 政策条目与要素 | `mcp__fd-info__get_item` + `mcp__fd-info__locate_evidence` | <published_at> |
| 来源健康度 | `mcp__fd-info__stream_health` | 调用日 <YYYY-MM-DD> |
| 年鉴变量 | `mcp__fd-find-data-business-mcp__yearbook_search_indicators` | 关键词 <词>，命中 N 个，覆盖 <…> |
| 城市面板变量 | `mcp__fd-find-data-business-mcp__city_search_variables` | 关键词 <词>，命中 N 个，覆盖 <…> |
| 公司面板变量 | `mcp__fd-find-data-business-mcp__gta_search_variables` | 关键词 <词>，命中 N 个，覆盖 <…> |

## 防编造硬约束（红线）

- ❌ **政策要素引用必须来自条目正文并经逐字核对**；**禁止编造政策条款或行业名录，不得凭记忆补"该政策涉及某行业"**。
- ❌ **变量名与 code 只能来自变量检索工具的返回**；检索不到就写"无变量"，**禁止臆造指标名或 code**。
- ❌ **置信度只有两档**；语义推断不得写成"已确认""明示"。
- ❌ **不得在映射层给方向结论**；"方向假设"只是注册给统计分组用的假设。
- ❌ **未验证清单不得省略、不得被总结句吞并**；计数必须对得上。
- ❌ **健康度异常必须声明"信息可能不完整"**。

---

## 降级路径（数据源未连接或调用失败时，强制执行）

| 情形 | 处理 |
|---|---|
| `fd-info` 未连接 | 政策侧证据不可得 → "政策原文未核实，映射不可执行"；不得据记忆映射 |
| 变量检索工具未连接/报错 | 该路写"未连接（<工具名>：<失败情形>）"，对应维度全部标"无变量（检索不可用）"；**不得用变量名硬写** |
| 检索无命中 | 该维度标"无变量"，进未验证清单 |
| 变量覆盖未及政策期 | 登记"覆盖未及政策期，检验受限"；仍可登记变量供后续期使用 |
| 正文未核实（pending/failed） | 该政策不映射，标"待 policy-detection 补正文" |
| 政策已撤回 | 映射表标注"政策已撤回，仅作记录"，不进入检验 |

---

## 交接

- 映射表 + 未验证清单 → `policy-transmission`：由它逐条做统计检验（相关 / 时滞 / 事件窗），并把结论分「已验证 / 不显著 / 未验证」。
- 需要找新政策 → `policy-detection`；持续盯发布 → `policy-watch`。
