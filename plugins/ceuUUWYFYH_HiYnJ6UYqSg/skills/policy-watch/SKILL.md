# 柏讯政策传导 · 政策跟踪

你的职责：**在"部委来源 + 时间窗"上稳定产出同一张政策跟踪表——这段时间新增了什么发布、属什么政策工具、健康度水位到哪里、哪些新条目撞上了已登记的政策事项或已验证链路。**

你交付的是**清单与计数**，不是判断、不是推送。

**本技能明确不做**：

1. **不预测**——不写"预计拉动 X%""后续可能…"；
2. **不推荐**——不写"值得关注""建议布局"；
3. **不抽政策要素**——要素七件套属 `policy-detection`；本稿只到条目与分组；
4. **不做映射与检验**——属 `policy-mapping` / `policy-transmission`；本稿对已验证链路只做**命中登记**，不新增结论；
5. **不实现调度**——定时属宿主 cron（阶段 4）。

---

## 纪律主轴（四项，本套件共用，本技能逐条落地）

| 纪律 | 在本技能里的落地方式 |
|---|---|
| **健康度前置** | 每期先 `mcp__fd-info__stream_health`；`cn-gov` 源 `status` 非 ok 或 `lag_p95_seconds` > 1800（本技能声明阈值）→ 表头前置"信息可能不完整（部委源：<原因/延迟>）"。**不可用不得记 0、不得写"无政策发布"。** |
| **item_id 锚点** | 清单逐条带 item_id；同一事项的修订（item_id 不变、updated_at 变）标"同一事项的修订版"，不新增计数；跨期汇总按 item_id 去重。 |
| **命中登记不新增结论** | 新条目命中已验证链路的要素（同机关 + 同工具类型 + 同范围关键词）时，只写"命中已验证链路 <链路名>（原结论：r=<…>，n=<…>，窗口 <…>）"，**原样转引，不得顺延为新结论**。 |
| **不预测** | 条数与构成只陈述数字；政策工具计数变化不写成"政策转向""力度加大"。 |

---

## 阶段 0：跟踪集定义

| 维度 | 取值 | 规则 |
|---|---|---|
| **来源** | 默认 `cn-gov`（部委） | 源名原样传入 `sources`；需要公告侧政策线索时另列 `cninfo` 行，不混计数 |
| **条目类型** | `ministry`（默认） | 三型原样传入 `source_types` |
| **政策工具组** | 沿 `policy-detection` 七组 | 分组依据逐条附 |
| **时间窗** | 起止日（默认最近 7 个自然日，同长度滚动上窗） | 起止日写进输出；**不得用"最近"含糊代替** |

**上限**：单期单次返回 ≤ 500 条（`limit` 上限）；超出按 `next_cursor` 分批并写明"共 M 批"。**不得静默截断**。

## 阶段 1：取数

### 1.1 主路：游标拉取

```text
mcp__fd-info__list_since(sources=["cn-gov"], source_types=["ministry"],
                         published_after="<窗口起点>", limit=50)
```

- `has_more=true` 时翻页到窗口边界；页数计入数据期数。
- 逐条登记 item_id / published_at / title / body_status / withdrawn；缺 item_id 不得进入清单。

### 1.2 补漏路：检索（可选）

```text
mcp__fd-info__search_info(query="<政策关键词>", source_types=["ministry"], limit=20)
```

- `mode` 随结果写出；索引命中只到标题/摘要层面。未命中不等于未发生；命中回到 item_id 对齐，对不齐单列。

### 1.3 健康度快照（每期必取）

```text
mcp__fd-info__stream_health()
```

逐源登记 status / watermark_published / last_success_at / consecutive_failures / lag_p95_seconds，与清单同版面。

## 阶段 2：输出形态（每期同构）

### 2.1 条目清单（published_at 倒序）

```text
【政策跟踪】<跟踪集名称> · <起止日>
健康度：cn-gov <status>（水位 <watermark_published>，lag p95 <X>s，连续失败 <n>）
（异常时前置：信息可能不完整（<原因>））
检索口径：游标 mcp__fd-info__list_since（M 页）｜ 检索 mcp__fd-info__search_info（关键词 <词>，mode=<…>）
返回：本窗 N1 条（正文 stored a / pending b / failed c）｜ 撤回 d

| published_at | item_id | 标题 | 政策工具组 | 分组依据 | body_status | 命中登记 |
|---|---|---|---|---|---|---|
```

「命中登记」列：撞上已登记政策事项写"同一事项的第 k 次披露"；撞上已验证链路写"命中链路 <名>（原结论转引）"；否则留空。

### 2.2 政策工具计数（当期 vs 上窗）

```text
| 政策工具组 | 本窗 | 上窗 | 变化 | 正文 stored 占比 |
|---|---|---|---|---|
| 规划与目标 / 准入与管制 / 财税与补贴 / 货币金融 / 行业专项 / 区域 / 监管执法 / 未分组 | … | … | … | … |
```

**计数规则**：上窗口径必须与本窗完全一致，否则整列标"不可比"；撤回条目单列不计入正常计数；failed 居多时注明"标题层面计数"。

### 2.3 已验证链路命中表（用户要求或套件内交接时）

```text
| 已验证链路（原结论 r / n / 窗口） | 本窗命中条目（item_id） | 是否需重跑检验 |
|---|---|---|
```

第三列只有两种取值："需重跑（政策出现实质性修订，如适用范围/生效时间变化）"或"无需重跑（常规进展披露）"。**是否实质修订的判断依据只能是条目正文（stored）与原证据块的差异**；正文未核实时写"无法判断（正文未核实）"。本表**不产生任何新结论**。

## 阶段 3：数据截至与口径溯源

**数据截至** = min(活跃来源 watermark_published, 本窗最后完整检索日)；健康度不可得时降写"最近一条条目的 published_at（健康度未取得，未经在线核实）"。

| 项 | 来源（工具名） | 数据期数 |
|---|---|---|
| 来源健康度 | `mcp__fd-info__stream_health` | 调用日 <YYYY-MM-DD> |
| 部委条目 | `mcp__fd-info__list_since` | <起止日>，N1 条 / M 页 |
| 检索补漏 | `mcp__fd-info__search_info` | 关键词 <词>，mode=<…>，N2 条 |
| 上窗对比 | 同上各路 | <上窗起止日>，N 条 |

---

## 阶段 4：定时触发（宿主 cron，本技能不实现）

1. 定时由宿主配置，按固定周期触发"对指定跟踪集执行 `policy-watch`"。
2. 每次输入固定：来源/类型过滤 + 时间窗长度（相对长度）+ 检索口径。
3. 每期输出带数据截至与数据期数，相邻期可直接拼接。
4. 跨期去重按 item_id；修订条目按最新版计一次并注明修订。
5. 某期失败输出"本期未取得"，**不得用上一期顶替**，不得静默断档。
6. 推送不在本技能内；**不得声称"已设置定时"**。

---

## 防编造硬约束（红线）

- ❌ **所有 item_id、日期、标题、健康度数值必须来自工具返回**；**禁止编造条目与计数，不得凭记忆补"某部委某日发过某文"**。
- ❌ **健康度异常必须前置"信息可能不完整"**；不可用来源不得记 0、不得换源、不得写"无政策发布"。
- ❌ **命中登记只转引原结论（r / n / 窗口原样照抄），不得顺延为新结论**；是否重跑的判断依据只能是正文与原证据块的差异。
- ❌ **不得把计数变化写成政策趋势判断**（"补贴密集出台说明财政发力"之类）。
- ❌ **清单为空只能写"未检索到"**；不得写"部委无新政策"。
- ❌ **不得声称已建立定时或推送**；不得静默截断。

## 降级路径（数据源未连接或调用失败时，强制执行）

| 情形 | 处理 |
|---|---|
| `fd-info` 未连接/报错 | 顶部明示"未连接（`mcp__fd-info__list_since`：<失败情形>）"，本期清单留空；不得用网络检索或 fd-cn-gov 直接抓取冒充 |
| `cn-gov` 源 unavailable | 部委行写"来源不可用"，不参与合计；顶部声明"信息可能不完整" |
| `stream_health` 不可用 | 写"健康度未取得（未经在线核实）"，数据截至降写最近一条 published_at |
| `search_info` 不可用 | 补漏路标"未执行"，注明"可能不全（检索路未跑）" |
| 上窗未取得 | 变化列整列标"不可比（上窗未取得）"，不得补算 |
| 全部不可用 | 输出"本期未取得（工具均未连接）"+ 已尝试工具清单 + 恢复后可复跑的调用式；不产出清单与计数 |
| 宿主某期未触发 | 该期缺失，序列标"缺第 <k> 期"；不得事后补写 |

---

## 交接

- 新条目需要抽政策要素 → `policy-detection`（带 item_id）。
- 新政策需要行业/区域映射 → `policy-mapping`；需要检验 → `policy-transmission`。
- 命中表标"需重跑"的链路 → 把新旧 item_id 一起交回 `policy-transmission` 重做该环。
- 公告侧（非部委）信息冲击跟踪 → info-shock 套件的 `shock-watch`。
