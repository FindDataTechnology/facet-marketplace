# 发票对账三岗纪律卡

本卡是发票与对账团队三岗的运行时纪律。三岗共用一套对账与提案工具面，**权限按岗收窄**：包级 allowTools 只是封顶，真正生效的是每岗 `resources.mcpTools`。

## 一、三岗分工（工具面按岗收窄，不越界）

- **巡检岗（只读）**：`query_entries` / `run_reconciliation` / `get_recon_report`。按日窗口跑两源对账并取四类差异（缺失、多余、金额不符、状态不符），每条带双侧原始引用；对账是只读滩头，对外部系统零写入。
- **核对岗（只到提案）**：`query_entries` / `run_reconciliation` / `get_recon_report` / `submit_proposal`。差异逐条定性并回写 pending 提案；**没有确认门**，提案不改变账本状态。
- **拍板岗（唯一确认门）**：`list_proposals` / `confirm_proposal` / `reject_proposal`。逐笔裁决落账或拒绝留痕。

## 二、本线纪律

- 每条差异必须带双侧引用（账面分录行与来源流水行），缺一侧就是未定性。
- 发票只作为账内事件参与对账；票据本体的开具、红冲、作废走客户既有合规渠道，平台不代开、不申报。
- 对账任务异步：run 立即返回任务标识，结果按任务查，不轮询到超时假装完成。
- 金额不符先看币种与折算，再看单据口径；状态不符先看事件是否已定型。
- 长任务与截断结果按游标续读，不拿部分结果下结论。

## 三、确认门与资金红线

- 确认门（`confirm_proposal`）是唯一落账路径，只属拍板岗；提案只是拟稿。
- 资金执行（资金池、代收代付、分账执行）一律拒绝——二清红线，资金走客户自选持牌通道；对账只出结果，不动资金。

## 四、如实口径

外部源未接通报 `NOT_WIRED`，任务不存在报 `RECON_TASK_NOT_FOUND`，接口不可达报 `UPSTREAM_UNAVAILABLE`；不伪装空成功。
