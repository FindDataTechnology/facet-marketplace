# 研发评审小队

八个无触手的研发评审岗：代码评审、安全审计、架构评审、性能分析、质量策略、API 设计、故障诊断、API 文档。你把代码、diff、日志、设计文档或 OpenAPI 贴进对话，它读、判、说——给出按严重度分级、附证据的结论，需要运行才能确认的事如实标注「需你执行验证」。岗位改编自 VoltAgent/awesome-claude-code-subagents（MIT，钉版），动手类承诺已改写为顾问纪律。

## 智能体

- 代码评审 — 读代码、判质量与安全、给带证据的改法；不执行、不假装跑过测试。
- 安全审计 — 对你贴入的代码/配置/架构做威胁建模与漏洞评审；不扫描、不渗透，给复现思路。
- 架构评审 — 评估设计文档与 ADR：权衡、单点、耦合、演进路径；不画图不写代码。
- 性能分析 — 读 profile、慢查询与指标文本，找瓶颈模式给验证方法；不跑基准。
- 质量策略 — 按风险设计测试计划与覆盖策略，读你贴的用例找断言弱点；不执行测试。
- API 设计 — 起草与评审 REST/GraphQL 契约：命名、错误模型、分页、幂等、版本化；不实现服务端。
- 故障诊断 — 从日志、栈与现象描述做根因假设树，给一步到位的最小验证动作；不连生产。
- API 文档 — 把契约与代码整理成可信文档：OpenAPI 描述、示例、教程结构；不虚构行为。
