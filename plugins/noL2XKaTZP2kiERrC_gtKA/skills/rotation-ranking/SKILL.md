# 柏讯自适应轮动 · 组与组内排序

你的职责：**在 regime 允许的组数内，排出该配哪些组、每组该配哪些标的，并把落选的说清为什么落选**。你不建仓——权重交给 `rotation-portfolio`。

---

## 阶段 0：组的基础（组从哪来）

**组 = 申万 L1（31 类，`801xxx` 编码）**，分类清单来自 `fd-cn-report` 的 `industry_taxonomy.json`（2021 版，31 个 L1 齐全）。

**成分股怎么取**：申万 L1 成分名单来自 `fd-cn-report` 的行业分类文档（`get_section` 取「行业分类」章节），或用部署侧的 `index_component_sw` 成分接口（返回 `证券代码 / 证券名称 / 最新权重 / 计入日期`）。spike 抽样 8 个 L1 全部成功（农林牧渔 103 只、基础化工 412、钢铁 44、有色金属 141、电子 496、汽车 290、家电 93、食品饮料 122，合计 1701 只）。

**价格怎么取**：成分股价格走**通道 B（本地 DAAS）**——`mcp__fd-daas-mcp__daas_get_indicator` / `daas_run_indicator`。**前置：DAAS 已播种该组成分股**（仓库内 `seed_astock_price.py` 是播种路径）。未播种则该组标记数据不足、不参与排序，**不得**改调外部行情 API 绕过通道 B。

**防编造硬约束**：成分名单、权重、价格、IR、Z 分数全部必须来自工具返回；取不到的组如实标为"数据不足"，**不得凭记忆列成分、不得编造权重或统计量**。

**组指数怎么合成（两种，按用户要求选）**：

| 方式 | 口径 | 何时用 |
|---|---|---|
| 等权 | 各成分归一化到首日 1.0 后取算术均值 | 默认。spike 实算通过（电子 5 只成分，末值 0.9904） |
| 权重加权 | 按 `最新权重` 加权 | 用户要求贴近真实指数时；权重需归一化后使用 |

**严禁**：不得写成"使用申万电子指数（801080）的官方收盘序列"——柏讯没有该序列，只有成分股。

**成分股筛选**（进入合成前必须过）：
1. 取 qfq 日线（**通道 B**：`mcp__fd-daas-mcp__alerts_get_series_latest` 或 `daas_get_indicator`；播种路径 `seed_astock_price.py`，其 qfq 走新浪乘法式复权），剔除在评估窗口内**有效 bar 少于 80%** 的成分（停牌/新股）。
2. 剔除**收盘价非正**的行——加法式前复权（如腾讯 qfq）会把老价减成负数，这类数据会污染任何合成。
3. 剩下的成分若少于 **3 只**，该组**标记为数据不足、不参与排序**（不降级为单只代替）。

**门槛的后果必须说清**：universe 小的时候这条门槛会让大多数组直接出局。实测（12 只种子股、7 个组）只有食品饮料凑够 3 只，其余 6 组全部"数据不足"→ 组排序退化为单组。这不是错误，是**如实反映 universe 不够宽**；输出里必须写明"本次仅 N 组满足门槛，轮动实际退化为 N 组选择"，不得为了让结果好看而放宽门槛。

---

## 阶段 1：组强度排序（信息比）

对每个可排序的组，用合成指数收益序列算**信息比**：

```
IR = mean(超额收益) / std(超额收益) × √252
超额收益 = 组日收益 − 基准日收益
```

- **回看窗：默认 120 个交易日**（约半年）。这是本套件的规定值，不是实现自选——输出中必须写明"IR 回看窗 120 日"。
- **基准**：宽基（默认沪深300ETF 510300）。**基准未播种时**：`summarize_information_ratio` 需要 benchmark 参数，缺基准就**如实声明"基准序列未播种，IR 以 0 为基准（即纯收益/波动比），与含基准的 IR 不可横比"**，并给出播种路径（`seed_astock_price.py --symbols 510300`）；**不得静默改用别的序列冒充基准**。

调 `mcp__fd-quant__summarize_information_ratio`，传入组收益序列、基准序列与 `as_of`，拿回 IR 与相关统计量。

**输出组排序表**（按 IR 降序）：

```
排名 | 组（申万 L1） | IR | 年化收益 | 年化波动 | 成分数（有效/总） | 是否入选
```

表下必须带一行口径：`IR 回看窗 120 日 / 基准 <名称或"未播种，以 0 为基准">`。

**入选规则**（由 `rotation-regime` 的判定决定名额）：

| regime | 允许活跃组数 | 现金下限 |
|---|---|---|
| risk_on | 最多 4 组 | 0% |
| neutral | 最多 2 组 | 20% |
| risk_off | 最多 1 组（或全现金） | 60% 起 |

**落选原因必须逐组给出**，至少包含：IR 排名超出名额 / 成分数不足 / 波动率超组上限 / regime 名额限制。

## 阶段 2：组内排序（残差动量 + 稳健 Z）

对每个入选组的成分股：

1. **动量**：取回溯窗（默认 60 个交易日）的累计收益 `Σr_i`。
2. **残差化（口径必须写对）**：对组指数收益做**带截距的 OLS 回归** `r_i = α + β·r_group + ε`，
   **残差动量取 `RM = 60 × α`**，即"回归截距 × 回看期数"，代表剔除组整体涨跌后个股自身的日均超额累积。
   - **不要用"残差之和"**：含截距的 OLS 残差和恒为 0（`Σε ≡ 0` 是正规方程的必然结果），
     按字面实现会让所有个股的残差动量都等于 0、排序完全失效。这是实测踩过的坑。
   - 也可以等价地用 `RM = Σr_i − 60·α − β·Σr_group` 之外的直接口径：**直接用 `60 × α`**，并在输出中注明用的是截距口径。
3. **稳健 Z**：对残差动量做**中位数/MAD 标准化**（`Z = 0.6745·(x − median)/MAD`），并**在 ±3 处截断**（防止单只极端值主导排序）。
   - **成员数 < 3 时稳健 Z 无分辨力**：2 只成员的组 MAD 退化为常数，Z 只会是 ±0.674；1 只成员组残差恒为 0。
     这种情况下必须在表下注明"该组稳健 Z 无分辨力（成员数 N），组内排序仅按残差动量名义值"。
4. 调 `mcp__fd-quant__rank_factor_scores` 完成排序；需要分组收益验证时调 `mcp__fd-quant__compute_grouped_returns`；
   需要回归系数时调 `mcp__fd-quant__compute_factor_exposure`（返回 α 与 β，可直接作为残差动量的输入并交叉校验本地实现）。

**输出组内排序表**：

```
组 | 排名 | 标的 | 残差动量 | 稳健Z（截断后） | 原始Z | 是否被截断 | 是否入选
```

**入选规则**：每组取前 N 只（默认 N=5，可配），且稳健 Z 需 > 0；Z ≤ 0 的一律不入选并注明"残差动量弱于组内中位"。

**截断必须可见**：被截断的标的要在表里标出原始 Z 值，说明"该值极端，已截断至 ±3，排序按截断后"。**不得静默截断**。

## 阶段 3：例外框架（排序结果的修正）

排序是机械的，例外框架处理三种特殊情形（参数与判定规则来自 FinRL-X 的 `exception_framework`）：

| 例外 | 触发条件 | 动作 |
|---|---|---|
| **Z 持续性** | 某标的稳健 Z 连续 K 个交易日（默认 K=3）高于阈值（默认 2.0） | 提升其排序权重（防止"强但刚触发"被埋没） |
| **强信号单触发** | 单日稳健 Z 跳变超过阈值（默认 3.0）且当日组指数未跌 | 单独标记为"强信号"，不因未满足持续性而排除 |
| **再入冷却** | 某标的刚被剔除，冷却期内（默认 10 个交易日）不得重新入选 | 冷却期内即使排名靠前也排除，并注明"冷却中，剩余 N 日" |

三类例外各触发了几次、触发了哪些标的，**必须在输出中列明**（不能只说"应用了例外框架"）。

---

## 阶段 4：口径校验

1. 所有排序只使用 `as_of` 及之前的数据；过 `mcp__fd-quant__check_observation_sufficiency` 确认回溯窗样本够。
2. 组合成与组内排序的输入序列**不得跨 as_of**。
3. 输出附**数据期数汇总**（口径可溯源）：组指数与个股序列的**来源指标名 + 起止日 + 有效点数**，逐项列出。

---

## 降级路径

| 情形 | 处理 |
|---|---|
| 成分股接口不可用 | 明示"无法取得申万成分股，组排序不可进行"，不凭记忆列成分 |
| 价格未播种到 DAAS | 明示"价格通道未就绪（该组成分未播种）"，给播种路径，**不调外部 API 绕过** |
| 某组成分有效数 < 3 | 该组标记数据不足、不参与排序 |
| 基准序列不可用 | 明示"信息比无法计算（缺基准）"，**不以个股自身收益冒充超额** |
| 用户要求"直接用行业指数" | 说明柏讯未采指数序列，只能用成分股合成，并给出合成口径 |

排序完成 → `rotation-portfolio`：把入选组与入选标的、各组 IR、各标的稳健 Z 一并交出去做风险预算建仓。
