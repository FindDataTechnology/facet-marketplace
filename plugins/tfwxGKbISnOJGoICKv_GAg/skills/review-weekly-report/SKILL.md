## 适用与触发
挂 agent-review（周报复盘岗）。每周一 09:20 触发，输入为本周 rectification 记录（本岗工具面无 handoff 工具，不经交接认领，一律以 memory_query 检索取得）；节点外不出周报、不补跑历史周。

## 工作流
1. 触发核对：确认本周一 09:20 触发成立；无触发不动，按输出契约报 blocker，不自行补跑。
2. 定窗口：确定本周统计窗口与数据截止时间（截至触发时刻），周报必须标注该时间。
3. 检索单据：memory_query 以 rectification 为键检索本周各日（rectification/{date}）整改单，逐单 memory_read_page 读明细与状态；一条都检索不到 → 走「本期无单」分支（第 5 步口径），不凭记忆补单。
4. 算三数与复发：完成率 = 已整改 / 总单数；逾期数 = 状态「逾期」的单数；复发 = 同门店同类型问题本周 ≥2 次，逐条列复发清单（门店、问题类型、次数、单据路径）。
5. 分母与源缺口处理：总单数为 0 只写「本期无单」，不出百分比、不编数据；整改回执源未接入时，完成率按现有单据状态计算并显式标注「回执源需接入，暂记不可判定」，不因缺源推断或改写单据状态。
6. 落档周报：memory_write_page 写 weekly/{year}-W{week}，正文结构固定＝先三个数（完成率、逾期数、复发数）→ 复发清单 → 一句结论，并标注数据截止时间与源缺口；只汇总，不追加单店逐条处置。
7. 收尾报数：按共用层·报数包口径执行 report_status（pack ref 收口时核定，本技能不复制其正文）。

## 职责边界
- 只做周度汇总，不做单店逐条处置、不改单据状态、不新建整改单（出单与销项归整改岗）。
- 口径只用段 4 固定两条（完成率、复发定义），不得另造口径；分母为 0 只写「本期无单」。
- 不发消息、不跨队调度、不执行 publish/apply 类动作；记忆中检索不到的数据一律不臆造。
- 无触发不动；本周 rectification 记录缺失或回执源未接入，如实报 blocker，不自行补数。

## 输出契约（report_status 必含）
- summary：一句话周度结论（完成率、逾期数、复发数 + 周报落档路径）；总单数为 0 时首句为「本期无单」。
- 槽位口径：completion_rate=已整改/总单数（分母为 0 时填「本期无单」，不填百分比数字）；recurrence_count=复发清单条目数（同门店同类型本周 ≥2 次的组合数）；report_ready=周报已落档 weekly/{year}-W{week} 记 1，未落档记 0 并附 blocker。
- blockers：触发缺失、本周单据检索为空（区分「本期无单」与「记录缺失」）、回执源未接入等逐条列出；无 blocker 时不得虚列。

## 完成判据
本周检索到的每条整改单要么计入三数与复发清单、要么在 blockers 中说明不可判定原因；周报已落档且含三数、复发清单、结论、数据截止时间与源缺口标注；报数已完成。
