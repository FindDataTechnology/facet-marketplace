# 柏讯组合风险 · 风险预算

你的职责：**把用户给定的分配规则，变成一份满足单票上限与板块上限的 `TargetWeights` 契约实例**，并把约束是"怎样被满足的"讲清楚。你不选标的、不做择时、不做仓位规模建议——"该投多少钱"是用户的资金决策，本技能只处理权重结构。

**防编造硬约束**：权重里的每个数字**必须来自**本稿明示的分配规则与迭代步骤，并且可逐步复算；标的名单**必须来自**用户给定或持仓面返回；板块归属**只能来自**用户确认的分组表。取不到的输入一律标注缺口并停在该步，**禁止编造**标的、板块归属或权重。契约校验被拒时原样转述拒绝原因，**不得**偷偷归一化后重试。

---

## 阶段 0：先划三条边界（用户最容易误解的地方）

1. **只分配权重，不选标的**。候选池与行业分组由用户给定（或来自当前持仓 + 用户指定的候选）。"哪些标的值得配"属于选股/轮动类套件，本稿不越界。
2. **不做优化器**。分配规则必须是明示的三种之一：等权 / 用户给定权重 / 用户给定的组权重再组内等权。不做均值方差优化，也不做"黑箱最优化"——规则不可复算的权重，用户在回撤时无法归因。
3. **不做择时**。本稿只回答"给定这些标的与上限，权重怎么摆"；不回答"现在该不该加仓"。

**与相邻套件的分工**：持仓体检与判定一致性核查属 `pack-decision-review`；风控参数的含义与取舍属 `pack-strategy-lab`；本稿是**把预算纪律应用到用户的实际组合上**。

---

## 阶段 1：输入（缺一项就停在哪一步，不互相掩盖）

| 输入 | 来源 | 缺失时 |
|---|---|---|
| 候选标的（universe） | 用户给定，或 `mcp__fd-paper-trading__list_positions` 的持仓 + 用户指定候选 | 无 universe 则无法预算，停 |
| 账户与现金 | `mcp__fd-paper-trading__list_accounts` → `get_account(account_id)`；持仓 `list_positions(account_id)` | 持仓面不可用时，只能做"纯权重空间"的预算（用户给定 universe），并在输出标注"未核对当前持仓" |
| 板块归属 | 用户确认的分组表（标的 → 板块） | **不得猜测行业**；板块上限退化为"无法施加"，必须明示 |
| 目标现金 | 用户设定（默认 0，即目标投资比例 S = 1） | 未设定时按 0 处理并写明 |
| 单票上限 `max_weight_per_symbol` | 用户设定；起点量级 10% | 未设定时用 10% 并标注"起点量级，非用户设定" |
| 板块上限 `max_weight_per_sector` | 用户设定；起点量级 30% | 未设定时用 30% 并标注同上 |
| 迭代上限 `max_iterations` | 显式参数，默认 50 | 必须回显实际生效值 |
| 上限绑定是否可接受 | 用户选择（默认"可接受"） | 未选择时按"可接受"处理并写明含义（见阶段 2） |

**量级出处**：单票 10% / 板块 30% 是 FinRL-X `apply_risk_limits` 的公开默认值（美股语境）。A 股波动与涨跌停制度不同，这两个数只是**起点**，不是"正确值"；用户改值时必须写明"用户自设"。

**现金口径（必须先讲清）**：本稿的现金目标直接体现在**权重和**上——目标投资比例 `S = 1 − cash_target`，产出权重之和等于 S。`TargetWeights.cash_floor` 是契约字段，契约只校验 `Σweights + cash_floor ≤ 1`；引擎（权重模式回测）把 `cash_floor` 用作**权重上限校验**，**不是**独立的持仓约束——回测快照里 `cash_floor` 回读是 `0.0`，真正留出现金靠的是 `Σweights < 1`。**不要把"设了 cash_floor"理解成"引擎会替你扣出现金"**。

---

## 阶段 2：初始分配（规则必须是三种之一，且明示）

设目标投资比例 `S = 1 − cash_target`，初始权重 `w_i` 之和 = S。

| 规则 | 做法 | 何时用 |
|---|---|---|
| 等权 | `w_i = S / N` | 默认。最简单、最可复算 |
| 用户给定权重 | 按用户给的相对比例归一化到 S | 用户已有明确配置观点时 |
| 组权重 → 组内等权 | 用户给定各板块的预算占比（和 = S），组内标的等分该板块预算 | 用户只想到行业层时 |

**初始分配后先做一次检查**：任一名义权重是否已经超过单票上限或板块上限。超了不返回，直接进入阶段 3 迭代。

---

## 阶段 3：迭代重分配（本技能的核心，规则逐条可见）

**目标**：在保持权重非负、和 ≤ 1 的前提下，让所有单票与板块都不超上限；迭代在**生成阶段**完成。

```
输入：w（Σ = S）、c_sym（单票上限）、c_sec（板块上限）、max_iterations
for k = 1 .. max_iterations:
    1. 找出超限项：
       - 单票超限：w_i > c_sym
       - 板块超限：Σ_{i ∈ 板块} w_i > c_sec
    2. 裁剪超限部分：
       - 单票超限 → 裁到 c_sym
       - 板块超限 → 该板块内按当前权重比例裁到 c_sec
    3. 记本轮裁出的总额 E；若 E = 0 且无违规 → 收敛，跳出
    4. 对每个板块算两个余量：
       板块剩余空间  R_s = c_sec − Σ_{i∈s} w_i
       单票余量之和  H_s = Σ_{i∈s} max(0, c_sym − w_i)
       该板块本轮可吸收容量  C_s = min(R_s, H_s)
    5. 若 Σ C_s = 0：E 全部转入现金（记为"上限绑定"），跳出
    6. 若 E > Σ C_s：全部分配到容量（A_s = C_s），差额 E − Σ C_s 转入现金，
       记"上限绑定"并跳出
       否则按容量比例分到板块：A_s = E × C_s / Σ C_s
    7. 板块内按单票余量比例分：δ_i = A_s × (c_sym − w_i) / H_s
       （因 A_s ≤ H_s，必有 δ_i ≤ c_sym − w_i，不会产生新违规）
    8. w_i += δ_i
    9. 若 k = max_iterations 且仍有违规 → 报告未收敛（列出最后违规项），
       **不返回权重**
```

**为什么用"板块容量"再"板块内单票余量"两级分摊**：只按单票余量摊，同板块的多只标的一起分就会撞穿板块上限；只按板块余量摊，已达单票上限的标的会继续吃预算。两级分摊各自满足一条上限，且**每一级都在容量内按比例**——因此不会产生新违规，违规总数逐轮单调下降，这就是收敛依据。若某一步把超限额裁掉后无处可放（容量为 0 或不够），余额转入现金并明确记为"上限绑定"，**不静默丢弃**。

**四条必须回显的迭代事实**：

1. **迭代上限是显式参数**（默认 50），实际生效值写进输出。
2. **每轮分配按"剩余空间"比例**，不是平均撒；这样已接近上限的标的不会先被填满。
3. **权重和保持 S**（除非上限绑定），本稿**不做**"重新归一化到 1"——归一化会把约束问题变成隐藏的现金变化。
4. **收敛判据是"无任何违规"**，不是"变化小于阈值"；后者会在边界上留下微小违规。

---

## 阶段 4：上限绑定 vs 未收敛（两种结果必须分开说）

| 情形 | 判据 | 处理 |
|---|---|---|
| **收敛** | 所有单票 ≤ 上限、所有板块 ≤ 上限，且 Σweights 仍等于 S | 返回合规权重 |
| **上限绑定（可行但投不满）** | 所有约束满足，但所有板块的可吸收容量 ΣC_s 已为 0，Σweights < S | 若用户接受上限绑定：返回合规权重，多出的比例转入现金并**显式报告**"上限绑定，现金高于目标" |
| **上限绑定（用户不接受）** | 用户要求必须投满 S，而上限使 `Σ c_sym` 或板块上限之和不支持 S | 报告**不可行**（点名哪条上限绑死），**不返回权重** |
| **未收敛** | 达到 `max_iterations` 仍有违规 | 报告**未收敛**，列出最后的违规项与最后一轮权重，**不返回不合规权重** |

**为什么要这么严**：用户拿到的必须是一份能直接过契约的权重。把"没算完"的中间结果返回，等于让契约层替我们兜底——而契约层是拒绝，不是修正。

**典型的上限绑定**：3 只标的、单票上限 10% ⇒ 最多只能投 30%，其余 70% 只能是现金。这不是错误，是上限与 universe 规模的数学后果；输出必须写"本次上限绑定，实际投资比例 30%，现金 70%"，而不是悄悄返回 30%。

---

## 阶段 5：取整与权重和

1. 权重四舍五入到 **6 位小数**。
2. 取整残差**归入现金**（即 Σweights 略小于 S），**不得**强行凑到 S——残差留现金是正常且诚实的形态。
3. 输出 `Σweights`、`cash = 1 − Σweights`、`cash_target`，三者并列，让用户看清"目标现金"与"实际现金"的差别。
4. **权重非负**：负权重会被契约拒绝，本稿不产生负权重，也不支持做空。

## 阶段 6：产出 `TargetWeights` 契约实例

```json
{
  "schema_version": "1",
  "as_of": "2026-10-18",
  "universe": ["600519", "000333", "601318", "600036", "600276"],
  "weights": {
    "600519": 0.16,
    "000333": 0.16,
    "601318": 0.16,
    "600036": 0.16,
    "600276": 0.16
  },
  "cash_floor": 0.2,
  "constraints": {
    "max_weight_per_symbol": 0.2,
    "max_weight_per_sector": 0.3
  },
  "evidence": [
    {
      "evidence_id": "budget-rule",
      "label": "分配规则与迭代上限",
      "value": "等权；单票 0.2 / 板块 0.3；max_iterations=50；首轮即无违规（收敛）",
      "unit": null,
      "as_of": "2026-10-18",
      "source": "portfolio-budget"
    }
  ],
  "producer": {"pack": "wire-portfolio-risk", "skill": "portfolio-budget"}
}
```

**上例为什么合规（输出时必须能这样逐条核对）**：Σweights = 0.80，`cash_floor` = 0.20，`0.80 + 0.20 = 1.00` 落在容差内；单票均 0.16 < 0.20；板块（白酒 / 家电 / 保险 / 银行 / 医药，**每只一个板块**）各 0.16 < 0.30。**示例不是模板**：换成两只白酒就会撞穿 0.30 板块上限，必须重新跑迭代，不得照抄这五个数。

**产出时必须交代的四件事**：

1. **as_of**：权重对应的口径日；此后的数据不得进入本次预算。
2. **约束字段只有两个**：`constraints` 仅含 `max_weight_per_symbol` 与 `max_weight_per_sector`——契约 schema 不接受止损价、换手上限、最小权重等额外字段。风控参数不在这里表达（见 `portfolio-stop-discipline`）。
3. **每个数字的来源链**：初始规则 → 第几轮裁了谁 → 按哪个剩余空间比例分给了谁 → 最终值。
4. **迭代收敛情况**：轮数、是否达上限、是否有上限绑定。

**约束满足表（固定输出）**：

```
标的 | 板块 | 初始权重 | 最终权重 | 单票上限检查 | 所属板块合计 | 板块上限检查
...
迭代：轮数 k / max_iterations；收敛=是/否；上限绑定=是/否
Σweights = X；cash = 1 − X；cash_target = Y
数据期数：持仓与现金取数日（get_account/list_positions 返回日）；价格序列来源 + 起止日 + 有效点数（若用了现价）
```

---

## 阶段 7：层次声明（**必须原样讲给用户**）

> **生成即合规，契约层仍严格。** 本稿的迭代重分配发生在**生成阶段**：产出之前就把超限部分按比例分给了未超限标的，所以交出去的权重已经满足上限。
>
> 契约层不会做第二遍归一化——它对不合规输入是**拒绝**（负权重、Σweights > 1、键不在 universe、`cash_floor + Σweights > 1` 都会被原样拒绝）。因此不能把本稿的迭代理解成"契约层会帮我修"：契约层只负责守门，不负责修补。
>
> 这与 FinRL-X 在策略引擎内部做 `apply_risk_limits` 的语境不同：那是引擎内部步骤；柏讯的纪律是"**产出合规 + 契约边界严格**"。两者不冲突，但不能混为一谈。

## 降级路径（三种缺失互不掩盖）

| 情形 | 处理 |
|---|---|
| **持仓面不可用**（`fd-paper-trading` 调用失败） | 明示"⚠️ 持仓面不可用：本次预算未核对当前持仓与现金"，只做纯权重空间预算（用户给定 universe 与 S）；**不得**编造当前持仓 |
| **价格通道未连接**（通道 B 与 `get_bars` 都取不到价） | 预算本身在权重空间可继续；但"当前权重、当前市值、调仓差额"标注**未计算**，**不得**用成本价或记忆价格代替现价 |
| **计算面不可用**（`fd-quant` 未上牌或调用失败） | 预算主流程不依赖计算面；集中度/换手的事后校验标注"本次未做"，**不得**手算 HHI 后声称来自计算面 |
| **板块归属不可得** | 板块上限标注"无法施加（无板块归属）"，只做单票上限；**禁止**按名称猜测行业 |
| **契约校验被拒** | 原样转述拒绝原因（点名字段与值），修正后重试；**不得**改键、改容差或归一化绕开 |

---

## 防编造硬约束（贯穿全程，红线）

- 标的名单、持仓数量、现金、价格、板块归属**必须来自工具返回或用户明确给定**；**禁止编造**、**不得凭记忆补写**。
- 权重**必须**由本稿规则复算得出；**不得**把"看起来合理"的数字直接写进 `weights`。
- **不得**声称契约层会归一化、会裁剪、会补齐；它只会拒绝。
- **不得**声称引擎会按 `cash_floor` 自动留现金；现金来自 `Σweights < 1`。
- 任何用户自设的上限值都要标注"用户自设"，不得写成"业界标准"。

---

## 口径溯源

- 持仓、现金与账户：标注 `get_account` / `list_positions` 的返回日（**数据期数**）。
- 现价（若使用）：标注通道（通道 B 指标名，或 `get_bars`）+ 序列起止日 + 有效点数（**数据期数**）。
- 上限量级：标注"FinRL-X 公开默认值（美股）"或"用户自设"；不得含糊。
- 迭代过程：轮数、每轮裁剪对象、收敛判据一并保留，便于复算。

---

## 交接

预算完成 → `portfolio-rebalance-plan`：把当前持仓、目标权重与 `TargetWeights` 实例交出去，生成逐标的差额、股数与成本预估，并送权重模式回测验证。

研究参考，不构成投资建议。AI 辅助生成，所有数字以工具返回与用户设定为准。上游 FinRL-X 业绩数字为未经审计的自述回测，不作为预期。
