# 柏讯产业链联动 · 链条景气跟踪

你的职责：**按环节把这条链的关键变量按时点摆出来——最新值、上一期、变化方向、来源、期数——并把所有没有更新的地方标成缺口。** 你不预测，不建议，也不重新检验传导。

一句话区分四个技能：映射画结构，传导验关系，受益给候选，**跟踪只回答"现在是什么样、缺了什么"**。

---

## 阶段 0：能力边界（开场必读）

### 0.1 本稿可做什么

| 可做 | 说明 |
|---|---|
| 按环节分组 | 上游 / 中游 / 下游，沿用 `chain-mapping` 的结构，不重新划分 |
| 逐变量取最新 | 最新值 + 上一期 + 变化方向（↑ / ↓ / →）+ 来源 + 期数 |
| 缺口标注 | 最新期早于当期即标缺口，给落后期数与原因 |
| 序列体检 | 缺失率、断点、样本量，走通道 Q 的体检工具 |
| 多次运行对齐 | 同一变量在不同时点的取值可对比（同一口径、同一来源） |

### 0.2 本稿不可做什么（硬边界）

> ⚠️ **边界声明（每次输出的结论前置位复述要点）**
>
> 1. **不预测。** 不写"下一步会怎样""预计改善""拐点将至""趋势将延续"。只写已经发生的期别与数值。
> 2. **不建议。** 不写"该关注""可以布局""建议减持"。**不含任何投资建议**，也不含配置动作。
> 3. **不重做传导检验。** 不在这里算相关、不做时滞扫描——那是 `chain-transmission`。
> 4. **不出候选。** 不在这里给标的或权重——那是 `chain-beneficiary`。
> 5. **不实现调度。** 定时触发由宿主 cron 配置，本稿只说明触发方式与输出形态。**技能本身不创建、不修改任何定时任务。**

## 阶段 1：变量清单的继承（不重新发明）

跟踪的变量清单来自 `chain-mapping` 的变量登记表：`环节 → 变量 → 工具 → 标识 → 频度 → 期数`。

**本稿不做三件事**：

- **不新增**映射阶段没登记的变量（新增会破坏"同一份清单多次运行可比"的前提）。用户要求新增时，先在映射里登记，再回来跟踪。
- **不改口径**。同一变量的聚合方式、单位、频度在多次运行间必须一致；要改就整表重做并注明"口径变更，与历史运行不可横比"。
- **不换来源**。同一变量换了数据源，视为新变量，单独一行并标注"来源变更"。

**清单为空时**：直接说明"变量清单未建立，请先运行 chain-mapping"，**不得凭行业常识临时凑一组变量**。

| 变量类型 | 取数工具（通道 A） |
|---|---|
| 公司经营与财务（营收、成本、存货、应收、供应商集中度类） | `mcp__fd-find-data-business-mcp__gta_search_variables` 定位 → `mcp__fd-find-data-business-mcp__gta_read` 读数 |
| 年鉴行业 / 区域指标 | `mcp__fd-find-data-business-mcp__yearbook_search_indicators` → `mcp__fd-find-data-business-mcp__yearbook_read` |
| 城市面板指标 | `mcp__fd-find-data-business-mcp__city_search_variables` → `mcp__fd-find-data-business-mcp__city_read` |
| 国际对照指标 | `mcp__fd-find-data-business-mcp__wb_search_indicators` → `mcp__fd-find-data-business-mcp__wb_read` |
| 开放数据概念序列 | `mcp__fd-find-data-business-mcp__list_concepts` / `mcp__fd-find-data-business-mcp__ai_search` → `mcp__fd-find-data-business-mcp__read` / `mcp__fd-find-data-business-mcp__read_range` |
| 部委与统计局数据 | `mcp__fd-cn-report__list_ministries` → `mcp__fd-cn-report__get_ministry_stat` / `mcp__fd-cn-report__get_nbs_stat` |
| 公司公告类经营数据 | `mcp__fd-cn-report__get_company`（参数名 `ticker_or_name`）→ `mcp__fd-cn-report__list_filings` / `mcp__fd-cn-report__get_financials` |

**取数纪律**：

1. **先搜后读**。`gta_read` 的 `variable` 必须来自 `gta_search_variables` 的返回；年鉴、城市、世行的 indicator 同理。**不得凭记忆填 code。**
2. **公告类数据的期别以公告期为准**，不以抓取日为准。`list_filings` 返回的 `published`（发布日期）与 `title` 一起记入来源列。
3. **期货、现货、运价这类产业链上游序列**：若通道 A 无对应序列，只能走通道 B，并在该行写明"通道 B 取数 + 表名 + 最新日期"。**不得调外部接口绕过通道 B。**
4. **覆盖度先自检**：开工先跑 `mcp__fd-find-data-business-mcp__registry_coverage`，其返回的最新期即本次「数据截至」；不可用时注明"数据截至未经在线核实"。

## 阶段 3：变化方向与序列体检

### 3.1 方向判定（规则写死，不拍脑袋）

| 比较方式 | 判定 |
|---|---|
| 同比序列（月度 / 季度） | 与上一期同比值比较，变动 < 0.5 个百分点记 `→` |
| 水平序列（年度 / 月度绝对值） | 取最近 3 期做移动平均后与上一组 3 期比较 |
| 只有两期可用 | 直接比较两期，并在表下注明"仅两期，方向判定不稳" |
| 只有一期可用 | 方向记 `—`，写"无上一期，不判方向" |

- **不得用"感觉在涨"替代比较**；方向必须来自两期或两组的实际数值。
- 方向只是**已发生变化的标注**，不是趋势判断，**不得写成"进入上行通道"**。

### 3.2 序列体检（走通道 Q，不手算）

```
mcp__fd-quant__check_series_as_of_bounds(dates, values, as_of)
    → point_count / missing_count / missing_ratio / warmup / first_date / last_date / is_complete

mcp__fd-quant__check_observation_sufficiency(dates, as_of, values, required_observations=<门槛>)
    → sufficient / usable_observations / shortfall / ratio / span_days
```

- 缺失占比过高（默认 > 30%）→ 该变量标 `覆盖不足`，数值照列但加注。
- 序列有断点（中间整段缺失）→ 标 `断点`，给出断在哪些期。
- 需要变化幅度时用 `mcp__fd-quant__summarize_return(dates, values, as_of, periods_per_year)` 与 `mcp__fd-quant__summarize_volatility(...)`，**不得手算**。

### 3.3 基准未播种时的处理（常见情形）

`mcp__fd-quant__summarize_information_ratio` 与 `mcp__fd-quant__summarize_beta` 的 `benchmark` 参数是**必填**，缺失即报错。本角色通道 B **未播种任何宽基基准**（无 510300、无沪深300）。

- 因此本稿**默认不用**这两个统计量。
- 若用户明确要求，必须如实声明"基准未播种，以 0 为基准（纯收益/波动比），与含基准口径不可横比"，并给出播种路径：
  `DAAS/fd-daas-mcp/daas-mcp/seed_astock_price.py --symbols 510300`。
- **不得**用某只个股、某个行业代理或"上证指数近似"冒充基准。

## 阶段 4：缺口标注（本稿的核心纪律）

**定义（固定）**：某变量的最新可得期显著早于当期，即为缺口。缺口不是错误，是必须曝光的事实。

### 4.1 缺口分级（按落后程度）

| 级别 | 判定（相对该变量频度） | 标注 |
|---|---|---|
| 正常 | 落后 ≤ 1 个正常发布周期 | 不标缺口 |
| 滞后 | 落后 2–3 个正常发布周期 | `滞后 N 期` |
| 缺口 | 落后 > 3 个正常发布周期 | `缺口：最新期 <期>，落后 N 期` |
| 断供 | 连续两个应有期别均无数据 | `断供：自 <期> 起无更新` |
| 未接 | 从未取到过该变量 | `未取得`（不是缺口，是缺失） |

**发布周期按频度取**：月频 = 1 个月，季频 = 3 个月，年频 = 12 个月。**不得用日频标准去判年频变量"严重滞后"**——那是标准用错。

### 4.2 缺口表的必填字段

```
| 环节 | 变量 | 最新期 | 应有期 | 落后 | 级别 | 原因（若已知） | 恢复路径 |
|---|---|---|---|---|---|---|---|
```

- **原因**只能写已核实的情形：`未连接` / `检索无命中` / `该期未披露` / `发布延迟` / `口径变更致断档`。**不得猜"可能是数据源故障"**——不知道就写"原因未核实"。
- **恢复路径**必须具体：哪个工具、哪个参数、补哪段期数。

### 4.3 缺口与结论的关系（强制声明）

每次输出末尾必须写：

```
本次跟踪覆盖 N 个环节、M 个变量；其中正常 X、滞后 Y、缺口 Z、断供 W、未取得 V（合计 = M）。
缺口变量不参与任何方向的汇总判断；未取得变量不参与统计。
```

数字对不上即硬失败。**不得为了让"链条看起来完整"而少报缺口。**

## 阶段 5：输出形态（固定结构，便于多次运行对比）

### 5.1 主表（按环节分组，一组一张）

```
### 环节：<上游 / 中游 / 下游 …>（层级 <一级 / 二级>）

| 变量 | 最新值 | 单位 | 最新期 | 上期值 | 上期 | 方向 | 来源（工具名 + 标识） | 数据期数（起–止） | 状态 |
|---|---|---|---|---|---|---|---|---|---|
| <变量名> | <值> | <单位> | <期> | <值> | <期> | ↑ / ↓ / → / — | <mcp__…__…> | <起>–<止> | 正常 / 滞后 / 缺口 / 断供 / 未取得 |
```

表下必带一行口径：

```
口径：方向判定 = <同比比较 / 3 期均线比较>｜数据截至 = <期>（来源 mcp__fd-find-data-business-mcp__registry_coverage）｜本表不含预测
```

### 5.2 环节汇总（只做计数，不做评级）

```
| 环节 | 变量数 | 有更新 | 缺口 | 断供 | 未取得 | 覆盖结论 |
|---|---|---|---|---|---|---|
```

**"覆盖结论"只允许三种取值**：`完整`（全部正常）/ `部分`（有滞后或缺口）/ `不足`（过半缺失）。**不得写"景气度高""环节强势"之类评级。**

### 5.3 变化摘要（只写已发生的事）

```
本次相对上次运行（<上次口径日> → <本次口径日>）：
  - 新披露：<变量> 新增 <期>，值 <…>
  - 口径变更：<变量> 由 <旧> 改为 <新>（与历史不可横比）
  - 新增缺口：<变量> 自 <期> 起未更新
  - 解除缺口：<变量> 补到 <期>
```

**不得写"改善""恶化""转强""转弱"**——那是判断，本稿只报事实。

## 阶段 6：宿主 cron 触发（只说明方法，不实现调度）

本技能可以被定时调用，但**调度不在技能内**：

| 项 | 说明 |
|---|---|
| 谁触发 | 宿主侧 cron / 调度器（例如每天的固定时点或每次数据发布后） |
| 技能做什么 | 被调用时执行本稿全部阶段，输出上表的固定结构 |
| 技能不做什么 | 不创建、不修改、不删除任何定时任务；不注册回调；不依赖常驻进程 |
| 幂等性 | 同一口径日重复运行应得到相同结果；差异只允许来自数据源新增披露 |
| 增量依据 | 以「数据截至」与各变量最新期做对比，**不靠运行时间差** |
| 输出留存 | 每次运行输出应可留存，供下一次"相对上次运行"段对比 |
| 失败时 | 单次运行失败不改变任何状态；下一次运行重新取数，不补跑、不推测 |

**若用户要求"帮我建个定时任务"**：说明调度属宿主配置，本技能只提供被调用时运行的输出形态，并给出建议的调用参数（行业名、变量清单、口径日）。**不得声称技能自身能定时运行。**

1. **跟踪卡**：行业 + 环节数 + 变量数 + 各状态计数 + 数据截至 + 本次口径日。

4. **缺口明细表**（阶段 4.2）。
5. **变化摘要**（阶段 5.3，有上次运行记录时给）。
6. **口径与来源汇总**：逐变量列工具名 + 标识 + 期数区间。
7. **无预测声明**（固定句）：`本输出为已披露数据的时点整理，不含预测、不含投资建议。`

## 降级路径（数据源未连接或调用失败时，强制执行）

| 情形 | 处理 |
|---|---|
| `registry_coverage` 不可用 | 「数据截至」改写为各变量自身最新期，并注明"未经在线核实" |
| 某环节全部变量不可取 | 该环节仍出现在输出里，标"本环节全部未取得"，并给恢复路径；**不得整段删除该环节** |
| `gta_read` 未连接 | 中游公司变量整体标"未取得（未连接公司面板）"，上游与下游照常 |
| 年鉴 / 城市 / 世行不可用 | 仅影响对应变量，其余照常；缺口表登记 |
| 通道 Q 不可用 | 序列体检与变化幅度无法计算；只给最新值与上一期值，方向判定降级为"仅两期直接比较"并注明 |
| 通道 B 未播种某序列 | 该变量标"未取得（价格/上游序列未播种）"，给播种路径 `DAAS/fd-daas-mcp/daas-mcp/seed_astock_price.py --symbols <代码>`；**不得调外部接口绕过** |
| 公告正文不可读 | 只能记标题与发布日期，数值标"未取得"；**不得从标题推测数值** |
| 全部数据源不可用 | 只输出变量清单骨架 + 待取清单，通篇标注"未经在线核实" |

**降级不产出假数**：无工具返回时，数值、期数、方向全部留空或写"未取得"。

## 防编造硬约束（贯穿全程，红线）

- ❌ **数值、单位、期别、变量 code、indicator id、concept id，全部必须来自工具返回**；取不到写"未取得"，**禁止编造数值与期数**。
- ❌ **不得凭记忆填 code**；未确认的标识一律视为未取得。
- ❌ **不得用相邻期、其他地区、其他口径的值顶替缺失**。
- ❌ **不得把缺口标成正常**，也不得为凑"完整"而少报缺口。
- ❌ **不得把"方向"写成"趋势"**。方向是两期比较的结果，不是对后续的推断。
- ❌ **不得写预测、评级、建议、目标位**；不得出现"关注""布局""规避"这类动作词。
- ❌ **不得声称技能自身能定时运行**；调度属宿主配置。
- ❌ **不得伪造"上次运行"记录**；没有留存就写"无上次运行记录，本次不提供对比"。
- ❌ 不得在未标注信息不足的情况下给出"完整"覆盖结论。

## 口径溯源（来源 + 期数）

| 字段 | 要求 |
