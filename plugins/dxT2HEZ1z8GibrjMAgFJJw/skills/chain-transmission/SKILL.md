# 柏讯产业链联动 · 传导验证

你的职责：**对映射阶段交来的每一条"上游变量 → 中游变量（→ 下游变量）"假设，逐环做统计检验，并把结果分成三类如实呈现：显著、不显著、未验证。** 你不给候选（那是 `chain-beneficiary`），也不解释成因果。

本稿存在的唯一理由：**"上游涨价 → 中游承压 → 下游提价"听起来总是对的。** 时滞多长、幅度多大、到底有没有发生，三个问题没有一个能靠叙事回答。所以每一环都要有两条序列、一个窗口、一个样本量。

---

## 阶段 0：能力边界与用词纪律（开场必读）

### 0.1 本稿可做什么

| 可做 | 说明 |
|---|---|
| 单环相关 | 两条同频序列的相关系数（Pearson 或 Spearman），带样本量 |
| 时滞扫描 | 把上游序列错位 k 期后逐 k 求相关，输出整张滞后表 |
| 分组收益 | 按上游变量分组看下游收益差异（`compute_grouped_returns`） |
| 窗口敏感性 | 同一环在多个窗口下并列报告，结论不一致就写"依赖窗口" |
| 样本闸门 | 检验前先问"这段历史够不够"（`check_observation_sufficiency`） |
| 稳健性 | walk-forward 切窗，检验时滞是否在样本外仍然成立 |

### 0.2 本稿不可做什么（硬边界）

> ⚠️ **边界声明（每次输出的结论前置位复述要点）**
>
> 1. **不做因果推断。** 本稿只做相关与时序错位。全篇不得出现"导致""引起""决定了""因为上游涨价所以中游承压"这类因果句。**"传导"一词在本稿中仅指统计上的联动与时序错位，不是因果机制。**
> 2. **不做价格预测。** 传导显著不等于未来涨跌；本稿不给任何价格预期、不给目标位、不给买卖判断。
> 3. **不报 p 值。** 计算面不输出 p 值（`compute_factor_exposure` 明确只给 `t` 值，不查表）。因此本稿用**检验前声明的阈值**判定显著与否，并在输出里写明"这是按预设阈值判定，不是正式的显著性检验"。**不得编造 p 值。**
> 4. **不做结构化传导模型。** 不用 VAR、状态空间或任何需要更强假设的模型。显式相关 + 显式时滞 + 显式窗口，是故意选的简单。
> 5. **不补缺失、不插值、不前向填充**来凑样本量。缺失就是缺失，样本量按实际配对数报。

## 阶段 1：输入契约（映射交来的东西必须先过这一关）

`chain-mapping` 交来的每一环应该长这样：

```
环节对：<上游环节> → <中游环节>
上游序列：<变量名>｜工具 <完整工具名>｜标识 <code / id>｜频度 <月/季/年>｜起止 <…>｜最新 <期>
中游序列：<变量名>｜工具 <完整工具名>｜标识 <code / id>｜频度 <月/季/年>｜起止 <…>｜最新 <期>
机制假设：<上游通过哪个科目进入中游>（这是假设，不是结论）
```

**输入不合格的四种情形，逐一处理，不得自行补全**：

| 情形 | 处理 |
|---|---|
| 缺标识（只有变量名没有 code） | 回到 `chain-mapping` 补检索；补不到 → 该环 `未验证` |
| 缺频度 | 从工具返回的期别推断；推断不出 → 该环 `未验证` |
| 两条序列时间不重叠 | 该环 `未验证（窗口无交集）` |
| 只有一侧有序列 | 该环 `未验证（仅一侧可得）` |

---

## 阶段 2：频度对齐（频度差是本套件最常见的伪结论来源）

产业链上游客流数据常是月频，公司面板是年频。频度不齐时，**先定对齐规则，再算相关**，顺序不能反。

| 频度组合 | 对齐方式 | 必须写进输出 |
|---|---|---|
| 同频（月–月 / 年–年） | 直接按同一期匹配 | 配对数 = 两序列的期别交集 |
| 月频上游 + 年频中游 | 上游按**年均**聚合成年值（不是取 12 月单点，也不是年末值），再与年频匹配 | "上游由月频聚合为年频，聚合口径 = 年内算术平均；聚合后损失 N 个月度观测" |
| 季频上游 + 年频中游 | 上游按**年均**聚合 | 同上，注明季度数 |
| 年频上游 + 季频中游 | **不可自行细化**。只能把中游聚合为年频，或直接标未验证 | 不得把年值复制到四个季度——那会人为把样本量放大 4 倍 |

**三条硬规则**：

1. **只能向低频聚合，不得向高频展开。** 把年值填进月频，等于凭空造观测。
2. **聚合口径必须写出来**（年均 / 期末 / 区间累计），并且全文只用一种。
3. **聚合后的有效样本量按低频计。** 36 个月对 3 年，有效样本是 3，不是 36。输出里写 `有效样本 n=3（月度观测 36 条聚合为 3 个年度观测）`。

## 阶段 3：样本闸门（先问够不够，再花算力）

对每一对序列，先跑：

```
mcp__fd-quant__check_observation_sufficiency(dates=<期别轴>, as_of=<口径日>,
    values=<该侧数值序列>, required_observations=<门槛>)
```

- `usable_observations` 是**非缺失**点数，`missing_count` 是缺失数，`shortfall` 是还差多少。
- 门槛按频度设，**必须在检验前声明**：

| 频度 | 建议门槛 | 理由 |
|---|---|---|
| 月频 | 24 | 两整年，勉强覆盖一个完整周期 |
| 季频 | 12 | 三年 |
| 年频 | 8 | 八年，少于这个数任何滞后扫描都不可信 |

- 再跑 `mcp__fd-quant__check_series_as_of_bounds(dates, values, as_of)` 看 `missing_ratio` 与 `warmup`：缺失占比过高（默认 > 30%）或前后段断裂的序列，**降级为"覆盖不足"**，不强行参与检验。
- `sufficient=false` → 该环直接记 `未验证（样本不足：可用 X < 门槛 Y）`，**不得**缩窗口硬算。

## 阶段 4：逐环检验（三步，每步都有产物）

### 4.1 第一步：同期相关（时滞 k = 0）

```
mcp__fd-quant__compute_information_coefficient(
    dates=<对齐后的期别轴>,
    factor=<上游序列>,
    forward_returns=<中游序列>,
    as_of=<口径日>,
    method="pearson" 或 "spearman",
    min_observations=<阶段 3 的门槛>)
```

返回里要用的字段：`ic`（相关系数）、`n_observations`（实际配对数）、`n_dropped`（因缺失剔除的对数）、`used_indices`（参与计算的观测索引，供审计）。

**口径两条**：

- `method="spearman"` 更抗极端值；**默认用 spearman**，若同时给 pearson 必须并列呈现两个值，不得只报好看的那个。
- 该工具**不做 shift**（文档明写"第二列是前瞻还是同期收益由调用方负责"）。所以时滞对齐必须在传入前由本稿完成，并把错位方向写进输出。

### 4.2 第二步：时滞扫描（本稿的核心）

对 k = 0, 1, 2, … K 逐期错位，每次调一次 `compute_information_coefficient`：

```
上游_t  与  中游_{t+k}   →  相关(k)
```

- **K 的取值按频度定，且必须写在输出里**：月频默认 K = 0–12；季频默认 K = 0–8；年频默认 K = 0–3。K 是规定值，不是实现自选。
- **错位方向必须写死**："上游第 t 期 对 中游第 t+k 期"，k > 0 表示**中游滞后于上游**。反向错位（中游领先）若也要看，必须单独标注，不得混在同一张表里。
- **整张滞后表都要交出来**，不能只报相关最高的那个 k。只报最优 k 是后选择偏差——你从 13 个 k 里挑最大的那个，它天然偏高。
- 若要用"最优 k"下结论，必须补一次**样本外验证**：

```
mcp__fd-quant__split_walk_forward_windows(dates, values, as_of,
    train_window=<…>, test_window=<…>, short_sample="refuse")
```

在训练窗定下 k，在紧随其后的测试窗重算该 k 的相关，两个值并列报告。样本外不成立就写"最优时滞未通过样本外验证"。

### 4.3 第三步：滞后方向的回归读数（可选，给系数与 t 值）

需要"上游变动一个单位，中游同向变动多少"的方向性读数时：

```
mcp__fd-quant__compute_factor_exposure(dates=<对齐轴>,
    factor=<上游序列（已按选定 k 错位）>,
    returns=<中游序列>, as_of=<口径日>, min_observations=<门槛>)
```

返回 `alpha`、`beta`、`t_beta`、`R²`、`residual_stdev`、`n_observations`。

- **`t_beta` 是系数显著性读数，不是 p 值**；本稿原样报 t 与自由度语境下的样本量，不改写成 p。
- **β 是同一时间轴上的统计弹性，不是"传导系数"**。输出写法固定为"同期回归斜率 β = …（统计读数，非因果系数）"。
- 需要看强弱分组差异时用 `mcp__fd-quant__compute_grouped_returns(dates, factor, forward_returns, as_of, n_groups=5)`，报 `top_minus_bottom` 与 `monotonic`；组内成员索引在 `groups[].members`，可用于审计哪几期进了高低组。

### 4.4 判定规则（必须在跑之前声明，不得看到结果再定）

| 判定 | 条件（默认阈值，可配但须预先声明） |
|---|---|
| **显著（按预设阈值）** | \|r\| ≥ 0.30 且 n ≥ 门槛，且相邻 2 个 k 上相关系数符号一致（不是孤立尖峰） |
| **不显著** | n ≥ 门槛但 \|r\| < 0.30；或符号在相邻 k 上反复翻转 |
| **未验证** | 任一侧序列不可得 / 样本不足 / 窗口无交集 / 频度无法在不造数据的前提下对齐 |

**"显著"在本稿里只有一个含义：通过了检验前声明的阈值。** 它不表示因果成立，也不表示关系稳定，更不表示未来仍会成立。

**多重检验必须自曝**：一次分析扫了 L 条链 × (K+1) 个时滞 = L×(K+1) 次检验。输出里必须写"本次共执行 N 次相关检验"，并在结论旁边注明"多重比较下，孤立的高相关可能是偶然"。不得把某一次孤立高相关当整条链的证据。

## 阶段 5：未验证环节的声明纪律（强制格式，不得省略）

**这是本套件的硬约束。** 任何一环只要拿不到可核验的两侧序列，就必须原样出现在结果表里，标 `未验证`，并给出原因与恢复路径。

```
环节对：<上游> → <中游>
状态：未验证
原因：<数据不可得 / 仅一侧可得 / 样本不足：可用 9 < 门槛 24 / 窗口无交集 / 频度无法对齐>
已知：<有哪一侧、覆盖到哪一期，如实写；没有就写"两侧均未取得">
缺失变量：<变量名 + 用哪个工具检索过 + 检索结果>
恢复路径：<接入哪个数据源 / 补哪段期数 / 换哪个代理变量后可以重做>
影响：<哪条受益结论因此不能成立>
```

**五条不容商量的规则**：

1. **未验证 ≠ 成立。** 不得在正文别处默认它成立，也不得在总结里写"整体传导顺畅"而把未验证环悄悄并入。
2. **未验证环节不得被"合理推测"补充。** 不许写"虽然数据不可得，但从行业逻辑看上游涨价应当会压制中游毛利"——这句话就是本套件要消灭的东西。
3. **不得因为"这一环肯定有"而跳过登记。** 越是想当然的环节，越要出现在表里。
4. **不得用相邻环节的结论替代。** A→B 未验证，不能拿 B→C 的显著结论反推 A→B 成立。
5. **汇总句必须计数**：`共 L 环：显著 X 环、不显著 Y 环、未验证 Z 环（X+Y+Z=L）`。数字对不上就是硬失败。

## 阶段 6：不显著的呈现纪律

不显著和显著**同权同版面**：

- 每一环都进同一张主表，不按显著性重排后把不显著挤到附录。
- 不显著的行必须给：`r`、`n`、`窗口`、`时滞范围`，一个都不能少。
- 不得写"趋势上仍有一定传导""弱显著""方向正确"这类软化措辞。**不显著就写不显著。**
- 不显著本身是有价值的信息：它阻止了一个错误的传导假设进入候选池。输出里要明确写出这一点：

```
说明：本环不显著。这不是"分析失败"——它意味着在这段窗口里，没有证据支持该传导假设，
因此该环节不得作为 chain-beneficiary 的依据。
```

- 若某个 k 显著而 k=0 不显著：如实写"仅在第 k=X 期错位下超过阈值，其余时滞未超过；该结果对时滞选择敏感"。**不得**只引用那个显著的 k。

## 阶段 7：非因果表述（措辞对照表，逐句自查）

| ❌ 禁止 | ✅ 改为 |
|---|---|
| 上游涨价导致中游毛利下滑 | 上游变量与中游毛利在 k=X 期错位下呈负相关（r=…，n=…） |
| 传导时滞约 3 个月 | 相关在 k=3 期时最高（窗口 …，n=…），其余时滞未超过阈值 |
| 中游把成本压力传给了下游 | 未检验；或"中游与下游在 k=… 的相关系数为 …" |
| 这说明该环节必然受益 | 该环在本次窗口下通过预设阈值；不构成对未来或对价格的含义 |
| 因为上游产能收缩，所以下游供给紧张 | （删除因果连词）上游产能与下游供给变量在 k=… 的相关系数为 … |
| 传导机制成立 | 该环的历史统计关系通过阈值；机制解释仍属假设 |

**额外禁令**：不得出现"将会""预计""有望""必然""确认了传导""验证了机制"这类断言；"验证"在本稿中的对象是**统计关系是否存在**，不是**机制是否存在**。

## 阶段 8：交付结构（每稿必交）

1. **结论卡**：链名 + 环节数 + 显著 / 不显著 / 未验证 三档计数 + 口径日 + 数据截至。
2. **检验参数声明**（必须在结果之前）：频度与聚合口径、门槛、K 的取值范围、判定阈值、method、共执行多少次检验。
3. **逐环主表**：

```
| # | 环节对 | 上游变量（来源·期数） | 中游变量（来源·期数） | 频度/对齐 | 窗口 | k* | r | n | t（若做回归） | 判定 |
|---|---|---|---|---|---|---|---|---|---|---|
```

4. **完整时滞表**：每环一张 k → r 的表，k 从 0 到 K，缺测的 k 写"无数据"。
5. **窗口敏感性表**：至少两个窗口（全样本 + 近 N 期），两窗判定不一致时写"结论依赖窗口"，并列出各自数字。
6. **未验证环节明细**：按阶段 5 的固定格式，逐环给原因与恢复路径。
