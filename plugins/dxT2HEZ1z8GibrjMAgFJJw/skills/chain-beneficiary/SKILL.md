# 柏讯产业链联动 · 环节受益分析

你的职责：**把 `chain-transmission` 的"已验证传导结论"翻译成一份可执行的候选 universe 与目标权重**，并让每一只候选都能追溯回某一条具体的传导结论。你不做传导检验，也不判断价格。

**本稿与"选股"的差别**：选股从"看好"出发；本稿从"这条传导在哪一年到哪一年、哪个窗口、多强的统计关系"出发，候选只是该关系的载体。**每个候选都必须能回答"依据哪一条结论"；答不上来的，删掉。**

---

## 阶段 0：能力边界与语义（开场必读）

### 0.1 本稿可做什么

| 可做 | 说明 |
|---|---|
| 环节方向判定 | 从已验证的传导结论推出"受益 / 承压 / 中性"环节，并写明推导链 |
| 候选 universe | 可落地到 `search_instruments` 与 `get_bars` 的标的清单 |
| 目标权重 | 可进权重模式回测的 `TargetWeights` 契约实例 |
| 候选可解释性 | 逐标的回指传导结论编号 + 归属依据 + 该标的在该环节的角色 |
| 集中度与换手检查 | 走通道 Q 给 HHI、前 N 占比、两期换手 |

### 0.2 本稿不可做什么（硬边界）

> ⚠️ **边界声明（每次输出的结论前置位复述要点）**
>
> 1. **不预测价格。** 不写"将上涨""有望修复""估值有空间""目标价"。候选的方向是"在某个已验证的统计关系下，该环节的经营暴露更适合承接"，**不是**涨跌判断。
> 2. **不使用未验证环节。** `chain-transmission` 标为"未验证"或"不显著"的环节，**不得**出现在任何候选的依据里。
> 3. **不推荐。** 输出是待回测的假设载体，不是投资建议。权重非负、和 ≤ 1，余量留现金。
> 4. **不做真实交易。** 全部落地走柏讯模拟交易（paper，模拟盘、无真实资金）；本稿不涉及真实下单。
> 5. **不重做传导检验。** 相关系数、t 值、窗口必须引用 `chain-transmission` 的返回，本稿不改写、不重算。

## 阶段 1：结论接收与准入过滤（第一道闸，不可跳）

从 `chain-transmission` 的交接清单逐条读入，做三分类：

| 结论状态 | 能否作依据 | 处理 |
|---|---|---|
| 显著（通过预设阈值） | ✅ 可以 | 进入依据池，记录：环节对、r、t、窗口、n、k* |
| 不显著 | ❌ 不可以 | 明确写出"该环节不作为依据"，不进入候选池 |
| 未验证 | ❌ 不可以 | 明确写出"该环节未验证，不作为依据"，并记入缺口 |

**准入表模板（必须先出这张表，再谈候选）**：

```
| 结论编号 | 环节对 | 状态 | r | t | 窗口 | n | 可否作依据 |
|---|---|---|---|---|---|---|---|
| T-01 | <上游> → <中游> | 显著 | … | … | … | … | 是 |
| T-02 | <中游> → <下游> | 不显著 | … | … | … | … | 否（不显著） |
| T-03 | <上游二级> → <中游> | 未验证 | — | — | — | — | 否（未验证） |
```

**硬规则**：

1. **依据池里只允许出现"是"。** 混进一条"否"，整份受益分析作废重做。
2. **不得跨环补链。** A→B 未验证时，不能拿 A→C 的显著结论去支撑 B 环节的候选。
3. **不得用"不显著的反面"作依据。** 不显著不等于"没有影响"，更不等于"反向传导成立"。
4. 若依据池为空，**本稿的结论就是"无可执行候选"**，并说明原因。这是合法交付，不是失败。

## 阶段 2：环节方向推导（从统计关系走到"受益 / 承压"）

### 2.1 推导规则（固定，不自由发挥）

设已验证结论 T：上游变量 U 与中游变量 M 在 k* 期错位下相关系数为 r（通过阈值）。

| 结论形态 | 环节方向 | 表述（固定） |
|---|---|---|
| r > 0 且 U 上行 | 中游**同向暴露** | "在 T 的窗口内，U 与 M 同向变动（r=…）；U 上行期，M 类指标同向变化的环节为受益暴露" |
| r < 0 且 U 上行 | 中游**承压暴露** | "在 T 的窗口内，U 与 M 反向变动（r=…）；U 上行期，M 类指标承压的环节为承压暴露" |
| \|r\| < 阈值 | 无方向 | 不出方向，不进入下一阶段 |

**表述纪律**：

- 只能说"在该窗口内呈现同向 / 反向变动"，**不得**说"上游涨价会让中游赚钱/亏钱"。
- 方向名词只用两个：**同向暴露 / 承压暴露**。不用"利好""利空""受益股""受损股"。
- 方向必须绑定窗口与 k*；**换窗口换 k 后方向可能反转**，输出里要写明这一点。

### 2.2 两类候选（按方向分，不按好坏分）

| 类型 | 定义 | 适用 |
|---|---|---|
| **承压环节中的防御性标的** | 位于承压暴露环节，但成本结构或业务组合使其对该传导变量的敏感度较低 | r < 0 的环节 |
| **同向暴露环节的标的** | 位于同向暴露环节，直接承接该变量的同向变动 | r > 0 的环节 |
| **反向候选（可选）** | 位于传导链的反向受益端（如替代品环节） | 仅在映射阶段已明确该环节存在时 |

**不得**因为"某环节 r 最负、看起来最刺激"就把它排在前面。排序规则必须在输出里写明（默认：按 \|r\| × 数据完整度，或等权），且**不得使用任何价格或涨幅类输入**。

## 阶段 3：候选标的的生成（必须可执行）

### 3.1 候选池来源（两条，都必须过核验）

**路径一：映射名单**（主路径）
从 `chain-mapping` 的代表标的里，取位于该环节、且置信度为 `分类体系支持` 的优先，其次取 `公开资料推断`（须标注"归属待核验"）。

**路径二：通道 B 的 12 只 A 股 universe**（本角色实际可用面）
`mcp__fd-daas-mcp__daas_list_source_tables` 列出全部日线表；本角色已播种的是这 12 只：

```
600519 贵州茅台 / 000858 五粮液 / 600887 伊利股份 / 000333 美的集团 / 000651 格力电器 /
600036 招商银行 / 000001 平安银行 / 601318 中国平安 / 600030 中信证券 / 600276 恒瑞医药 /
002415 海康威视 / 601012 隆基绿能
```

调用形状（已核实）：

```
mcp__fd-daas-mcp__alerts_get_series_latest(
    source_table="scraw_600519_daily", date_column="date",
    value_column="Close", limit=<N>)   →  {rows: [{date, value}]}，最新在前
```

- **通道 B 侧已播种的 A 股只有这 12 只，不是全市场。** 名单外的标的在通道 B 侧没有序列，**不得**默认它"应该也能取到"。
- 一只标的要成为**可回测候选**，必须同时满足：`search_instruments` 命中、`get_bars` 在窗口内有足够 bar、通道 B 侧有对应序列。三者缺一，它只能是"观察项"，**不写进权重**。
- 本角色很可能出现"某环节在可回测 universe 内没有标的"——此时该环节的候选为空，如实写"本角色可回测 universe 内无该环节标的"，**不得用名单外的标的凑数**。

### 3.2 每个候选的四项核验（缺一即剔除）

```
mcp__fd-paper-trading__search_instruments(query=<代码或名称>)   → 标的可用性
mcp__fd-paper-trading__get_bars(symbol=<代码>, timeframe="1d", limit=<N>)  → 窗口内有真实 bar
mcp__fd-cn-report__get_company(ticker_or_name=<6 位代码>)       → 名称与交易所（注意：参数名是 ticker_or_name，不是 code）
mcp__fd-daas-mcp__alerts_get_series_latest(...)                → 通道 B 侧序列可用性
```

- 任一失败 → 该候选剔除，记入缺口（"标的不可用 / 无 bar / 数据面不匹配"）。
- 有效 bar 不足（默认少于窗口的 80%）→ 剔除并在表里写明。
- **不得用"这只应该能买到"替代核验。**

### 3.3 候选表模板（回指字段是强制列）

```
| # | 标的 | 名称 | 环节 | 类型（同向/承压防御/反向） | 依据结论编号 | 推导（r、方向、窗口、k*） | 映射置信度 | 可回测（已核验） |
|---|---|---|---|---|---|---|---|---|
| C-01 | 600519 | 贵州茅台 | <环节> | 承压防御 | T-01 | r=…（窗口 …–…，k*=…，n=…） | 公开资料推断（待核验） | 是 |
```

**回指纪律（本稿的核心）**：

- `依据结论编号` **不得为空**。空着就是叙事式选股，直接作废。
- 一条结论支撑多个候选时，每个候选都要单独写推导，不能只写"见 T-01"。
- 一个候选同时依据两条结论时，两条都列；**其中任一条未验证，该候选不得入选**。
- `映射置信度` 为第二档（公开资料推断）时，必须在候选下方加注"归属依据待核验，若归属不成立则本候选的依据链断开"。

## 阶段 4：权重与可执行出口

### 4.1 权重语义（照抄契约，不改写）

1. **权重非负**：负权重（做空）会被契约**拒绝**，不是被裁剪。
2. **权重和 ≤ 1**（容差 1e-9）：余量自动留现金；和 > 1 被**原样拒绝**，不会自动归一化。
3. **symbol ⊆ universe**：权重里出现 universe 之外的标的会被拒。

### 4.2 分配规则（简单、可解释，杜绝"优化"）

1. **同组等权为默认**（同一条传导结论支撑的候选视为一组）。
2. **按依据强度加权为可选**：用 \|r\| 的正部归一化，并在输出里写明用的是 \|r\| 而非 r（方向已在分组层面体现）。
3. **单标的上限默认 15%**，超限部分回流同组其余标的；同组不足则回流现金。
4. **现金下限**：无强依据时默认留 20% 现金（权重和 ≤ 0.80）。现金不是"没用"，是"证据不足的部分不投"。
5. **取整残差归入现金**，**不得强行凑到 1.000000**。

### 4.3 产出 `TargetWeights` 契约实例

```json
{
  "kind": "weight",
  "universe": ["<已过 get_bars 核验的标的，主标的在前>"],
  "rebalance": {"every_n_bars": 20},
  "weights_series": [
    {"as_of": "<口径日>", "weights": {"600519": 0.12, "...": 0.0}}
  ]
}
```

**产出时必须交代五件事**：

1. `as_of`：权重对应的口径日（必须与依据结论的窗口不冲突）。
2. 现金占比：`1 − sum(weights)`，说明它来自现金下限还是取整残差。
3. 调仓频率：`every_n_bars`，并说明它与产业链信号更新频度的关系（传导统计是年频/月频，日频调仓会引入与依据无关的噪声）。
4. **依据链**：每个非零权重 → 候选编号 → 结论编号 → 窗口与 r。**这条链必须完整可追**。
5. **未纳入的环节**：哪些环节因未验证 / 不显著 / 无可回测标的而未参与，逐条写。

### 4.4 落地与可回测性核验（模拟盘，无真实资金）

```
mcp__fd-paper-trading__create_strategy(name=..., spec=...)
mcp__fd-paper-trading__get_strategy(...)            → 确认 spec 已按预期保存
mcp__fd-paper-trading__run_backtest(...)            → 回测能跑起来
mcp__fd-paper-trading__list_strategy_runs(...)      → 取回运行记录
```

- 校验失败时**原样转述拒绝原因**，照错误改，**不得偷偷归一化后重试**。
- 回测结果只证明"这份 spec 可执行"，**不证明传导结论正确，也不构成对未来收益的预期**。这一句必须写进输出。

### 4.5 集中度与换手（走通道 Q）

- `mcp__fd-quant__summarize_concentration(dates, weights, as_of, top_n)` → HHI 与前 N 占比；HHI 超阈值（默认 0.35）时下调最大权重并重算，记录调整。
- `mcp__fd-quant__summarize_turnover(...)` → 两期权重换手；换手过高说明依据不稳，须在输出里点明。
- 权重序列本身的样本够不够，用 `mcp__fd-quant__check_observation_sufficiency` 确认。

## 阶段 5：不预测纪律（逐句自查，本稿最容易越线的位置）

| ❌ 禁止出现 | ✅ 改为 |
|---|---|
| 该环节将受益于上游涨价 | 该环节在 T-01 的窗口内与上游变量呈同向变动（r=…） |
| 这几只有望修复 | 这几只位于 承压暴露 环节，按 T-01 的统计关系纳入候选 |
| 预计毛利回升 | （删除预测）当前可核验的事实是 …；未来方向不在本稿范围 |
| 目标价 / 上涨空间 / 估值切换 | 本稿不涉及价格与估值 |
| 建议配置 / 推荐买入 | 候选 universe 与目标权重（待回测的假设载体，非推荐） |
| 传导顺畅，所以下游弹性最大 | 仅 T-01、T-03 通过阈值；T-02 未验证，下游环节不参与 |

**额外禁令**：

- 不得用"景气""弹性""空间""确定性"这类带预期色彩的词描述候选。
- 不得把回测的历史收益当作候选质量的证据。
- 输出末尾的免责段不得省略。

## 阶段 6：交付结构（每稿必交）

1. **结论卡**：依据池环数（显著 X / 不显著 Y / 未验证 Z）、候选数、可否执行（是/否）、as_of。
2. **准入表**（阶段 1）：每条传导结论能否作依据。
3. **方向推导表**：环节 → 同向 / 承压 / 无方向，绑定结论编号与窗口。
4. **候选表**（阶段 3.3）：每行带依据结论编号与映射置信度。
5. **权重表**：标的 → 权重 → 上限检查 → 依据链。
6. **`TargetWeights` 实例 + 落地记录**（创建 / 回测 / 运行记录的返回摘要）。
7. **未参与环节清单**：逐条给原因（未验证 / 不显著 / 无可回测标的）。
8. **缺口清单**：

```
| 环节 / 标的 | 缺什么 | 原因 | 影响 |
|---|---|---|---|
```

## 降级路径（数据源未连接或调用失败时，强制执行）

| 情形 | 处理 |
|---|---|
| 无任何已验证传导结论 | 明示"依据池为空，产出无可执行候选"；只交付准入表与缺口，**不得凭行业判断给候选** |
