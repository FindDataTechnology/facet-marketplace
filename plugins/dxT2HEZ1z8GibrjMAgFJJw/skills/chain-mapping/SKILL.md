# 柏讯产业链联动 · 链条映射

你的职责：**把一个行业拆成可核验的环节结构——环节（上游 / 中游 / 下游，可多级）→ 代表标的 → 每环关键变量与来源——并给每一个归属标上置信度。** 你不检验传导（那是 `chain-transmission`），也不出候选（那是 `chain-beneficiary`）。

---

## 与既有 `industry-chain-analysis` 的关系（先说清，避免装错）

市场上会同时看到两个相关套件，这是设计而非重复：

| 维度 | 既有 `industry-chain-analysis` | 本套件 `wire-industry-linkage` |
|---|---|---|
| 定位 | 行业研究方法技能（景气位置、格局四要素、传导四问、GTA 实证） | 可安装套件 + 可执行出口 |
| 前端 | 链条是叙述的一部分，隐含在分析里 | **链条结构是独立产物**，逐归属标来源与置信度 |
| 中段 | 传导机制与实证同一章完成 | **传导验证独立成技能**，逐环有数据才下结论 |
| 后端 | 不给候选、不给权重 | **候选 universe / 目标权重**，与因子、轮动套件同出口 |
| 所属 | `wire-industry-corporate` 套件 | 本套件（两者可共存） |

一句话：**做行业研究与景气位置判断，装既有套件；要可审计的链条结构和可执行出口，装本套件。** 本稿不复制既有技能的景气位置判定矩阵，也不输出"扩张期 / 收缩期"这类结论——那是既有技能的职责。

## 阶段 0：能力边界（开场必读，不得省略）

### 0.1 本稿可做什么

| 可做 | 说明 |
|---|---|
| 环节切分 | 上游 / 中游 / 下游，允许多级；每环写清投入、产出、卖给谁 |
| 代表标的 | 每环节 3–8 家（可配），逐家给归属依据与置信度 |
| 关键变量登记 | 每环至少一个可观测变量，登记工具名、标识、期数区间 |
| 置信度分层 | 两档：`分类体系支持` / `公开资料推断`，逐归属标注 |
| 缺口清单 | 取不到的环节与变量如实列出，不用推测补位 |

### 0.2 本稿不可做什么（硬边界）

> ⚠️ **边界声明（每次输出的结论前置位复述要点）**
>
> 1. **不声称使用申万成分接口。** `index_component_sw` 对本角色**未启用**；包环境内没有 `industry_taxonomy.json`；指标规则集的 `company_profile.industry` 返回 `"unknown"`；通道 B 的申万相关函数数量为 0。因此**不能**据此列成分股。
> 2. **不把归属当事实。** 没有工具返回的分类字段，归属一律标 `公开资料推断`，不得写成"该公司属于 X 环节"这种确定句。
> 3. **不做传导检验。** 本稿只回答"结构长什么样"，不回答"传导是否发生、时滞多长、幅度多大"。
> 4. **不出候选、不给权重、不判断好坏。** 候选与权重是 `chain-beneficiary` 的事。
> 5. **不覆盖未上市公司做实证。** GTA 面板只含上市公司；非上市主体只能通过 `mcp__fd-find-data-business-mcp__ia35_company_search` 的静态工商快照做经营范围层面的参考，且必须注明批次年。

## 阶段 1：映射可及性自检（开工第一件事，跳过即硬失败）

产业链映射的难点不在"想不出链条"，而在**归属依据够不够硬**。先查清本角色到底能拿到什么，再动手。

| 需要的分类能力 | 本角色实际状态（已核实） | 对映射的影响 |
|---|---|---|
| 申万 L1 分类（31 类，`801xxx`） | 作为分类标准存在；但 `index_component_sw` 对本角色未启用，包环境内无 `industry_taxonomy.json` | **不能**据此取得成分股名单 |
| 公司行业标签 | `mcp__fd-cn-report__get_company` 返回 `stock_code / name / name_en / org_id / exchange / category`；其中 `category` 是交易所 / 板块类别，**不是行业分类** | 不能当行业归属使用 |
| 指标规则集的公司画像 | `company_profile.industry` 返回 `"unknown"` | 不能当行业归属使用 |
| 公司面板变量 | `mcp__fd-find-data-business-mcp__gta_search_variables` 覆盖 1,468 个公司—年度变量 × 5,939 家 × 1990–2025；**是否含行业分类变量以本次检索返回为准** | 有则可用（第一档），无则不用 |
| 公告与工商 | `mcp__fd-cn-report__list_filings`（公告标题、表单类型、发布日期、`pdf_url`）；`mcp__fd-find-data-business-mcp__ia35_company_search`（静态工商快照，含 `business_scope`、`former_names`、`batch_year`） | 只能支撑第二档推断 |
| 实体图谱 | `mcp__fd-find-data-business-mcp__graph_search`（`neighbors` / `subgraph` 等）可给实体关系线索 | 边语义以返回字段为准；未标明分类关系的一律按推断处理 |

**必须在输出里写下的自检结论（固定句式）**：

```
映射可及性：申万成分接口未启用、公司行业标签不可用（category 非行业、profile 为 unknown）。
本次 N 个归属中，分类体系支持 X 个、公开资料推断 Y 个。
说明：在本角色当前数据面下，第一档（分类体系支持）在多数行业上不可达，多数归属只能是第二档——
这不是本稿的缺陷，是本角色数据面的真实边界；第二档归属使用前须由使用者复核。
```

**跳过这一步直接给链条 = 硬失败项。**

## 阶段 2：两档置信度（定义固定，不得改写、不得自造第三档）

| 档位 | 定义 | 允许的依据 | 输出写法（固定） |
|---|---|---|---|
| **分类体系支持** | 归属直接来自工具返回的分类字段 | `gta_search_variables` 检索到并在 `gta_read` 取值中体现的行业分类变量；年鉴或城市面板返回的行业代码字段 | `置信度：分类体系支持（依据：<工具名> + <变量 code> + <数据期数>）` |
| **公开资料推断** | 工具中没有分类字段，归属由公开资料推断 | 年报主营业务描述、经营范围、公告标题与正文摘录、图谱关系线索；以及用户的明确指定 | `置信度：公开资料推断（依据：<具体资料>；待核验）` |

**纪律**：

1. 只有这两档。**不得**写 `0.73 置信度` 这类伪精确分数——归属来源是定性问题，包装成定量问题只会让人误以为它被量化过。
2. 第二档不等于错，等于"使用者需要复核"。**把第二档写成事实，是本套件最要防的错误。**
3. 同一归属有两条依据时取较高档，但两条依据都要列出。
4. 用户口头指定某公司属于某环节，**不能**升级为第一档——这只是"用户提供的信息"，仍按第二档并注明来源为使用者。

## 阶段 3：环节切分（结构从哪里来）

### 3.1 切分规则

- 上游 = 提供原料、设备、能源、零部件；中游 = 加工、制造、集成、组装；下游 = 需求、渠道、应用场景。
- **允许多级**：上游可再分"上游一级（资源）/ 上游二级（材料）"，下游可再分"下游一级（整机）/ 下游二级（终端需求）"。多级不是越多越好，**每多一级就多一组必须核验的变量**。
- 每个环节必须回答三问，缺一不可：

```
环节：<通用名词，不用公司名>
投入：<从哪来，投入什么>
产出：<产出什么，卖给谁>
关键变量：<至少一个可观测变量；没有就写"无可观测变量">
```

### 3.2 结构表模板

```
| 环节 | 层级 | 投入 | 产出 | 关键变量（候选） | 变量来源（待检索确认） |
|---|---|---|---|---|---|
| <环节名> | 上游一级 | <…> | <…> | <如 产量 / 开工率 / 单位成本 / 库存> | <工具名 + 检索词> |
```

### 3.3 本阶段的两条禁令

- **禁止在映射阶段写传导结论。** "上游涨价会传导到中游毛利"这类句子属于 `chain-transmission`，不在这里写。**"上游涨价→中游承压→下游提价"听起来总是对的，这正是本套件存在的理由**——它是一个待检验的假设，不是结构事实。
- **环节找不到可观测变量时必须如实断开**：写"该环节无可观测变量，传导链在此中断"。不得为了让链条看起来完整而编一个变量，也不得把"行业常识"当作变量来源。

## 阶段 4：代表标的（逐家可解释）

### 4.1 取名单的四条可达路径（按优先级）

1. **先搜分类变量**（第一档的唯一入口）：
   `mcp__fd-find-data-business-mcp__gta_search_variables("行业")`、`("所属行业")`、`("行业代码")`、`("证监会行业")`、`("主营业务")`。
   逐个确认返回的 `code` 与口径，**再**用 `mcp__fd-find-data-business-mcp__gta_read(variable=<code>, start_year=..., end_year=..., limit=...)` 取公司—年度值。
   返回里 `firm_id` 是左补零的 6 位代码，`firm_ids` 也按代码传（不足 6 位会被补零）。
   **变量 code 必须来自检索返回，不得凭记忆填写。**
2. **公告线索**：`mcp__fd-cn-report__list_filings(ticker_or_name=<代码或名称>)` 取年报标题与 `pdf_url`。若正文可读，用其中的主营业务描述作为归属依据；若只拿到标题与链接而读不到正文，依据只能写到"公告标题层面"，仍属第二档并注明"正文未核验"。
3. **工商快照**：`mcp__fd-find-data-business-mcp__ia35_company_search(name_prefix=... / credit_code=...)` 取 `business_scope`。这是**静态快照**（响应带 `batch_year` / `snapshot_caliber`），不得表述为当前工商状态，也不得据此推断上市公司主体地位。
4. **图谱线索**：`mcp__fd-find-data-business-mcp__graph_search(algorithm="neighbors", start_entity_code=<代码>, max_depth=2)`。边能说明"有关系"，**不自动等于"同一环节"**；未标明分类语义的边按第二档处理。

### 4.2 名单不完整时的诚实处理（本角色很可能遇到）

如果既检索不到行业分类变量、用户也没有提供候选名单，**本稿不能自造一份全行业名单**。此时只能：

- 对用户点名的公司逐家取证，输出**部分映射**；
- 在输出顶部写明：`本次名单为部分映射（仅覆盖用户点名或工具返回 N 家），不代表全行业成分`；
- 把"无法系统取得成分名单"写进缺口清单，并给出恢复路径（接入分类数据后再扩名单）。

### 4.3 每个标的必须给的六项

```
标的：<6 位代码> <名称>
环节：<环节名>
归属依据：<具体到变量 code + 取值与期数，或公告标题 / 经营范围原文摘要>
置信度：<分类体系支持 / 公开资料推断>
依据期数：<该依据对应的年份或公告期>
可解释性：<一句话说明"为什么它在这个环节"，不得写"行业龙头""知名企业"这类空话>
```

**不满足六项的标的，从名单里删除**，并在缺口清单登记"未取得归属依据，不纳入"。不得用"大家都知道"补位。

### 4.4 名单口径

- 每环节 3–8 家（可配）；不足 3 家时如实写"该环节仅取得 N 家，代表性有限"。
- 龙头与中小企业都要有；**不得按主观偏好挑选**，筛选规则必须在输出中写明（如：按分类变量取值 + 数据完整度）。
- 名单里出现同一公司跨两个环节（例如兼营材料与整机）时，两个环节都列，但**必须注明"该公司跨环节经营，归属按主营业务占比未能核验"**，不得二选一后当成确定归属。

## 阶段 5：每环节关键变量与来源登记（传导技能的输入）

### 5.1 检索顺序（先搜后登记，不得跳步）

| 需要的变量 | 检索工具 | 读取工具 |
|---|---|---|
| 公司经营与财务变量 | `mcp__fd-find-data-business-mcp__gta_search_variables` | `mcp__fd-find-data-business-mcp__gta_read` |
| 年鉴行业 / 区域指标 | `mcp__fd-find-data-business-mcp__yearbook_search_indicators` | `mcp__fd-find-data-business-mcp__yearbook_read` |
| 城市面板指标 | `mcp__fd-find-data-business-mcp__city_search_variables` | `mcp__fd-find-data-business-mcp__city_read` |
| 开放数据概念序列 | `mcp__fd-find-data-business-mcp__list_concepts` / `mcp__fd-find-data-business-mcp__ai_search` | `mcp__fd-find-data-business-mcp__read` / `mcp__fd-find-data-business-mcp__read_range` |
| 覆盖度确认 | `mcp__fd-find-data-business-mcp__registry_coverage` | — |

### 5.2 变量登记表模板

```
| 环节 | 关键变量 | 变量类型 | 取数工具 | 标识（变量 code / indicator id / concept id） | 频度 | 数据期数（起–止，最新） | 覆盖结论 |
|---|---|---|---|---|---|---|---|
| <环节> | <变量名> | 量 / 价 / 成本 / 库存 / 需求 | <工具名> | <工具返回的标识> | 月 / 季 / 年 | <起>–<止>，最新 <期> | 可取 / 覆盖不足 / 未定位 |
```

### 5.3 登记纪律

- **标识必须来自工具返回。** 未确认的写"未定位"，绝不填一个"看起来像"的 code。
- **每个变量都要给期数区间与最新期**——这是 `chain-transmission` 做频度对齐和滞后扫描的唯一输入。
- **频度不齐要写明**：上游常是月频、公司面板是年频。频度差不是错误，但**必须在这里暴露**，不能留到传导阶段才发现。
- `registry_coverage` 返回的最新期数即本次口径时点，写进输出的「数据截至」。

## 阶段 6：交付结构（每稿必交）

1. **关系声明**：本套件与 `industry-chain-analysis` 的分工（装哪个、为什么）。
2. **口径与数据截至**：行业名、使用的分类口径、`registry_coverage` 返回的最新期数。
3. **可及性自检结论**：第一档 / 第二档各几个归属，以及"第一档在多数行业不可达"的说明。
4. **链条结构表**：环节 → 代表标的 → 关键变量（一张总表）。
5. **置信度明细表**：逐归属给依据与档位。
6. **变量登记表**：逐环节给工具、标识、频度、期数。
7. **缺口清单**：

```
| 环节 | 缺什么 | 原因 | 影响哪个下游步骤 |
|---|---|---|---|
| <环节> | <分类字段 / 变量 / 期数> | <未连接 / 未检索到 / 覆盖不足 / 接口未启用> | <传导链 #n / 候选池> |
```

8. **交接清单**：把"环节对 + 上下游变量 + 频度 + 期数"整理成待验证的传导假设列表，交给 `chain-transmission`。**本稿不给这些假设任何真伪判断。**
