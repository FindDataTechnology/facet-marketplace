# 柏讯信息冲击 · 冲击识别

你的职责：**把一段时间内的信息流找全、按类型初筛、标清每条的身份与健康度背景。**

你交付的是一张可复核的冲击候选清单，不是判断。**本技能明确不做**：

1. **不读正文下结论**——标题、摘要与初筛标签只是检索入口，正文判断属 `shock-reading`；
2. **不判断利好利空**，不做"冲击强度 7/10"式打分（无标尺，且会被当成结论）；
3. **不预测影响**，不写"预计影响 X%"，不说"构成重大冲击"；
4. **不做窗口统计**——前后窗口的价格与指标偏离属 `shock-window`；
5. **不实现定时与推送**——定时属宿主 cron，持续跟踪属 `shock-watch`。

---

## 纪律主轴（四项，本套件共用，本技能逐条落地）

| 纪律 | 在本技能里的落地方式 |
|---|---|
| **健康度前置** | **引用任何条目之前先查 `mcp__fd-info__stream_health`。** 某来源 `status` 非 ok、或 `lag_p95_seconds` 超过本技能声明的阈值（默认 1800 秒 / 30 分钟）时，输出首行声明"信息可能不完整（<source>：<原因/延迟>）"。**不得把空结果表述为"没有事件"。** |
| **item_id 锚点** | 清单的必填字段是 `item_id`（`(source, source_id)` 的稳定哈希，标题修订不改变身份）。无 item_id 的条目不得进入清单；后续解读、统计与证据定位全部以 item_id 回指。 |
| **正文状态分流** | 每条带 `body_status`（stored / pending / failed）。`stored` 才可进入 `shock-reading` 的正文解读；`pending` / `failed` 只做标题层面登记，标"正文未核实"。**不得把标题要素当正文事实。** |
| **不预测** | 清单只陈述"入库了什么条目"，不陈述"这意味着什么"。初筛标签是检索分组，不是性质判断。 |

## 阶段 0：健康度前置（每次开跑的第一步）

```text
mcp__fd-info__stream_health()
```

返回逐源：`status`（ok / unavailable）、`watermark_published`、`last_success_at`、`consecutive_failures`、`lag_p95_seconds`。三条处理规则：

1. **status=unavailable** → 该源条目写"来源不可用"，**不得写"无条目"、不得记 0**；清单顶部声明"信息可能不完整"。
2. **lag 超阈值**（本技能声明阈值：`lag_p95_seconds` > 1800）→ 顶部声明"信息可能不完整（<source> 入库延迟 p95 ≈ <X> 秒）"，并给出 watermark 作为"已覆盖到"的时点。
3. **consecutive_failures > 0** → 如实登记失败计数；失败来源的结论一律不得超出已入库条目。

健康度快照写进输出（来源 / 状态 / 水位 / 延迟），让读者知道"这份清单截至哪里、缺谁"。

## 阶段 1：两路检索（互补，逐路记录）

### 1.1 第一路：游标拉取（主力，覆盖面最稳）

```text
mcp__fd-info__list_since(sources=["cninfo"], source_types=["announcement"],
                         published_after="2026-10-16", limit=50)
```

- **参数语义**：`sources` 按源名过滤（当前在册源：`cninfo` 公告、`cn-gov` 部委、`sse-interaction` 互动）；`source_types` 按三型过滤（`announcement` / `ministry` / `interaction`）；`published_after` 为发布时间下界（ISO 日期）；`limit` 默认 50、上限 500。
- 返回 `{items, next_cursor, has_more}`，按 `(published_at desc, item_id desc)` 稳定排序。**`has_more=true` 时必须用 `next_cursor` 翻页到用户要求的时间边界**，不得只取第一页就宣称"已列全"。
- 翻页途中插入新条目不影响顺序稳定性；**每页的 items 逐条登记，不重不漏**。

### 1.2 第二路：检索补漏（召回不定）

```text
mcp__fd-info__search_info(query="收购", source_types=["announcement"], limit=20)
```

- 返回带 `mode` 字段：`text-core`（语义/全文混合检索，附命中 chunks）或 `index`（标题/摘要索引兜底）。**mode 必须随结果写出**——索引命中的表述只能到"标题/摘要含关键词"，不得冒充全文语义命中。
- 换一个近义词结果集就变。**未命中 ≠ 未发生**。凡使用检索路，输出写明关键词、mode 与命中数。
- 命中条目必须以 `item_id` 与第一路对齐；对不齐的单列"仅检索命中，未在游标拉取中核到"。

## 阶段 2：来源三型与七组冲击类型（初筛，不是定性）

三型由 `source_type` 字段直接给出；七组冲击类型由标题/摘要/上游分类**初筛**而来，每条附一行依据：

| 冲击类型 | 初筛信号（标题/摘要层面） | 提示 |
|---|---|---|
| 业绩类 | 业绩预告/快报、定期报告、分红送转 | 预告是区间估计，定期报告是既成事实，**不得混标** |
| 融资类 | 定增/配股/可转债/公司债 | **预案 ≠ 落地**，标注所处阶段字样（如"预案"）且不解读 |
| 股权类 | 权益变动、股权激励、解禁 | 解禁是"可流通安排"，**不得写成"减持"** |
| 监管类 | 问询/处罚/立案/退市风险 | 交易所公告与部委口径分列，不合并计数 |
| 经营类 | 重大合同、中标、投产 | 金额与生效条件交 `shock-reading` 读正文 |
| 政策类 | 部委发布（source_type=ministry） | 政策要素抽取与行业映射属 policy-transmission 套件，本稿只登记条目 |
| 互动类 | 互动问答（source_type=interaction） | 上游可用性未确认，见 4.3 |

**未命中任何组** → 归「未分组」单列，**不得强行塞进最接近的组**；初筛依据必须可复现（形如"标题含'业绩预告'→业绩类"）。

**归类依据必须写**：只写组名不写依据的条目视为不合格。

## 阶段 3：清单字段（缺任一项即不合格）

| 字段 | 必填 | 取值来源 | 说明 |
|---|---|---|---|
| **item_id** | 是 | `list_since` / `search_info` 返回 | 身份锚点；解读、统计与证据定位全部回指它 |
| **source / source_type** | 是 | 条目字段 | 源名与三型原样记录 |
| **published_at** | 是 | 条目字段 | 用**发布时间**；修订不改 published_at，另看 updated_at |
| 标题 | 是 | 条目字段 | 只作检索入口，**不作结论** |
| **body_status** | 是 | 条目字段（stored/pending/failed） | 决定下游能做什么：stored → 可读正文；否则"正文未核实" |
| doc_id | stored 时必填 | 条目字段 | 正文定位与逐字片段的入口 |
| withdrawn | 是 | 条目字段 | 撤回条目不消失，标"已撤回"，**不得混入正常计数** |
| 冲击类型 | 是 | 七组之一或「未分组」 | 附一行初筛依据 |
| 来源工具 | 是 | 实际调用的工具名与 mode | 便于复核 |
| 数据期数 | 是 | 本次检索起止 + 返回条数 | 见阶段 5 |

**主体锁定**：条目的 `entities` 字段给出涉及主体；主体未在条目中出现时不得由技能自行补公司名——登记"条目未标注主体"。

## 阶段 4：检索局限声明（每次输出必附）

### 4.1 覆盖以已入库条目为准，不是"全市场全历史"

`list_since` 返回的是 info-stream 已摄取的条目，受上游口径与入库节奏约束。**"本次返回 N 条"不等于"该期间共 N 条"**。健康度 lag 超阈值时（阶段 0），此局限必须升格为顶部声明"信息可能不完整"。

### 4.2 检索路的召回不确定

`search_info` 是关键词/语义检索：换词换结果。**未命中不等于未发生**；`mode=index` 时命中只到标题/摘要层面。

### 4.3 互动来源的可用性如实登记

`sse-interaction` 源的上游可用性未在本套件验收范围确认。处理规则三条，不得变通：

1. `stream_health` 里该源 `status=unavailable` 或源不在健康度返回中 → 互动类写"来源不可用"，**不写 0、不写"无互动记录"**；
2. 返回条目 `body_status=failed` 居多时 → 登记"互动条目多无正文"，不冒充可读；
3. **不得用其他来源顶替**互动条目。

### 4.4 "未检索到"的写法

清单为空时只能写：

> 在 <起止日>、<sources/source_types/关键词> 口径下未检索到条目。

**不得写"公司无重大事项""期间无信息事件"**——那是判断，不是检索结论。

## 阶段 5：输出卡与口径溯源

```text
【冲击候选清单】<标的/范围> · <起止日>
健康度：<source> ok（水位 <watermark_published>，lag p95 <X>s）｜<source> unavailable ｜ …
（任一来源不可用或 lag 超阈值时，本行前置：信息可能不完整（<原因>））

| published_at | item_id | source | 类型 | 标题 | body_status | doc_id | 冲击类型 | 初筛依据 | 来源工具 |
|---|---|---|---|---|---|---|---|---|---|

局限声明：<按阶段 4 逐条，至少含 4.1 与 4.2>
数据截至：<watermark 或最近一条 published_at（写明取哪个）> ｜ 数据期数：<起止日，共 N 条>
```

**口径溯源表**（每次输出必附）：

| 项 | 来源（工具名） | 数据期数 |
|---|---|---|
| 来源健康度 | `mcp__fd-info__stream_health` | 调用日 <YYYY-MM-DD> |
| 条目清单 | `mcp__fd-info__list_since` | <起止日>，N1 条 / M 页 |
| 检索命中 | `mcp__fd-info__search_info` | 关键词 <词>，mode=<…>，N2 条 |
| 条目详情 | `mcp__fd-info__get_item` | <item_id 级，逐条> |

## 防编造硬约束（红线）

- ❌ **所有 item_id、标题、published_at、body_status、entities 必须来自工具返回**；无返回写"未取得"，**禁止编造条目、日期、标识或链接，不得凭记忆补"某公司某日发过某公告"**。
- ❌ **引用条目前必须先查 `mcp__fd-info__stream_health`**；来源不可用或 lag 超阈值时必须声明"信息可能不完整"，不得把空结果写成"没有事件"。
- ❌ **不得把标题当结论**：初筛标签只是检索分组；看到"重大合同"就写"利好"或"冲击"是越界。
- ❌ **不得把"返回 N 条"写成"共 N 条"**，不得把第一页当全量，不得跳过 `next_cursor` 翻页。
- ❌ **body_status=pending/failed 的条目不得写成"已核实"**；正文相关表述只能到"据标题/摘要，正文未核实"。
- ❌ **不得自行发明冲击类型**：七组之外只允许「未分组」。
- ❌ **撤回条目不得消失也不得混入正常计数**；互动来源不可用时不得记 0、不得换源。

## 降级路径（数据源未连接或调用失败时，强制执行）

| 情形 | 处理 |
|---|---|
| `fd-info` 工具未连接/报错 | 顶部明示"未连接（`mcp__fd-info__list_since`：<失败情形>）"，正式清单留空；**不得用 fd-cn-report 公告面或通用网络检索冒充信息流**（套件分工见 spec：信息类取数只走 info-stream） |
| `stream_health` 不可用 | 写"健康度未取得（未经在线核实）"，清单照出但顶部声明"信息可能不完整（健康度未知）" |
| 某来源 unavailable | 该源写"来源不可用"，顶部声明"信息可能不完整"；其余源照常 |
| `search_info` 不可用 | 检索路标"未执行"；清单只保留游标路，声明召回可能不全 |
| `get_item` 报"条目不存在" | 该 item_id 标"条目不可得"，不补造内容 |
| 全部不可用 | 输出"本次未取得（工具均未连接）"+ 已尝试工具清单 + 恢复后可复跑的调用式；**不产出清单** |

---

## 交接

- 清单中 body_status=stored 的条目 → `shock-reading`：交 item_id 与 doc_id，由它读正文抽要素并给逐字证据。
- 需要"同类冲击的历史窗口表现" → `shock-window`：本技能只给事件样本（item_id + published_at + 类型），不给反应数字。
- 需要持续盯信息流 → `shock-watch`：本技能是一次性检索，不承担定时。
- 部委政策条目需要行业与区域传导分析 → policy-transmission 套件（policy-detection 起）。
