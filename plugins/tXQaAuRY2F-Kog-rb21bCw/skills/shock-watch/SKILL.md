# 柏讯信息冲击 · 信息流跟踪

你的职责：**在"一组过滤条件 + 一个时间窗"上，稳定地产出同一张信息流跟踪表——让人能一眼看到这段时间新增了什么、来自哪个源、属于哪类、健康度水位到哪里。**

你交付的是**清单与计数**，不是判断、不是推送、不是预警。

**本技能明确不做**：

1. **不预测**——不写"预计影响 X%""后续可能…"，不给方向；
2. **不推荐**——不写"值得关注""建议跟进"，不做标的排序；
3. **不做正文解读**——清单只到"入库了什么条目"；条款与条件交 `shock-reading`；
4. **不做窗口统计**——反应分布交 `shock-window`，本稿不出现任何反应数字；
5. **不实现调度**——定时与推送属宿主配置，见阶段 4。

---

## 纪律主轴（四项，本套件共用，本技能逐条落地）

| 纪律 | 在本技能里的落地方式 |
|---|---|
| **健康度前置** | 每期开跑先 `mcp__fd-info__stream_health`；任一来源 `status` 非 ok 或 `lag_p95_seconds` > 1800（本技能声明阈值）→ 本期表头前置"信息可能不完整（<source>：<原因/延迟>）"。**水位（watermark_published）就是"已覆盖到"的时点，数据截至不得晚于它。** |
| **item_id 锚点** | 清单逐条带 item_id；跨期汇总按 item_id 去重；同一事项的修订（updated_at 变化、item_id 不变）标"同一事项的修订版"，不新增计数。 |
| **正文状态分流** | 计数表加"正文 stored / pending / failed"列；failed 居多的来源注明"该期条目多无正文，标题层面计数"。 |
| **不预测** | 条数变化只陈述数字与构成，不写"信息密度上升说明…""公司动作加快"。 |

## 阶段 0：跟踪集的定义（先定义，再检索）

| 维度 | 取值 | 规则 |
|---|---|---|
| **标的/范围** | 主体名或全量 | 主体过滤只能用条目 `entities` 字段命中；条目未标主体的不算命中，不得自行补挂 |
| **来源** | `cninfo` / `cn-gov` / `sse-interaction`（或全部） | 源名原样传入 `sources` 参数 |
| **条目类型** | `announcement` / `ministry` / `interaction`（或全部） | 三型原样传入 `source_types` 参数 |
| **时间窗** | 起止日（默认最近 7 个自然日，同长度滚动作上窗对比） | 起止日必须写进输出；**不得用"最近"含糊代替** |

**跟踪集上限**：单期单次返回不超过 500 条（`limit` 上限）；超出时按 `next_cursor` 分批并在输出写"共 M 批"。**不得静默截断**。

## 阶段 1：取数与筛选

### 1.1 主路：游标拉取

```text
mcp__fd-info__list_since(sources=["cninfo"], source_types=["announcement"],
                         published_after="<窗口起点>", limit=50)
```

- `has_more=true` 时用 `next_cursor` 翻页到窗口边界；每页条数与页数记入数据期数。
- 逐条登记 `item_id` / `published_at` / `title` / `body_status` / `withdrawn` / `entities`；**缺 item_id 的条目不得进入清单**。

### 1.2 补漏路：检索（可选）

```text
mcp__fd-info__search_info(query="<关键词>", limit=20)     # mode 一并登记
```

用于主题跟踪（如"回购""中标"）。命中必须回到 item_id 与主路对齐；对不齐的单列"仅检索命中"。**未命中不等于未发生**，输出里写这句。

### 1.3 健康度快照（每期必取）

```text
mcp__fd-info__stream_health()
```

逐源登记：status / watermark_published / last_success_at / consecutive_failures / lag_p95_seconds。健康度表与清单同版面，不进附录。

### 1.4 筛选规则（机械执行）

1. 按 `published_at` 过滤到时间窗内（含首尾）。
2. 按冲击类型初筛（沿 `shock-detection` 七组），每条附一行初筛依据。
3. 未分组单列，不计入七组。
4. 已撤回条目（withdrawn=true）单列"撤回"行，不计入正常计数。
5. **不得按"重要性"主观剔除**；缩小清单只能按用户指定的来源/类型/主体，且把规则写出来。

## 阶段 2：输出形态（每期同构，便于逐期对比）

### 2.1 条目清单（按 published_at 倒序）

```text
【信息流跟踪】<跟踪集名称> · <起止日>
健康度：cninfo <status>（水位 <watermark_published>，lag p95 <X>s，连续失败 <n>）｜ cn-gov … ｜ sse-interaction …
（任一来源不可用或 lag 超阈值时，本行前置：信息可能不完整（<原因>））
检索口径：游标 mcp__fd-info__list_since（M 页）｜ 检索 mcp__fd-info__search_info（关键词 <词>，mode=<…>）
返回：本窗 N1 条（stored a / pending b / failed c / 撤回 d）｜ 检索补漏 N2 条

| published_at | item_id | source | 类型 | 标题 | body_status | 冲击类型 | 初筛依据 |
|---|---|---|---|---|---|---|---|
```

### 2.2 来源与类型计数（当期 vs 上窗同长度窗口）

```text
| 维度 | 本窗 | 上窗 | 变化 | 备注 |
|---|---|---|---|---|
| 公告（cninfo） | … | … | +n/-n/持平 | 正文 failed 占比 <…> |
| 部委（cn-gov） | … | … | … | … |
| 互动（sse-interaction） | <可用性如实> | <同左> | — | 不可用时不计 0 |
| 业绩类 / 融资类 / … / 未分组 | … | … | … | … |
```

**计数三条规则**：

1. 分母写清：条数 = 条目数；主体数 = entities 去重计数，两个数不得混用。
2. 上窗口径必须与本窗完全一致（同过滤、同长度、同检索路），否则标"不可比"，**不得强行给出变化**。
3. 不可用来源不参与合计，不得以 0 计入后得出"该来源无条目"。

### 2.3 表述纪律（跟踪表最容易越界的地方）

| 错误写法 | 正确写法 |
|---|---|
| "本周公告明显增多，值得关注" | "本窗 12 条，上窗 7 条；增加集中在经营类（+4）" |
| "该公司连发利好" | "本窗 3 条，类型分别为…（未读正文，不作性质判断）" |
| "来源正常" | 逐源写 status 与 lag 数值，不写"正常"这种结论词 |
| "无新信息" | "本窗在 <口径> 下未检索到条目" |

## 阶段 3：数据截至与口径溯源

**数据截至** = min(各活跃来源 watermark_published, 本窗最后完整检索日)。取哪个写哪个；健康度不可得时降写"最近一条条目的 published_at（健康度未取得，未经在线核实）"。

| 项 | 来源（工具名） | 数据期数 |
|---|---|---|
| 来源健康度 | `mcp__fd-info__stream_health` | 调用日 <YYYY-MM-DD> |
| 条目清单 | `mcp__fd-info__list_since` | <起止日>，N1 条 / M 页 |
| 检索补漏 | `mcp__fd-info__search_info` | 关键词 <词>，mode=<…>，N2 条 |
| 上窗对比 | 同上各路 | <上窗起止日>，N 条 |

---

## 阶段 4：定时触发（宿主 cron，本技能不实现）

1. 定时由**宿主**配置，按固定周期触发一次"对指定跟踪集执行 `shock-watch`"。
2. 每次触发输入固定：过滤条件（sources/source_types/主体）+ 时间窗长度 + 检索口径；时间窗写成**相对长度**（如"最近 7 个自然日"），由触发时刻决定绝对值。
3. 每期输出必须带数据截至与数据期数，相邻两期可直接拼接成序列。
4. **去重**：宿主跨期汇总按 item_id 去重；同一 item_id 的 revised 条目按最新版计一次并注明修订次数。
5. **失败处理**：某期检索失败输出"本期未取得（<工具名>：<失败情形>）"，**不得用上一期结果顶替**，不得静默断档。
6. 推送不在本技能内；**不得声称"已设置定时"**，除非宿主侧确实配置并验证。

## 防编造硬约束（红线）

- ❌ **所有 item_id、published_at、标题、body_status、健康度数值必须来自工具返回**；**禁止编造条目、日期、计数或健康度读数，不得凭记忆补"某公司本周发了某条"**。
- ❌ **健康度异常必须前置"信息可能不完整"**；不可用来源写"来源不可用"，不得记 0、不得换源、不得写"无条目"。
- ❌ **不得把条数变化写成趋势判断**；不得做推荐与排序。
- ❌ **数据截至不得晚于水位**；健康度取不到时如实降级标注。
- ❌ **清单为空只能写"未检索到"**，禁止"无重大事项""经营平稳"。
- ❌ **不得声称已建立定时或推送**；不得静默截断。

## 降级路径（数据源未连接或调用失败时，强制执行）

| 情形 | 处理 |
|---|---|
| `fd-info` 工具未连接/报错 | 顶部明示"未连接（`mcp__fd-info__list_since`：<失败情形>）"，本期清单留空；不得用其他公告面或网络检索冒充信息流 |
| `stream_health` 不可用 | 写"健康度未取得（未经在线核实）"，数据截至降写最近一条 published_at，表头声明"信息可能不完整（健康度未知）" |
| 某来源 unavailable | 该源行写"来源不可用"，不参与合计；其余源照常 |
| `search_info` 不可用 | 补漏路标"未执行"；清单注明"可能不全（检索路未跑）" |
| 上窗数据未取得 | 变化列整列标"不可比（上窗未取得）"，不得补算 |
| 全部不可用 | 输出"本期未取得（工具均未连接）"+ 已尝试工具清单 + 恢复后可复跑的调用式；不产出清单与计数 |
| 宿主某期未触发 | 该期缺失，序列标"缺第 <k> 期"；不得事后补写当期数字 |

## 交接

- 清单中需要读正文的条目 → `shock-reading`（带 item_id）。
- 需要"这类冲击历史窗口如何" → `shock-window`（本技能只给条数与样本入口，不给反应统计）。
- 需要一次性全量梳理 → `shock-detection`。
- 部委条目的政策传导 → policy-transmission 套件（policy-watch 为其跟踪件）。
- 定时与通知 → 宿主 cron（本技能只提供可重复执行的输入定义与输出形态）。
