# 柏讯 · 信息冲击

柏讯信息冲击四件套：冲击识别（先查来源健康度，游标拉取+检索补漏两路，按来源三型与七组冲击类型初筛，逐条附 item_id、发布时间与正文状态）、冲击解读（读正文抽金额/比例/期限/主体/生效条件五要素，结论分明确与需看条件两栏，每条结论附证据块：item_id + as_of + 经 locate_evidence 核对的原文逐字片段；强断言缺可定位证据时只作「据标题/摘要，正文未核实」弱表述）、影响窗口统计（前窗 5 日基准 + 后窗 5/10/20 日并列，样本量、分位、离散度与必选的反例比例随表输出，样本不足整表标注「不作依据」）、信息流跟踪（来源与类型计数、期间对比、健康度水位，滞后与不可用前置「信息可能不完整」）。与事件驱动套件的分工：事件驱动走 fd-cn-report 公告面，本套件走 info-stream 统一信息条目（公告+部委+互动），以 item_id 为引用锚点、以逐字证据为结论门槛。核心纪律：健康度前置（引用前先查 stream_health，lag 超阈值声明信息可能不完整，空结果不得写成没有事件）、不预测（不给涨跌预期）、正文支撑（标题只是检索入口）、历史分布非预测（样本量与反例比例强制随表）。不构成投资建议。

## 技能

- shock-detection — 柏讯信息冲击 · 冲击识别。当用户要求"最近有什么新公告/新信息""把今天的信息流筛一遍""找出可能构成信息冲击的条目"时使用。先查来源健康度，再按游标拉信息流（list_since），按来源三型（公告/部委/互动）与七组冲击类型做初筛，逐条附 item_id、发布时间、正文状态与初筛依据。只做识别与初筛：不读正文下结论（交 shock-reading）、不做窗口统计（交 shock-window）、不预测影响。
- shock-reading — 柏讯信息冲击 · 冲击解读。当用户要求"这条公告/这条信息说了什么""把关键条款摘出来""这个消息的具体金额和条件"时使用。读条目正文，抽取金额/比例/期限/主体/生效条件五类要素，结论分"明确（正文要素直接支撑）"与"需看条件"两栏；每条结论附证据块：item_id、as_of（发布时间）与经 locate_evidence 核对的原文逐字片段。硬约束：未读正文不结论；强断言缺可定位证据时只能弱表述"据标题/摘要，正文未核实"。不预测涨跌。
- shock-window — 柏讯信息冲击 · 影响窗口统计。当用户要求"这类公告发布前后一般怎么走""这条信息的历史前后窗口表现""前后窗口指标偏离多大"时使用。对同类信息冲击做多窗口（默认前窗 5 日基准 + 后窗 5/10/20 个交易日）的历史统计：样本量、分位、离散度与必选的反例比例；样本不足时整表标注"不作依据"。全部输出为描述性历史分布，不是预测；价格只走通道 B，计算只走通道 Q。
- shock-watch — 柏讯信息冲击 · 信息流跟踪。当用户要求"帮我盯着信息流""每天把新条目按来源和类型筛一遍""给我一张信息流跟踪表"时使用。按来源与冲击类型筛选条目流，输出条目清单、来源计数、期间对比与来源健康度水位；滞后与不可用如实标注"信息可能不完整"。不做预告、不预测影响、不做窗口统计；定时触发属宿主 cron，本技能只提供可重复执行的输入定义与输出形态。

## MCP 连接指引

本插件声明以下 MCP 引用（**不随插件自动连接**——插件本体不携带任何服务器配置或凭据）：

- **fd-info** — 端点 `https://mcp.finddatatech.cloud/fd-info/mcp`（需要组：wire-customers）
- **fd-quant** — 端点 `https://mcp.finddatatech.cloud/fd-quant/mcp`（需要组：wire-customers）
- **fd-daas-mcp** — 端点 `https://mcp.finddatatech.cloud/fd-daas-mcp/mcp`（需要组：wire-customers）
- **wire-build-mcp** — 端点 `https://mcp.finddatatech.cloud/wire-build-mcp/mcp`（需要组：wire-customers）

连接方式：支持 MCP OAuth 的客户端可直接对该端点授权；否则用谦面 CLI 铸取调用键后写入本机配置：

```
npx @finddatatechnology/facet connect
npx @finddatatechnology/facet install <packRef> --target workbuddy --write-mcp
```
