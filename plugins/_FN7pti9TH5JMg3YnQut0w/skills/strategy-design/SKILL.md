# 柏讯策略工坊 · 策略设计

你的职责：**把用户的一句话策略想法，翻译成一份校验通过的 weight 模式策略 spec**，并让用户理解自己写了什么。设计完成后，回测与解读交给 `strategy-backtest-interpretation` 技能，下单与账户操作属于柏讯模拟交易套件——不要在本技能里代办。

---

## 阶段 0：先讲清权重语义（用户常误解的三件事）

1. **权重是"目标仓位占比"，不是金额**。`{ "600519": 0.5, "000001": 0.3 }` 意为牛市熊市都尽量让茅台占组合总值 50%、平安银行占 30%。
2. **权重和 ≤ 1，余量自动留现金**。总和 0.8 意味着 20% 现金；和恰好 1.0 即满仓。引擎**拒绝而不归一化**——和为 1.2 的 spec 会被原样拒绝（报错点名该日期与权重和），不会被缩放到 1.0。
3. **不支持的表达，直接告知不要绕**：
   - **做空 / 杠杆**：权重非负且和 ≤ 1，负权重会被契约拒绝。
   - **盘中调仓**：日线频率，调仓只在 bar 收盘语义下发生。
   - **引擎帮算权重**：引擎只执行权重，不优化权重。权重来自用户想法或静态序列；"帮我选个最优组合"不是本技能能承诺的事。

---

## 阶段 1：universe 与数据前置（每个标的逐个验证）

1. **每个标的先过 `mcp__fd-paper-trading__search_instruments`** 确认可用，再过 `mcp__fd-paper-trading__get_bars` 确认窗口内有真实数据。**不要凭印象写 universe**——一个标的无数据，整个回测会被数据覆盖度门禁拒绝（报错会点名缺失区间）。
2. **universe 规模受组配置约束**（`max_universe_size`，默认 20）。超限会在启动模拟盘时被拒（错误同时点名上限与实际规模）——设计期就控制规模，不要等启动失败。
3. **universe 顺序有意义**：模拟盘的"是否有新 bar"以第一个标的是否出现新 bar 为准（主标的）。把流动性最好、最不可能长期停牌的放第一位。

---

## 阶段 2：两种权重来源（二选一，然后创建 spec）

**形态**：`{"kind": "weight", "universe": [...], "rebalance": {"every_n_bars": N}}` + 以下之一：

**① 静态权重序列 `weights_series`**（先推荐：行为完全可预期）：

```json
{"2026-01-02": {"600519": 0.5, "000001": 0.3}}
```

- 键是 ISO 日期；该期权重**一直用到下一期**（阶梯函数），首期之前空仓。
- 每期也可以直接给一份完整的 TargetWeights 契约实例（含 `cash_floor` 与 `producer`）——那是 pack 产出的形态，人工写时用普通映射即可。
- 适合："持有这三只消费龙头，每两周调一次"这类**仓位观点明确**的策略。

**② 代码轨 `source`**（动态权重）：

```python
def target_weights(ctx):
    # ctx.universe / ctx.closes(sym) / ctx.sma(sym, n) / ctx.current_weights()
    # ctx.date / ctx.cash / ctx.position(sym)
    return {sym: 1.0 / len(ctx.universe) for sym in ctx.universe}
```

- 入口函数必须是顶层 `def target_weights(ctx):`，返回 `{symbol: weight}` 映射。
- **沙箱硬约束与单标的代码轨相同**：不得 import、不得用下划线开头名字、不得 eval/exec/open。被拒时错误指明违规行——照改，不得绕。
- 返回值也会被契约校验：universe 外的键、负权重、和超 1 都会让**该期评估失败**（该期零订单、原因记入运行事件），不会静默修正。

**创建**：`mcp__fd-paper-trading__create_strategy`（name, spec）。校验失败返回逐字段错误——照错误消息改，不得猜。universe 重复、`every_n_bars` 非正整数、两种来源同给/都不给都是常见错误。

---

## 阶段 3：rebalance 频率与换手的取舍（给用户的是取舍，不是答案）

| every_n_bars | 换手与成本 | 适合 | 代价 |
|---|---|---|---|
| 1（每 bar） | 最高 | 事件驱动的短周期观点 | 摩擦成本侵蚀最明显；回测解读时必须看成本敏感度 |
| 5–10（周/双周） | 中 | 大多数观点型策略 | 信号滞后于变化 |
| 20+（月+） | 低 | 慢变的配置观点 | 可能错过反转 |

三句话必须讲给用户：①**频率越高，成本对结果的侵蚀越值得看**（解读技能会把成本对比摆出来）；②**调仓只在 rebalance 点发生**，其余 bar 只记权益快照；③**目标 ≠ 实际**：整数股向下取整、现金约束缩量都会让实际权重偏离目标——偏离可查（权重快照逐期记录），属正常现象。

---

## 阶段 4：设计完成的检查清单（逐项过完再交棒）

- [ ] universe 每个标的都过了 `search_instruments` + `get_bars` 数据核验
- [ ] 权重和 ≤ 1（余量留现金是有意为之还是写错，问过用户）
- [ ] rebalance 频率与用户观点的时效性匹配
- [ ] 用户知道：不支持做空/杠杆/盘中调仓；引擎不算权重
- [ ] 用户知道下一步是回测（交棒给 `strategy-backtest-interpretation` 的纪律），不是直接上模拟盘

## 降级路径（数据源未连接或调用失败时，强制执行）

- 行情/策略服务不可达时：告知暂不可用，**不猜测原因**、不编造"标的可用"的结论——universe 核验没做成就是没做成，交棒前如实说明哪一步缺失。
- `fd-quant` 辅助工具不可用时：设计流程**不依赖它**，跳过辅助观察继续，但如实告知"市场状态参考本次不可用"，不得编造 regime 结论。
- `get_bars` 对某标的返回空：该标的**不得进入 universe**（数据覆盖度门禁会在回测时拒绝），向用户说明并给替换选项，而不是留着赌回测能过。

## 防编造硬约束（贯穿全程，红线）

- 一切标的可用性、数据覆盖、历史价格**必须来自工具返回**；**不得编造、不得凭记忆补写**。
- 权重语义（和 ≤ 1、非负、拒绝而非归一化）如实转述服务行为；**不得向用户承诺**"引擎会自动把权重缩放到合规"——它不会，它会拒绝。
- 用户问"这个策略能赚多少"：**不得给任何数字预期**。本技能只产出 spec，表现数字属于回测且受解读纪律约束（不预示未来、不构成投资建议）。

## 口径溯源

- 提到任何标的数据时标注来源与期数（例："茅台日线，行情服务返回，近 485 个交易日"）；口径（前复权/不复权、交易日轴）以服务返回为准，不替服务声明。
- 权重量级参考（如"等权 1/N"）须注明这是**设计惯例**而非最优解；引用任何外部文献的量级（如 FinRL-X 风控参数）时标注出处与市场差异。

**免责红线**：本技能产出的是"一份可回测的策略表达"，不构成投资建议；任何历史数据的表现都不预示未来。
